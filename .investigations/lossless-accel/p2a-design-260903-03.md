## 0. 实施结果与方向变更（260903-03 session 末，supersedes 本文 §1 裁剪决策）

- **裁剪变更**：§1 原拟「5 channel 根闭包」→ 实施改为 **final_density 整树直采**（C++ WG_DFC_CPU 已验证形态）。原因：5-channel 分解是 Rust transpiler 侧宏化产物，不在 vanilla JSON 树中，做 5 根闭包需生成器多点根手术。
- **正确性结果（决定性正结果）**：DFC 整树路径 vs f64 DF 树（macro 同源）**块级 4 chunk 393216 块 0 mismatch**（`{:.6}` 内 FINAL diff=0.000000，delegate 角点级 diff ≤1e-6 = 纯 f32 精度）；vs transpiler 0.92% mismatch ≈ transpiler 已知 1.2pp vanilla 残差（P0 归因）——**DFC 比生产 transpiler 更贴 vanilla**。
- **性能结果（决定性负结果）**：DFC 逐点采样 650 ms/chunk ≈ transpiler 51 ms 的 **12.7×慢**（macro 56 ms）。微观剖析：grid 重建 0 次（缓存正常），瓶颈 = 每点 split_top（~25 实例 ×240 octave 拆分）≈3.9 μs/pt——**逐点架构比角点采样天然多 ~16× 树求值量，CPU 上无法靠微优化翻盘**。
- **对 P2a 方向的含义（须用户拍板）**：架构 260903-01 P2a 的「整树扁平化」若要走 CPU 路线，正确形态应是**扁平表 + 角点采样**（把 transpiler 的 1225 角点 × 5 channel 的树递归换成 DFC 扁平求值），而不是逐点直采；这需要回到 5-channel 闭包问题（Rust 侧 channel 分解与 vanilla 树的桥接）。备选：① 转向 X1 GPU 路线提前（P2b 角点 GPU 方案不受本负结果影响，22-39× 实证仍在）；② 封存 DFC-CPU，transpiler 保留生产位。本轮代码全部 env 门控默认关，生产零影响。

## 1. 裁剪决策（核心）

DFC 只替换**角点采样**层——5 channel 根（1 BlendDensity + 4 RangeChoice noodle，terrain.rs:289-304）各作为独立求值根；下游逐 block 插值/combine/beardifier/aquifer 链**一行不动**。

- 理由：零退化验证面最小（channel 角点级对比即闭环）；terrain.rs:339 每点 Vec 分配已在 S0 前修掉；下游语义（RangeChoice 非线性 combine 在插值之后）保持原样，避免「先 combine 后插值」语义等价性论证。
- 缓存语义消除：transpiler_cache_2d/3d（TLS+RefCell+256 线性扫，density.rs:335-395）与字符串噪声查表（noise.rs:344）在 DFC 模型下被 split 表（每 corner 一次性算 int/frac 拆分坐标）+ perm 索引直查天然替代——与 C++ WG_DFC_CPU 已验证形态同源。

## 2. 形态：小 emitter + 手写表驱动 runtime

- **Python**：dfc_gen.py 新增 `gen_tables_rs(root_df)` ——只产数据（不产求值代码）：
  - noise 实例表：kind/params/splitBase/octBase/n/persistence/amplitude/amps（split 循环数据化）
  - DF 节点表：DF_TYPE/A1/A2/A3/F0-F3（复用 _compute_val_layout）
  - 闭包表：CLOSURE_*（5 interp）+ 5 channel 根作为 5 个顶层闭包（复用 top closure 机制 ×5）
  - spline 6 表 + NOISE_SLOT_BASE/STRIDE + COORD_SLOT_TABLE + coord fold（fold 表达式产为数据 op 表或小型生成 match——实现时定，倾向 op 编码数据化）
  - 产出：`WorldgenRust/src/generated/dfc_cpu_tables.rs`（const 数组 + include!）
- **Rust runtime**：`WorldgenRust/src/dfc_backend.rs` 手写，全表驱动：
  - `init(world_seed)`：经现有 noise.rs Splitter/采样器初始化（octave origin 用于 split），collectPerm 到 `Vec<u32>`
  - `split(x,y,z)`：数据驱动循环填 `splitCoord`（thread_local 或 per-sample ctx，红线：per-thread）
  - `eval_closure(closure_id)`：显式栈序贯求值（直译 eval_df 闭包机制）
  - f32 原语：pn_sample3_f32/pn_section_f32（fadeY 用第 7 值）/interp_noise 双早停/persistence 每 octave /2/mapPermD v&255/GRADIENTS f32/维护 maintainPrecision/minY=-64/floorDiv 负坐标
  - spline：显式栈 stage 机 + D23 边界嵌套递归到 v0/v1 子帧（直译 mvp_spline_eval 模型）
- **接线**：terrain.rs 新 `DfcDensity` 采样器（与 TranspilerDensity 同 trait 形态），`WG_DFC` env 门控默认关（worldgen_handle.rs 与 WG_TRANSPILER 同点分流，优先级：WG_DFC > WG_TRANSPILER > macro）。

## 3. 精度口径声明（§9.7 预声明）

DFC 求值为 **f32 语义**（同源 GLSL/C++ 红线，非 Rust f64 路径）。验收判据按架构 §3：vs 现路径 98304 点 `{:.6}` 舍入内 max_diff=0.000000；若 6 位舍入边界出现翻转，回退数据层取证（|density| 离舍入边界距离分布），不得静默放宽口径。

## 4. 验证判据（预注册，同架构 §3）

1. 全 chunk 98304 点 5 channel density：WG_DFC on vs off，`max_diff=0.000000`（{:.6}）

3. 性能：WG_PHASETICK + 无探针整批 wall（pipeline_bench/transpiler_prod_perf 口径），vs 现路径 + vs Java 大样本 ≥256 chunks 中位数
