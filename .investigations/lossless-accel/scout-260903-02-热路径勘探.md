## 1. Rust 侧 density 热路径地图

### 1.1 调用链（生产入口 → 热路径）
- 生产封装入口：`WorldgenRust/src/worldgen_handle.rs:380` `WorldgenHandle::fill_chunk_blocks(cx,cz)` → :388-405 调 `fill_chunk`（WG_TRANSPILER 时传 `transpiler_density`，否则 `macro_sampler`；beardifier RwLock 读锁 clone 后释放再进入 fill_chunk :399-402）。
- 批量入口（JNI/FFI）：`WorldgenRust/src/api.rs:133` 线程池循环调 `h.fill_chunk_blocks(...)`。
- `fill_chunk` 主体：`WorldgenRust/src/terrain.rs:240-282`。结构：每 chunk 先 `dense.sample_chunk()`（terrain.rs:256）构建宏观网格 → 逐列自顶向下逐 block：density 插值/采样（:266）→ beard 修正（:269）→ aquifer 分类（:270）→ surface 高度 + biome（:274-278）。
- 宏观网格（1225 角点）：`terrain.rs:121-137` `MacroGrid::build`（gx=5, gy=height/8+1=49, gz=5 → 5×49×5=1225 次 `dense(&NoisePos)`）；TranspilerDensity 版 `terrain.rs:305-323` `build_slices`（5 channels × 1225 点）。

### 1.2 TranspilerDensity（WG_TRANSPILER 门控的生产采样器）
- 定义 `terrain.rs:289-304`：NoiseSet + cell 4×8×4 + nch=5 channels（1 BlendDensity + 4 RangeChoice noodle，:286 注释）。
- 角点采样 `terrain.rs:315` → `generated_density::fill_cell_corner_densities_final_density`；块级插值 + combine `terrain.rs:348` → `compute_final_density`。生成代码位于 `WorldgenRust/src/generated/vanilla_density_functions.rs`（每函数一行超长内联代码；角点函数带 `__fcq_x/z` floor 对齐 + `transpiler_cache_2d(id,...)` 调用，见该文件 :3,:24,:39 等）。

### 1.3 DensityFunction::sample_ctx 分派（逐点路径 / macro grid arg 路径）
- enum 密集 match：`density.rs:527-619`（BinOp :535-544、UnaryOp :547、Clamp :548、ShiftA/B :596-598、RangeChoice :602-603、WeirdScaled :609、BlendDensity/Wrapping :614-615、Cache2D/FlatCache/Interpolated/Spline :552 附近 + :619）。
- **每节点一次 enum match + Box<Arc> 指针追踪**：`self.arg.sample_ctx(pos, interp)` 逐层递归（:535,:539,:541-544 等）——虚分派等价物，无内联扁平化。
- InterpolatedDF：`density.rs:226-321`（thread_local INTERP_CACHE :230-235，Box<RefCell<InterpSlot>> per cache id；`build_grid` :261-279 对 arg 递归 sample 25 点（5×5×1——注意这是**嵌套 Interpolated 的 5×5×1 网格**，与 1225 宏观网格不同层）；命中/重建 :287-290；GRID_ARG_SAMPLES 原子计数 :274）。
- SplineDF：`density.rs:74-119` SplineData 已是**扁平表**（nodes/locations/derivatives/sub_idx + loc_fns: Vec<Arc<DensityFunction>>），但 `sample_node` :95-119 **递归**：location f = `loc_fns[loc_fn].sample(pos)`（:98，每 node 重算 location 函数）→ 二分 → 递归 `sample_node(subs[i])`（:112,:117 等）——递归深度 = spline 树嵌套（finalDensity 树含 6 个 SplineDF，locationFunction 又是 InterpolatedDF/SplineDF 深层嵌套，见 AGENTS.md 多线程课题定论）。
- FlatCacheDF：`density.rs:428-443`（5×5 chunk 级、y 无关，thread_local）。

### 1.4 transpiler_cache_2d/3d 缓存结构
- `density.rs:335-362`（2d）/ :368-395（3d）：key = `(x<<32)^z` / `(x<<32)^(y<<16)^z`；存储 = **thread_local** `C2D_CACHE: RefCell<Vec<Option<Box<RefCell<Cache2DSlot>>>>>`（:327-330），每 slot 256 项数组 + 线性扫描（:342-344）+ LRU stamp（:357-359）。
- **无锁**（thread_local 每线程一份，跨线程共享树无 cache-line 争用——与 InterpCache 同策略，:226 注释）。
- 命中模式：每 2D 采样 = 一次 TLS `with` + RefCell borrow + ≤256 次线性 key 扫描（:338-347）；miss 时两次 TLS 进入（查+写）+ 闭包重算。
- NoiseSet：`noise.rs:332-354` —— `sample_noise(&str,...)` **每次采样字符串查 HashMap**（:344 经 index 拿 usize 下标再 O(1) 数组访问；索引查找本身仍在热路径）。生成代码里每次噪声调用都传字符串字面量（vanilla_density_functions.rs :3 可见）。

### 1.5 并发瓶颈判读（证据 + 定性）
| 环节 | 证据 | 并发定性 |
|---|---|---|
| 树遍历 enum match 递归 | density.rs:527-619 逐节点 match + Arc 解引用 | 每点 98304→1225 次已被宏观网格压缩，但**每角点仍是深递归**；单线程已证 spline 扁平化 -24%（AGENTS 定论）→ P2a 目标 |
| transpiler_cache TLS/RefCell/线性扫描 | density.rs:338-360 | 无锁但每点多次 TLS+RefCell+256 线性扫；**64 角点/chunk × ~100 cache id × 5 channels** 放大 |
| 字符串 key 噪声查表 | noise.rs:344 | 每次噪声采样 hash(String)——热路径纯开销 |
| 互斥锁 | Rust 侧无 Mutex 在 density 热路径（beardifier RwLock 读在 chunk 级，worldgen_handle.rs:399）；GpuDensityEngine 有 fillMtx（C++，见 §3） | Rust CPU 路径无锁竞争主嫌疑；11× 膨胀主因仍是**虚分派+cache miss 链**（AGENTS.md 2026-08-16 定论） |
| 分配 | build_slices 每 chunk `vec![0.0; gx*gy*gz*nch]`（terrain.rs:307）+ interp `vec![0.0; nch]` **每 sample 一次**（terrain.rs:339） | 每 block 插值都分配 5-f64 Vec（~98304 次/chunk）——热路径分配热点，P2a 顺手可消 |
| 原子 | GRID_ARG_SAMPLES fetch_add（density.rs:274，诊断计数） | 仅诊断开时;需确认是否常开（生产建议门控） |

**对 P2a/P2b 含义**：P2a（整树 DFC 化）收益点确凿——generated/ 已是直排代码但**仍经 transpiler_cache_* 的 TLS+线性扫 + 字符串噪声查表**，DFC 化应连缓存语义一起编译成扁平表（CpuBackend 形态）；P2b（GPU 算 768 角点）下 Rust 侧只需保留三线性插值 + combine（terrain.rs:324-349 插值部分），并把 terrain.rs:339 的每点 Vec 分配消掉。

## 2. spline / DFC 资产盘点

- **dfc_gen.py**：`.investigations/perf-rework/dfc_gen.py`（~3100+ 行）。产出三形态：
  ① GLSL compute shader：`gen_shader`（:1404）、`gen_split_shaders` 8 个 corner shader（:2860，corner_0..7.spv 已在 vulkan-proto/）、显式栈后序求值 `eval_df_glsl`（:413,:485，GLSL 禁递归 D4，:1307 注释）；
  ② C++ CpuBackend：`gen_cpu`（:1651）→ 产出 `versions/1.20.1/cpp/worldgen/gpu-assets/cpu_backend.h`（生成器产物，A 数据表 + split/perm/spline 扁平表，:2032-2075 注释「严格同源 _compute_val_layout」）；`gen_cpu_sampling`（:1885，spline_eval 显式栈，stage 模型直译）；
  ③ 噪声 manifest：`gen_noise_manifest`（:1503）。
- **C++ 侧已有 DFC 扁平表 / CpuBackend**：`cpu_backend.h`（上述）；运行时引擎 `versions/1.20.1/cpp/worldgen/src/gpu_density_engine.cpp:11`（Impl{ CpuBackend backend; VkRuntime; ...}）；运行时头 `worldgen/src/vulkan_runtime.h`。**CPU-only DFC 后端也已有**：worldgen_api.cpp:453 `WG_DFC_CPU` 门控 + :880 `WG_WARM_GRID`（`h->dfcBackend`，CPU DFC 路径已在 worldgen dll 内存在）。
- **Rust 侧扁平化尝试现状**：
  - SplineData 已是扁平表但 sample 递归（density.rs:84-119，见 §1.3）——即「表已有、遍历未扁平」；
  - transpiler（WG_TRANSPILER）= build-time 直排代码路线（generated/vanilla_density_functions.rs），是**已有的整树编译**，但缓存/噪声查表仍走运行时 helper（§1.4）；
  - 未发现 Rust 侧 CpuBackend 式「全扁平节点表 + 显式栈」实现（grep 扁平/flatten/spline_eval 无 Rust 运行时命中）。

**含义**：P2a 不需要从零写生成器——dfc_gen.py 的 `gen_cpu` 已产出与 GLSL 同源的 C++ 扁平表，P2a = 将该生成目标**加一个 Rust 后端**（或由 transpiler 路线直接编译缓存语义），逐位对齐锚点用 vulkan-proto 既有 e2e。

## 3. GPU 通道候选现状（C++ GpuDensityEngine）

- 接口形态（`worldgen/src/gpu_density_engine.h`）：
  - 构造 `GpuDensityEngine(uint64_t seed, const std::string& spvPath)`（:14）——CpuBackend.init(seed)（.cpp:75）+ Vulkan init + pipeline 编译（**一次性 ~70-100s**，.cpp:77-81）；
  - 批量入口 `void fill(const int32_t* coords, int n, float* out)`（.h:20，.cpp:106-118）：n×3 块坐标 in → n float final_density out；内部 CPU split（double→int32+float）→ upload → dispatch → readback；
  - 单点 `sample(x,y,z)`（.h:23，N=1 仅诊断）；
  - 布局查询 `splitTotal()/perSample()/splineBindBase()`（.h:26-28）。
- 关键实现约束：`std::mutex fillMtx` 串行化所有 fill()（.cpp:25,:108——多线程并发 fill 曾 0xC0000005 @ nvtfi）；buffer 容量自动重建 ensureBuffers（.cpp:30-70）。
- 集成点：`worldgen/src/worldgen_api.cpp:522-536`（wg_create 时 WG_GPU_FILL 门控构造，spv 路径 WG_GPU_SPV 可覆写，缺 final_density.spv 则 CPU 回退）；density 阶段 GPU 分支 :841-847（批量算本 chunk 全部点 finalDensity）。
- **「经 FFI 借给 Rust」需暴露的最小面**：① create(seed, spvPath) ② fill(coords*, n, out*) ③ destroy ④（可选）splitTotal 等布局查询。需处理：初始化 70-100s 的生命周期管理（handle 级缓存而非每 chunk）、fillMtx 串行化跨 FFI 保留、float32 输出 vs Rust f64 插值链的精度口径（P2b 已收官逐位一致的口径是 C++ 侧——Rust 借用需重新验证可比性，§9.7）。
- env 门控清单：
  - **Rust 侧**：WG_TRANSPILER（worldgen_handle.rs:164,:390 transpiler 采样器开关）、WG_NO_MACROGRID（terrain.rs:109 回退逐点）、WG_SKIP_AQUIFER/OREVEIN/SURFACE/CARVER/FEATURES（worldgen_handle.rs:397,:412,:452,:458,:463）、WG_FEATURELOG（:466）、WG_CARVERDIAG（:574）、WG_DEBUG（api.rs:131）、WG_SEED（诊断 bin）、WG_SOUL_CTX_DUMP（surface_rules.rs:424）、WG_AQUIFERCOUNT/WL/BP（aquifer.rs:15,:26,:39）、WG_B1_COLS/YMAX（b1_column_trace.rs:3-4）、WG_BIOMEDUMP/WG_CONFUSION（multiworld_nether_blocks.rs:33,:105）。
  - **C++ 侧**：WG_GPU_FILL + WG_GPU_SPV（worldgen_api.cpp:522,:525）、WG_DFC_CPU（:453）、WG_WARM_GRID（:880）、WG_SPLINE_FILL（:420）、WG_FLAT_TOP（:434,:442）、WG_GEN_MODE=full（:358）、WG_PHASETICK/WG_PROFILE/WG_STAGETIMER/WG_MTTRACE/WG_CLOCKTRACE/WG_TASKTIME/WG_POOLDBG（:817,:823,:744,:102 bench,:1217,:1193）、诊断 dump 类 WG_BIOMEDUMP/COMP/ESTD/NOODLE/SURF/DBDEBUG/SPLINEDEBUG/SURFTRACE/AQFDUMP（:59,:656,:924-:1004,:1090）。

**含义**：P2b 的 FFI 借用面很小（3 个函数），但必须把「引擎生命周期 + mutex 串行化 + 精度口径」三件事写进 P2b 设计，且批 768 角点/chunk 恰好命中 22-39× 批量甜点。

## 附：一句话结论
热路径 = worldgen_handle.rs:380 → terrain.rs:240 fill_chunk → terrain.rs:305/315 TranspilerDensity 角点采样（5ch×1225）→ generated/ 直排代码 → density.rs:335/368 TLS 缓存 + noise.rs:344 字符串噪声查表；并发瓶颈主嫌 = 深递归分派 + 缓存 helper 开销 + terrain.rs:339 每点 Vec 分配，非互斥锁。P2a 资产（dfc_gen.py gen_cpu 扁平表 + WG_DFC_CPU C++ 先例）与 P2b 资产（GpuDensityEngine 3 函数面 + 768 角点批量 22-39×）都已存在，缺的是 Rust 后端与 FFI 借用层。
