## 1. 问题一：198 个 bbox 外成员是否直接支持「缺席面主体 = 载体覆盖差」？

**结论：支持「198/520 是口径覆盖差，非机制性缺席」，但只闭合 198 个（38%）；剩余 322 个 in-bbox 成员不被该解释覆盖，"缺席面主体"一词不成立。**

### 1.1 两口径覆盖面差异的来源（核对 e3a_cmp.py p10_constant_face + t8 台账）

- **face（t8 口径）的定义域** = `common = kd2 ∩ kd3 ∩ kv`（e3a_cmp.py L44-48）——即 **t8 三次独立 run（domain r2/r3 + vanilla r1）light snapshot 的共同 key 集**。light snapshot 覆盖 = 该 run 结算时点**全部已 lit chunk**（criteria-t8.md：FP-DRV 驱动 + settle 60s 后 snap_light 全量签名；P07v1 曾把该口径量作 9450）。所以 face 的候选池是 **~9450 量级的 lit 面**。
- **E-3a workload（E3A 打点面）** = **域批写回面**（P07v2 amend：`[E3A]` 行 = `[LIGHT-WB]` 写回面 = 3703；**vanilla 直亮 chunk 不走域批、无打点行**——这是 P07v1→P07v2 修正的核心教训：9450 lit ≠ 3703 打点面，正是 #132「分母语义 MUST 声明」的本案实例）。
- 因此 `absent = face − 打点面` 天然含两类成员：① t8 lit 面内有、E-3a 域批根本没写回的 chunk（覆盖差）；② 域批应写回而两臂都没写的 chunk（机制性缺席）。**520 是两类的混合，单看计数无法分账（#162：计数恒等≠集合恒等；缺席总数 520 与 260919-09 存在性差 520 同数不构成机制同一）**。

### 1.2 198 个 bbox 外成员的判读

edge_dist = −1 表示该 chunk 在两臂 E3A 并集 bbox 之外 → E-3a 两 run 的域批**在该 chunk 处从未活动**（连活动区都没进）→ 无 E3A 行是**必然**，不携带任何写回机制信息。这 198 个的存在**确证**了 face 与 E3A 打点面是两个不同覆盖集（t8 lit 面广于 E-3a 写回 bbox 至少一圈），与 1.1 的口径分析互洽。

⚠️ **但反向不成立**：in-bbox（edge_dist ≥ 0）的 322 个不因 in-bbox 就落入域批写回域——bbox 是并集外接框，框内同样存在 vanilla 直亮 chunk 与域批未覆盖 chunk。322 个的定性需要逐 chunk 对照「写回资格集」，现有归档没有该通道（见 §4）。
