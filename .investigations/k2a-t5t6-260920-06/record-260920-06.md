## 7. 错误记录：fe1 臂 VOID（五段式）

> 载体：本课题错误台账（.investigations/<课题>/ 内记录），证据 = `.tmp/k2a-t5t6-260920-06/formedge-fe1.log` + `formedge-fe1_result.json`。

- **现象**：fe1 run 的 `[FP-ON] ... drive=false grid=false edge=true` 打出 edge=true（开关链 `-Pformedge=1`→`-Dcoreswap.formedge` 映射与getProperty 消费均通），但 `[FP-EDGE]` 行 **0 条**（init/arm/done 全缺，SELFCERT `edge_init/edge_arm/edge_done` 全 0，probe_* 全 null），采集判据面整体缺失 → fe1 采集 VOID，不进判读。
- **根因**：FormProbe serverTick 分发路径上有**mixin/驱动门「DRIVE-only 放行」缺陷**——tick 内进入票据驱动分支的放行条件只认 formdrive（DRIVE）族开关状态，edge 分支虽被 init 打印（FP-ON edge=true）却从未被 serverTick 分发放行，`[FP-EDGE]` 时序码成为不可达路径。机制 = 门控条件枚举不全（新增分支未纳入既有放行谓词，属「开关家族扩展漏改门卫」结构错，非开关映射错——B6-1 门只保证 -P→-D 映射与消费点存在，不保证消费点内部子分支可达）。历史核清附带项：**260920-05 的 grid 臂实际是在 formdrive 开关寄生开启的状态下运行的**——该 run 的放行谓词恰好被 formdrive 满足，grid 时序得以走通，即上块 grid 数据面的驱动通路实为 formdrive 门放行而非独立 grid 门；此历史事实与本缺陷同根（同一放行谓词），登记为 fe1 核清副产物。
- **定位**：SELFCERT 硬门机械捕获——`edge_init:0` 与 `fp_on_edge:1` 并存构成「开关生效但行为面零输出」矛盾签名；grep fe1.log 全文无任何 `[FP-EDGE]` 行确认非打点丢失；对照 fe2（修复后）同签名消失（arm/probe/done 齐全）。
- **修复**：放行谓词扩展为涵盖 edge 分支（fe2 采集前合入，`compile*.log` 记录三轮编译），fe2 复跑全链 SELFCERT 绿 + 判据面完整。
- **教训**：① **SELFCERT 前置集价值实证**：`edge_init=0` 一项即机械拦下整轮 VOID，防止「开关打了 = 功能跑了」的假阳性判读（§15.1 preconditions 的判据 suspended 语义）；② 新增开关分支 MUST 审查**既有放行谓词/门卫条件**，不只是加 getProperty 消费点——B6-1 映射门是必要非充分；③ 历史正结果的「靠哪个门放行」也值得核清（260920-05 grid 寄生 formdrive 一例），避免后续把「grid 门独立可用」当公理续推（交接结论验证纪律）。
