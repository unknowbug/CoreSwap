## 1. 全局视图（目标 / 范围 / 排除项）

**目标**：Rust 实现光照引擎（block light + sky light），替换/绕开 Java LightEngine 的逐位照抄路径，以「重写 + 允许有损」换取显著加速。

**范围**：
- Java 光照引擎机制勘探（scout，产出结构地图）
- 验收判据 + 有损边界定义文档（开工前 MUST 落盘，用户批准）
- Rust 光照实现 + 接线（chunk 管线 LIGHT 阶段或等效拦截点）
- 性能 vs Java 基线端到端对比

**代码布局（260905-01 用户拍板）**：光照 Rust 代码 = **`WorldgenRust/src/light/` 模块**（同 crate 同 cdylib 同打包链，复用 block 注册表/数据驱动加载/BlockColumn；不建独立顶层 LightEngine 目录/独立 dll）。opacity 表从 JSON 数据文件加载（数据驱动铁律）。Java mixin/探针 = runtime/1.20.1/java（不入库）。ABI = 现有 api.rs/jni_bridge.rs/CppWorldgen.java 三处上加 wg_light_* 导出。

**明确不做什么**：
- 不要求逐位对齐（脱离逐位验证域）
- 不涉及地形/世界生成改动（本课题只动光照）
- 永久挂起 4 项（ore_vein 域 1 / aquifer 域 2 / C++ ore 族 desync / populationSeed）不拉起
- 实体 AI、多世界、DFC（§3 优先级 3/4/5）不在本课题

## 6. 风险 & 回退

- **光照下游依赖**：流体 tick/生怪/寻路读光照值——有损近似可能行为级放大。回退：正确性下界不达 → 收窄有损范围或回退全量复刻传播算法。
- **调度语义差**：Java 光照是异步 mailbox 增量调度，重写若改全量重算，需确认 chunk 加载路径无顺序依赖。scout 重点核实。
- **基线陷阱**：Java bench 冷启动/缓存假象（workflow-patterns #19：先删 run\world）——端到端铁律强制。
- **探针污染**：bench 串行（#28）、诊断门控 chunk 级（AGENTS 四）。
