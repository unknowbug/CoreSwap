| 决策 | 内容 | 理由 / 声明 |

## 14. 执行中的架构变更与实测更正（260910-06，按 core.plan「架构不适用 → 暂停回写」纪律）

### 14.1 设计变更：D-b 的「vanilla 锁形态」被实测证伪 → 改为无外层锁（1.21.6 同形态）

| 项 | 内容 |
|---|---|
| 触发 | 首轮实测两臂**都**卡死：Chunky `Processed: 0`、CPU ≈ 0.01 核（见 `.investigations/perf-reg-260910-06/errors-260910-06.md` E1） |
| 机制（决定性证据 = 自建线程栈看门狗 dump） | 外层 `ChunkSection.lock()` 与写回路径**自带**的内层锁冲突：`CppBridge.writeChunk` → `ChunkSection.setBlockState(x,y,z,st)`（4 参重载 → `lock=true`）→ `PalettedContainer.swap()` → **再次 `LockHelper.lock()`（非可重入 Semaphore）⇒ 同线程永久 park**。vanilla 能加外层锁是因为其 fill 改用 `setBlockState(..., lock=false)`（`swapUnsafe`） |
| 排除对照 | **同步臂也卡** ⇒「异步分派 / 完成跳回」被排除（该变量不解释卡死） |
| 变更 | 删 `wgLockSections`/`wgUnlock` 与 `whenCompleteAsync` 完成跳回；分派器 = `completedFuture(work.get())` / `supplyAsync(work, WG_FILL_POOL)` |
| 后果 | 与 vanilla 1.20.1 的形态**有意不同**（不加外层锁）⇒ 列入 verdict 的 §9.7 声明；理由与证据内联在源码注释中 |

### 14.2 新增诊断件（门控默认关，生产零成本）
