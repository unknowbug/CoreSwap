## 1. 全局视图（目标/范围/排除项）

- **目标**：为 light 接管面建立首份「读写声明表」——声明该接管在读哪些数据域（门控前提标注）、写哪些数据域；并用 ≤1 轮探针预验证「机械核对实际触达 ⊆ 声明」可行。
- **范围**：仅 light 面（`ServerLightingProviderMixin` + `java-core` light 链路 + `worldgen-core` light_compute）。overworld/nether/end 三维行为差异按已有判据（#130 载体存在性）引用不重查。
- **排除项**：不铺开到 surface/CARVERS/FEATURES 面（试点通过后另立项）；不改生产代码行为（只加声明文档 + 门控诊断，若有代码改动须行为恒等验证 #47 golden 对照）；不动协议（E:\PYTHON\Anchorlaw 只读）；不做逆路径实现（b1 已核 `wgReleaseLightTicket` 无逆——只登记为声明行，不造新机制）。
- **成功判据（预登记）**：
  - C1：light 面声明表落盘（reads:/writes:/门控前提/inverse 状态四列），每个写站点附一手源 file:line。
  - C2：探针预验证可判——用既有 `coreswap.light.betaprobe/betadump` 或 WG_* 门控仪器在 ≥1 次采集里产出「触达站点清单」，与声明表机械比对输出 ⊆/⊄ 结论（比对器独立于声明表作者）。
  - C3：#98 家族消解力演示——声明表能机械检出至少一个「声明前提在生产门控下不可达」的实例（现有候选：`terrain_cache` 写路径门控 #102 补充案例形态，若 light 面无实例则如实声明并降级 C3 为「判据存在、无对象」）。

## 2. 角色分配

- **scout（subagent，只读）**：light 面读写站点普查——`java-core`（ServerLightingProviderMixin / LightStorage / 持久化触点）+ `worldgen-core`（light_compute 及其输入数据域），产出站点地图（file:line + 读/写 + 门控）到 `.investigations/b63-260918-06/scout/`。
- **worker（subagent）**：按站点地图起草声明表（draft artifact）；比对器脚本由 worker 交付、主会话执行（subagent 无 shell）。
- **主会话**：编译/采集/探针执行（命令委托契约），声明表应用 + 门禁复核。
- **judge（subagent，MUST）**：收尾三源核对（artifacts 快照 / git diff / 验证记录）+ C1-C3 判据逐条核。
