### 0.2 🔴 前提核验（本块新增，**改变 C7-① 的做法**）

judge C7-① 的竞争假说 = 「`pending_cross_writes` 在 inflight=23 下顺序敏感 → 写丢失」。**本项依赖一个未核前提：`apply_features` 是否真的执行**。核验结果：

| 链节 | 证据 | 结论 |
|---|---|---|
| 默认阶段掩码 | `CppBridge.java:69-75 resolveStageMask()` → `prop==null ⇒ 0b011` | 默认 mask=3 = bit0 SKIP_CARVER + bit1 SKIP_FEATURES |
| 运行时值 | `cmd-output/r3-async-r1.log.err:76` / `r3sync-r1.log.err:76`：`flags=3 skip_features=true skip_carver=true skip_surface=false` | 两 R3 臂**都** skip_features |
| Rust 消费点 | `worldgen-core/src/worldgen_handle.rs:669-671`：`let skip_features = flags & FLAG_SKIP_FEATURES != 0 \|\| env WG_SKIP_FEATURES; if !skip_features { self.apply_features(...) }` | skip_features=true ⇒ **`apply_features` 不被调用** |
| `pending_cross_writes` 唯一生产者/消费者 | 生产 = `:1086-1091`（`apply_features` 内回调）；消费 = `:1051-1063`（`apply_features` 开头的 overlay） | **唯一入口在 `apply_features` 内 ⇒ 结构不可达** |
| 出货语义同源 | 260906-08 #66：vivo 出货 mod 亦 `stageMask=3` | 生产口径同样不可达（非仅 bench） |

**判定（静态）**：C7-① 的竞争假说在当前出货语义下是**空集**——`pending_cross_writes` 恒空 ⇒ 生产/应用/遗留三数恒为 0，不构成等价门的竞争解释。
**仍需行为化直证**（#37/#81：机制断言必须行为化，静态不过夜）：1 次 `WG_CA_LOG=1` 的 async 臂应产出**零 `[CA]` 行**；正向对照 = 同载体历史 `calog-e2-260909-04.err` **257 行 `[CA]`**（features 开启臂）⇒ 零行不是「env 没送达」的假阴性。
**设计后果**：**不再先加会计计数**（避免造一条不可执行、无法验证的路径）；会计实现改为**条件项**——仅在行为化核验推翻上述静态链时启用（见 §3 P2 分支）。C7-① 的收口形态改为「**空集 + 前置条件登记**」：未来若重启 Rust features 接管（bit1 清零），MUST 先落该会计再翻默认。

其余顺序敏感面（诚实声明，#107 R3 增量的 C3 家族）：`beardifiers: RwLock<HashMap>`（每 chunk insert/无 remove，内容中性）、`terrain_cache`/`est_l2`（纯 memo，只改命中率）、结构 beardifier 的跨 chunk 可达性（vanilla 同形异步，非新增分歧类）——均由 §3 的 C7-② run 级基线测量覆盖，不单独造仪表。
