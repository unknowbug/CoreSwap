# 架构设计：-P→-D 开关生效机械对账（260917-06）

## 1. 全局视图

### 目标
把「`-P` 开关是否真能生效」从**人工自证行**升级为**机械对账**：建立单一事实源（开关登记表），机械核对三方一致性——
- **M1 声明面**：`build.gradle` 的 `findProperty(...)` → `run.vmArg "-D..."` 映射；
- **M2 消费面**：源码中的 `System.getProperty` / `Integer.getInteger` / `Boolean.getBoolean` 读取点；
- **M3 使用面**（可选加强）：采集脚本/文档里实际传入的 `-P` 名。

### 排除项（明确不做）
- 不改任何现有开关注册行为、不重命名开关（避免污染历史口径）；
- 不引入运行时反射扫描（本项为**静态**对账，成本必须低）；
- 不做「开关→语义」的正确性判断（那是各课题的判据面）。

### 差集样例（须逐条定性，非一律判为 bug）
- **M1∖M2（32）** 例：`cpp.worldgen.dir`、`coreswap.rust.stages`、`coreswap.stallwatch`、`cpp.blockRegister`、`lightDataDump`、`biome6*`……其中多数**由别的 carrier 消费**（CppBridge 在 java-core 侧、native 侧读 env、或作为 JVM 参数被 Java 之外读取）——⇒ 需**跨 carrier 消费面扩展**，不能只看 versions/1.20.1/java/src。
- **M2∖M1（18）** 例：`coreswap.light.blockabi`、`coreswap.light.oldcollect`、`coreswap.exec`、`coreswap.maxinflight`、`bench.threads`、`blobProbe.*`……多数是**探针期直接 `-D` 手传**（不走 `-P`）——⇒ 属**合法旁路**，但必须显式登记「该开关的合法载体 = 直接 -D」才能与「漏映射」区分。

## 3. 任务拆解 & 依赖图

```
T1 开关登记表 schema + 生成器（从 build.gradle 机械抽取 M1）
      ↓
T2 消费面抽取器（全 carrier 扫描 M2：versions/1.20.1/java/src + java-core + worldgen-core + scripts）
      ↓
T3 对账器 + 三态判定（CONSISTENT / DEAD(无消费) / ORPHAN(无声明) / SCOPED(合法旁路需登记)）
      ↓
T4 逐条定性 50 个差集项（人工+机械辅助），产出登记表初稿（含每条理由）
      ↓
T5 落地：登记表入仓（单一事实源）+ 门禁脚本 + AGENTS.md 纪律条款
```

依赖：T2 依赖 T1（同一 schema）；T4 依赖 T2/T3；T5 依赖 T4 定稿。

## 6. 风险 & 回退

| 风险 | 处置 |
|---|---|
| 跨 carrier 消费面漏扫 → 误判 DEAD | T2 必须先**枚举 carrier 边界**并在产物中声明覆盖面；未扫描的 carrier 一律标 UNKNOWN 不判 DEAD（§9.7） |
| 差集项数量大（50）→ 定性成本高 | 分类批处理：明显旁路（如 `coreswap.*` 探针直传）批量登记 SCOPED（带 reason），只对可疑项逐条查 |
| 登记表成为新的事实源漂移点 | 登记表**由 T1 生成器机械产出**（不从手工维护起步），人工只补 `reason` 字段 |
| 与历史口径冲突（#156 家族：口径失传） | 本项只**登记**不**改名**，零行为变更；门禁初版为**报告级**（WARN），不阻断 |

## 8. fan-out 步骤预置

- **节点：T4 逐条定性**。分叉点 = 同一差集项可能有 ≥2 互斥定性（「合法旁路」vs「漏映射 bug」vs「该开关已废弃」）。
- 候选：`.b1` 旁路类（探针直传/其它 carrier 消费）、`.b2` 缺陷类（真漏映射/真死开关）、`.b3` 废弃类（历史遗留应删）。
- 规则：**≥2 互斥候选并存时 MUST 并行 fan-out**（禁主会话自推）；各 worker 产出 `.bN` 候选清单 + 理由，主会话收敛 → judge。
- 自检提示：若主会话对某差集项深钻到第二轮仍无定论，即为 fan-out 触发信号。

## 9. 知识库更新

- 结论性落盘（workflow-patterns / build-tooling / AGENTS.md 条款）：**subagent 产出草稿 → 主会话应用 + 验证**。

## 11. 验证方式（Phase 2.5）

- **载体**：静态抽取 + 一条**实测哨兵**（选 1-2 个开关，用 `-P` 传参跑 `gradle --dry-run`/采集脚本，核 `-D` 是否真出现在 JVM 参数面——#37/#81「生效证据必须行为化」）。
- **分层声明**：静态对账 = Degraded（静态审查）；哨兵实测 = Partial（单点行为化）。**MUST 分别声明**，不得把静态对账称 Full。
- **判据预登记**：T3 分类规则必须在跑之前写死（#112），差集项的定性策略（H2）须在 T4 开工前登记。
