# DFC C++ 完整实现架构（重量模式）

## 1. 全局视图

### 目标
把已通过 GPU e2e 验证的 DFC 采样逻辑（GLSL `final_density.comp`）移植为 **C++ 后端**，接入 `fillOneChunkCore` 的 density 阶段，替换 production `SplineDF` 的虚调用递归 + 指针追逐，从而消除多线程 density 11×（共享内存延迟）。

### 关键前提（已确证，本架构立论基础）
1. **DFC 算法已正确**：GPU shader `final_density.comp` 含完整 `eval_df(eval_density)` + `spline_eval`（显式栈）+ `spline_coord` + `normal_noise` + `old_blended`，e2e 与 CPU finalDensity 对拍 **maxDiff=3.128e-07**（逐位对齐）。
2. **CpuBackend 数据表已生成**（gen_cpu）：splineNodePack/Locs/Ders/ValF/ValKind/ValNode + noise perm + split 行。
3. **11× 根因 = SplineDF 指针追逐 + 长链共享内存延迟**（非虚调用本身）；DFC 连续化（无多态、无散布堆 locFn、连续表）是消除病根的方向。
4. **入口签名已定**：`eval_density(sIdx, ix, iy, iz) = eval_df(20, 0, sIdx, ix, iy, iz)`（root=20 = finalDensity 根节点）。

### 范围（含明确不做什么）
**做**：
- 扩展 `dfc_gen.py` 的 `gen_cpu`，额外生成 **C++ 版采样函数**（eval_df / eval_density / spline_eval / spline_coord / normal_noise / old_blended / interp），输出到 C++ 头文件。
- 用 CpuBackend 数据表（spline 扁平表 + noise perm + split）。
- C++ 接入点做成**对拍管线**：C++ DFC vs production SplineDF（同一 seed/坐标）逐位对比。
- 接入 fillOneChunkCore 的 density 阶段（作为替换路径，env 门控 WG_DFC_CPU=1）。
- 对拍验证：8576/3200 零退化 + 吞吐对比。

**不做**：
- 不改 GPU shader / Vulkan / GpuDensityEngine（GPU 已是另一条线，DFC C++ 是 CPU 路径优化）。
- 不改现有 production SplineDF 的语义（DFC 是并列替换路径，NOT 删除 SplineDF——保证可回退）。
- 不迁移到 Minecraft mod / JNI（只在 worldgen.dll 内）。

### 排除项（架构上明确排除，避免踩坑）
- **不做「放大 MVP」验证**：MVP 复现不了真实共享内存延迟（MT11 已确证）。
- **不改 locFn 为连续对象数组**（多态无法 value 存储）——DFC 数据驱动本身即连续化，是正确路径。
- **不触碰 GPU 编译性能**（D22 编译慢是 GLSL 侧/驱动问题，与 C++ 无关）。

## 3. 任务拆解 & 依赖图（Phase → 任务 → 依赖）

### Phase 1：GLSL → C++ 采样函数映射（识别全部 DF 类型 + 签名）
- 任务 1.1（scout/worker）：读 `final_density.comp` + `dfc_gen.py`，产出「GLSL 采样函数 ↔ C++ 签名」映射表（eval_df 的 DF 类型分派、spline_eval 显式栈、spline_coord coordType 分派、normal_noise/old_blended 数据驱动、interp 8 角点）。
- 任务 1.2（worker）：梳理 CpuBackend 已生成数据表（哪些已有、哪些需 gen_cpu 补生成）。
- 依赖：无。

### Phase 2：gen_cpu 扩展生成 C++ 采样函数
- 任务 2.1（worker）：扩展 `dfc_gen.py` 的 `gen_cpu`，生成 C++ 版 `eval_density/eval_df/spline_eval/spline_coord/normal_noise/old_blended/interp`（复用 CpuBackend 表，仿 GLSL 逻辑翻译为 C++）。
- 任务 2.2（worker）：生成新的 C++ 头文件（dfc_cpu_backend.h 采样函数部分），由 CpuBackend 数据表 + 采样函数组成。
- 依赖：Phase 1（映射表）。

### Phase 3：C++ 编译 + 对拍管线（DFC vs SplineDF 逐位）
- 任务 3.1（主会话）：写 `dfc_eval_pipeline`（对拍工具：同一 seed/坐标，C++ DFC `eval_density` vs production SplineDF `finalDensity->sample`），逐位对比差异 → 验证 DFC C++ 正确。
- 任务 3.2（主会话）：构建（build.ps1 cl 直链）+ 跑对拍（block_probe / 专用探针）。
- 依赖：Phase 2（生成头文件）。

### Phase 4：接入 fillOneChunkCore + 对拍验证
- 任务 4.1（主会话）：fillOneChunkCore 的 density 阶段加 `WG_DFC_CPU=1` env 门控分支，用 C++ `eval_density` 替换 `h->finalDensity->sample(fpos)`（语义一致）。
- 任务 4.2（主会话）：8576/3200 零退化验证（block_probe）+ 吞吐对比（conc_density_probe / bench_chunks，WG_PHASETICK）。
- 依赖：Phase 3（对拍通过）。

### Phase 5：结论落盘（subagent 产出）
- 任务 5.1（knowledge subagent）：DFC C++ 结果（对齐 + 吞吐 + 是否消除 11×）落盘 rootcause + 错误台账 + 10 时间线。

## 6. 风险 & 回退

- **风险 1：C++ 翻译不保真** → Phase 3 对拍逐位验证兜底（maxDiff 目标 <1e-7）；失败则修映射（Phase 1→2 循环）。
- **风险 2：DFC C++ 接入后吞吐不降 11×** → H4 停，回查（可能需进一步优化 DFC 的 cache 局部性或接入粒度）。
- **回退**：`WG_DFC_CPU` 默认关，SplineDF 原路径保底；DFC 可随时关闭。
- **风险 3：gen_cpu 扩展破坏 GPU 生成** → gen_cpu 生成 C++ 与 GPU shader 分离（新增函数，不删现有），GPU 生成不受影响。
