## 0. 课题一句话

520 个 absent chunk（face − E3A 行，其中 322 框内 = 119 z=188 直线带 + 203 散点边带，198 框外）**为何未出现在域批写回面**——即「写回资格」判定链无观测面（idk-E3a1 收窄 → idk-K2a，criteria-260920-02.md:32-33）。本设计给每个 lit chunk 一个**逐 chunk 的路径归属行**，使缺席可分账。

**idk 声明（@anchor.idk 式）**：
- idk-WBQ1：`wgLightNeighbor`/`wgLightHeightOk` 的具体实现体（Mixin:262 前后区域）本设计未逐行核读其回退分支计数——打点只需其布尔结果，不影响本档；若 G3 细分需要「哪个邻缺」，属实现细节（见 §2 P4，需返回值扩展）。
- idk-WBQ2：vanilla 侧（LIGHT_RUST 关 / 回退 vanilla 后）chunk 是否也算「写回」——**判读域限定**：face 定义 = t8 三 dump lit 集 vs E3A 域批写回面（#132 分母口径差），本档只对 **LIGHT_RUST 开臂**打点，缺席判定只在 face（lit 集）内进行，不涉及 vanilla unlit chunk。

## §2 打点方案

**通道**：`-Pwbqual=1` → `-Dcoreswap.light.wbqual=1`（build.gradle 映射行，须过 `python scripts\check_switch_mapping.py` B6-1 门；族内对齐既有驼峰先例 wbprobe/e3aInputHash，build.gradle:123-126）。门控类加载读一次（同 LIGHT_E3A 形态 Mixin:85），默认关，缺省路径零变化。

**计数器**：普通 holder 类 `wg.bench.WbQualStats`（**禁 mixin 类反射自载**，#176，形态 = versions/1.21.6 BlobProbeStats.java:4-11 修复后的正确形态）：`ENTER / INIT0 / PRECHECK_FAIL / COLLECT_FAIL / DOMAIN_SUBMIT / DEGRADE / WB_DOMAIN / LEGACY_ENTER / LEGACY_WB / LEGACY_FB / VANILLA_RET` 全 AtomicInteger；静态 shutdown-hook 或判读脚本读 stdout 汇总行兜底。

**行格式**：单行自包含 `[WBQ] ev=<ev> cx=<x> cz=<z> dk=<domainKey> x3=<kx> z3=<kz> extra…`（dk = `wgLightDomainKey` :529-531 输出；x3/z3 = 域内 3×3 槽位 0..2——南带判读的直接字段）。禁止跨行状态依赖。标签：`ev=enter|init0|precheck-fail|collect-fail|domain-submit|degrade|wb|legacy-wb|legacy-fb|vanilla-ret`。

### 3.2 存在性判据（无阈值带的写存在性）

- **E-存在**：face（t8 lit 集）内每 chunk 必须恰有一个**终态 ev** ∈ {`wb`, `degrade`, `legacy-wb`, `legacy-fb`, `init0`, `vanilla-ret`, `never-enter`}；`never-enter` = face 成员且整 run 无任何 `[WBQ]` 行（light() 未被调用/超窗，逐个登记）。
- **机械读法**：分账表 `face_chunk → 终态 ev → 计数`，7 类计数之和 = |face|（无阈值，恒等式；不满足即 Q7 VOID）。520 缺席的机制归属 = 该分账表中非 `wb` 各类的落点，**先分账后判读**。

### 3.3 判别性判据（两个互斥候选，阈值预登记）

- **H1 南带资格签名**（结构相关）：分账中「资格丧失类 ev」的 chunk（precheck-fail/collect-fail/legacy-fb/never-enter）落在**南带**（dk 槽 z3==2 行；或对无 dk 项按最近批锚 z=2 槽归属，260920-03 口径）比例 ≥ 2× 均匀期望（期望 = 南带面积/总域面积，采集后由 dk 分布实算预登记进判据 json）。
- **H2 均匀随机缺席**：上述比例落在均匀期望 ±20% 带内（criteria-260920-02 P2 同族读法）。
- **混合**：两者都未命中 → 分账式登记逐 chunk 归属，交 judge 强制复核（e3a-criteria §2 同构）。
- **形态门优先（#199）**：任何 H1/H2 读数**只在 Q7 对账通过后**计算；且必须分 `abi=blocks9` / `abi=packed` / legacy 三形态分别出读数，禁止跨形态混算一个比例（形态混算会掩盖单形态签名）。
- 读法写死（#112）：上述阈值带唯一，禁止事后挑读法；z=188 直线带成员（119 个）作为**先验子组**单独出列计数但不并入 H1/H2 分母（直线带结构已 confirmed，非本档判别对象，防循环论证）。

### 3.4 VOID 非零退出

比较器 `wbq_cmp.py`（只读输入、只写 --out json）：Q1-Q7 任一失效、stderr 残缺率 >5%（§4）、对账恒等式破坏 → `exit 1 [VOID]`；判据不可判（数据有效）→ `exit 5` 登记，不冒充 PASS。

### 3.5 覆盖面 / 外推边界（§9.7）

E1（同构建态单变量：同 seed 8576294172403134396、单维度 overworld、1.20.1、LIGHT_RUST+DOMAIN 开臂，LIGHT_PACKED 开/关两 run）；共享观测 key 集 S = `[WBQ]` 行 (cx,cz) ∩ face lit 集。不外推 E2/E3、不外推 1.21.6、不外推 LIGHT_RUST 关形态。与 E3A 口径可比性：`wb` 行数 ↔ E3A 行数应精确相等（同写回时点同循环），此为跨打点面挂钩项（登记进 Q7）。

## §4 窗标签自洽 sanity（#189）+ stderr 残缺率门（#190）

- **窗标签自洽**：本档无计时窗，自洽轴 = **计数恒等轴**——① `[WBQ-SUM]` 各计数器值 = 对应 ev 的逐行计数（脚本机械核对，子段=母段同构）；② `wb` 行 x3/z3 ∈ {0,1,2} 且 (x3,z3) 与 (cx,cz)−3·domainKey 一致；③ P9 `wb` 行数 ≡ 同 run `[E3A]` 行数（同循环同时点，Mixin:834-846）。任一不自洽 → 采集废，不进判读。
- **残缺率门**：`[WBQ]` 行与 FP/其他 stderr 行并发交错可残缺（#190，on2 4.16% 先例）。解析器规则写死：缺任一必需 key 的行记 `malformed`，不崩溃、不静默丢；**残缺率 ≤5% → 报告级登记**（malformed 计数入结果 json）；**>5% → VOID exit 1**；贴线（4-5%）臂登记复跑预案（换 tag 重采，#144/#146 无自动回退）。

## §6 已知风险与降级声明

1. **行号漂移**：本文 file:line 锚 HEAD 版本；打点码合入后行号即漂——引用锚以「方法名 + 本文行号（HEAD 版）」双写，插入点在方法级声明的（P1/P9/P11 等）不受微漂影响。
2. **stdout 量级**：逐 chunk 行 ≈ lit 面 9450 × ≤3 行/run，可控；若 FP-DRV 高频交错推高残缺率超 5%，启用复跑预案而非放宽门（§4）。
3. **G3 reason 细分**（P3）需要 `wgLightDomainReady` 返回细分或旁路判 `wgLightHeightOk`——若实现审查发现注入面代价高，可降级为布尔 `precheck-fail`（reason 字段缺省），H1/H2 读法不依赖 reason，降级须在判据 json 声明。
4. **降级声明（本设计稿本身）**：全文为**静态一手源核读**（Degraded 层，无运行时 trace）；资格链 G0-G8 均带 file:line，但「520 落在哪类终态」未采——这正是本通道目的，非本稿缺口。
5. **idk 遗留**：idk-WBQ1（G3 内部分支计数细节）、idk-WBQ2（vanilla unlit 域不判读，§1 已声明）；`never-enter` 类若无任何行可对，其机制（light() 未调用的上游原因）**不在本档闭合范围**，登记为下一步候选。
6. judge 预置：本通道出候选结论后 MUST judge（分账表 + H1/H2 读数 + Q1-Q7 读数三件一起审）；confirmed 留用户。
