## 候选 ①「嵌套接管管线复查：内层全管线 vs 外层分步拦截的双跑风险」

- **目标文件**：`knowledge/discovered/workflow-patterns.md`（发现 #N，N 按应用时序号）
- **价值门**：高价值（可复用判据 + 反模式，本次课题 P2 矿石归因的机制内核）
- **条目文本**：

> **发现 #N：嵌套接管管线复查——「内层全管线 vs 外层分步拦截」的双跑风险**
> 当宿主管线（如 Java worldgen：NOISE→CARVER→SURFACE→FEATURE）被原生层接管时，必须核对**接管边界与内层实现阶段的包含关系**：若内层（Rust/C++ `wg_fill_blocks_multi`）自己实现了完整管线（含 carver/feature），而外层 mixin 只拦截了部分步骤（populateNoise + buildSurface），未拦截的宿主步骤（CARVER/FEATURES）照跑 → **同阶段双跑**，产物计数系统性偏高（本案矿石 ~2.2×，消融 WG_SKIP_FEATURES 一步定位）。
> **可复用判据**：①「同 dll 存档口径 vs 分阶段消融」两步定位——先跑存档口径基线，再 env 门控逐阶段跳过（SKIP_FEATURES / SKIP_CARVER），单步消融差值直接归因该阶段双跑贡献；②产物计数族 vs 参照邻域——某块族计数 ≈2× ref 是双跑签名（≈1× 落回 ref 邻域即证实）；③**接管边界审计先于归因**——排查「某类块偏高」前先画清「谁拦了哪些步骤 + 内层自己跑了哪些阶段」的矩阵，勿先钻条件链。
> **反模式关联**：与发现 #10（先消融/直连基线后归因）同族——本案是「消融证明双跑」而非「消融排除替换方」，消融方向由接管矩阵决定。
> **遗留注意**：修复勿用进程全局 env 默认翻转（污染其它调用方），用句柄/调用级显式 flag。

## 候选 ②「fs::copy 保留 mtime——产物新旧验证用内容指纹不用时间戳」

- **目标文件**：`knowledge/discovered/build-tooling.md`（若该文件不存在则落 `compiler-idioms.md`，应用时按 INDEX 现状定；建议归 build-tooling——是工具链/构建产物判定坑，非语言惯用法）
- **价值门**：高价值（判错方法/签名，环境坑 E9 的可复用沉淀）
- **条目文本**：

> **发现 #N：fs::copy 保留 mtime——复制链产物判新旧用内容指纹，不用时间戳**
> Rust `fs::copy`（及多数系统 copy 语义）**保留源文件时间戳**：构建/部署链上复制出来的产物，mtime 反映源文件时间而非生成时刻。签名：文件「看起来很旧」但内容是最新的（本案 WorldgenRust.dll 显示 9/1 实为最新构建）；按 mtime 判新旧会误删新产物或继续用旧产物而不自知。
> **可复用判据**：①判产物版本 = 内容指纹（二进制字符串探测 / 哈希），mtime 只作线索不作结论；②凡「复制即部署」链路，默认不信任产物时间戳；③若需真实生成时间，复制后显式 `File::set_modified(now)` 或在产物内嵌构建戳。
