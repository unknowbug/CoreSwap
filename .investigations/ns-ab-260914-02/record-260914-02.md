## 四、过程错误与瑕疵（五段式，诚实声明）

### 瑕疵 1：pickHit 脚本双重重置（统计 bug）
- **现象**：脚本输出 pickHit 恒 0，与 log 实际不符。
- **根因**：脚本编辑残留导致 pickHit 变量被双重重置（机制 = 变量初始化语句重复执行，覆盖了计数）。
- **定位**：主会话手工逐臂扫 stdout+stderr 补验。
- **修复**：数值以手工补验为准（pickHit=2/臂）；脚本 bug 留待修正。
- **教训**：自证脚本的统计字段本身也要有自证（对照 log 手抽一条）；「自证工具输出为零」先怀疑工具再怀疑装置。

### 瑕疵 2：判据未预登记（#112 违例，本 record 最大的过程错误）
- **现象**：主会话在看到数字前没有写死「读法/离群处理」规则。
- **根因**：流程纪律缺口——预登记发生在采集设计中被遗漏，属 #112 同族违例。
- **定位**：本块收尾自查发现。
- **修复**：本 record 采用保守读法——全部数据呈现、离群候选（r1）只标注不剔除、任何剔除只作敏感性附注不作主判据。
- **教训**：**预登记判据必须发生在采集脚本定稿同一时刻**，与 seed 三查同级列入采集前检查单；事后补判据 = 判据污染，只能降级为附注。

### 瑕疵 3：rcon stop ConnectionRefused ×3（open，未查机制）
- **现象**：驱动侧 rcon stop 出现 3 次 ConnectionRefused 重试；服务器均正常退出、汇总行完整（7/7 臂含 smoke1）。
- **judge C2 补充线索**：脚本含两次 `rcon stop` 调用（FAIL 分支 + 正常分支各一；另拾取路径上 stop 在 wb 门后执行时服务器可能已被前序臂 stop 触发的关停序列波及）——「第二次 stop 时服务器已在退出」为机制候选高度可疑，低成本可收敛，本块不展开。
- **根因**：未查（open 登记）。来源为驱动侧控制台输出，不在 server log 内。
- **定位/修复**：未做。
- **教训（暂定）**：不影响本批数据有效性（汇总行完整性已逐臂核验），但后续采集块应记录重试次数与退避间隔，确认无静默截断风险。

## 六、判读（保守读法）

**主对比 = ns/call(total)：**
- bulk：r4/r5 = 3.474M / 3.536M（r1=5.449M 标注为首跑预热候选——JIT/类加载，**不剔除**）。
- perblock：7.218M / 7.344M / 7.598M。
- 配对比（judge C1 措辞修正）：全量读法（不剔 r1）＝ bulk 最差臂 r1 5.449M vs perblock 最好臂 7.218M → **至少快 ~1.32×**；剔 r1 敏感性读法（r1 为首跑预热候选，仅附注不作主判据）＝ bulk 最差臂 3.536M vs perblock 最好臂 7.218M → **~2.04×**；bulk 均值 3.505M vs perblock 均值 7.386M → **~2.11×**。结论 **~2.1×** 由剔 r1 两读法独立支撑（2.04×/2.11×），全量保守下界为 ~1.32×；三读法方向一致（bulk 显著快），量级以敏感性读法 ~2.1× 为准、不得单引 ~2.04× 为「保守值」。

**噪声带量化：**
- perblock 3 臂极差 = (7,597,723−7,217,233)/7,217,233 ≈ **5.3%**（与 #103 ±10% 噪声带同量级偏下 → 单臂不可信的判断被本批证实）。
- bulk 3 臂全量极差 ≈ 36%（以 r1 为基），完全由 r1 主导；剔 r1 附注：极差 ≈ **1.8%**——首跑预热效应显著大于机器噪声带。

**结论口径（candidate 建议）：**
