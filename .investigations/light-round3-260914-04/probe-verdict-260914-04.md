## 1. 任务 1：round2 减法口径证伪确认

### 1.1 证伪成立，但口径必须分层表述（#128/#132）

- **证伪成立（串行成本口径）**：12 篇 L94「Java 段 ≈0.3s/2025 ≈0.15ms/chunk」是 **e2e wall 减法余项**；探针实测 collectAvg = **4.5ms/chunk**（源 T，light 线程串行）——**30×** 于减法推算值。round2 把 3.5s gap 的 3.2s 归因内核、Java 段记 ≈0，在「每 chunk 串行成本」意义上是错的。
- **但二者不可直接比（口径声明）**：wall 减法余项 = ON/OFF 两臂在并行摊销后的净差，不是任何一臂的串行成本。正确的重算是下面的「对价模型」。

### 1.2 重算上限账——ON 臂串行构成 + vanilla 对价模型（新锚）

**ON 臂每 chunk 串行总账（源 T + 源 K）**：

| 环节 | 值 | 来源/口径 |
|---|---|---|
| Java collect | 4.5 ms/chunk（稳态 4.5-4.7，JIT 向下） | 源 T，400 chunk 档 |
| native（JNI 进入+拷贝+内核+出参） | 2.8 ms/chunk（2.77-3.01） | 源 T |
| — 其中内核 | 1.483 ms/chunk（源 K kernelWall 1482.6µs；与源 T nativeAvg 差值 = JNI 边界 ≈**1.3ms**） | 源 K |
| **ON 串行合计** | **≈7.3 ms/chunk** | T+K 合成 |

**vanilla 对价推导（本轮新锚）**：e2e gap = 3.5s/2025 = 1.73ms/chunk ⇒ 隐含 **vanilla 光照串行成本 ≈ 7.3 − 1.73 ≈ 5.6ms/chunk**。交叉佐证：① 12 篇 L49 round1 时代 Java 收集单独 ≈5.6ms/chunk 量级（vanilla propagateLight 全路不走 section 直采/TL 缓冲，成本更高，5.6ms 是下界量级吻合）；② r1 Done 17.465s ≈ 历史 ON 17.4s（12 篇 L94），同 regime 锚一致。**模型：两臂在同一 light 线程池上近似 1:1 串行兑现（boot pregen 阶段光照在关键路径上）**。

**JNI 拷贝分解账（nativeAvg 2.8 − 内核 1.48 = 1.32ms）**：进 3.5MB（10GB/s 下 0.35ms，pin/copy 未定，scout open 3）+ 出 ~244KB（~0.03ms）+ JNI 进入/TL/数组 region 调用残余。若纯带宽只解释 ~0.4ms，残余 ~0.9ms 指向 copy 实现或多调用开销——**open**（C 落地后自然消解，无需单独查）。

### 1.3 结论

round2 的「Java 侧已基本消除」结论**在本口径下证伪**（12 篇 L94 的 3.2s 内核归因分解错误；总 gap 3.5s 本身仍是对的）。修正口径：gap 3.5s = (rust 路 7.3 − vanilla ~5.6) × 2025。**含义反转：可收割面从「内核 1.5ms」扩为「collect 4.5 + JNI 1.3 + 内核 fill 面」≈ 6.5ms/chunk**。§15.4 取代声明：本节取代 12 篇 L94 的 Java 段 ≈0.3s 归因（原正文不删，用户拍板后由主会话按取代链落盘）。

## 2. 任务 2：三候选上限重算（真值代入）

### 2.1 直方图真值要点（源 P）→ 推演参数修正

- 95% bits=4（epl=16 整除无余位）→ B/C 解码主循环形态单一，JIT/Rust 均最优；bits5/6 仅 5%，无 0（无非空 singular 节——fill 特判保留但不命中）、无 15/16（无 ID_LIST，boot pregen 域内）。
- paletteSize 中位 ~10、均值 ≈9.4（直方图加权）→ palette 预编码小表 ~10 项/节，L1 常驻。
- 非空节 79.6/chunk（15924/200）→ 非空节展开格数 = 4096×79.6 ≈ **326k/chunk**；空节 ~136/chunk 已短路。
- 源 K：nonAir 32.6%（288k 格）、sky15 区间格 66.9%（592k 格）、memset **23.6µs 实测**（b1 推 30-90µs，取实值）。

### 2.2 候选 B（Java palette 展开填 blocks9）——上限大幅上修

- 新 collect 构成：空节短路（不动）+ 非空节 326k 格 ×（bits4 解码 ~8-12 条 + tab 索引 + blocks9 写）≈ 指令账 326k×10 条 @ ~0.5-1ns 有效 ≈ 0.33-0.65ms + 3.5MB 散写带宽 ~0.35-0.5ms（与指令部分重叠，取大者一半计）+ palette 预编码 80 节×10 项（<0.01ms）+ 不可消固定开销（节循环/快照读，~0.1ms）⇒ **collect_new ≈ 0.5-1.2ms/chunk**。
- **节省 ≈ 4.5 − (0.5~1.2) = 3.3-4.0 ms/chunk 串行**（vs b2 旧估 0.2s e2e——真值推翻减法口径后上修 ~30×）。
- e2e 预期（1:1 模型，§1.2）：ON 串行 7.3→3.8-4.5ms ⇒ gap 1.73→−0.8~−1.5ms/chunk ⇒ **ON−OFF ≈ −1.6 ~ −3.0s（ON 反超）**；若 wall 兑现系数打 0.3-1.0 折（并行重叠未定的保守带）：**−0.5 ~ −3.0s**。
- 判据预登记沿用 b2 §7（对拍 + golden + chunk 级计时前后对照：collect 段 4.5→≤1.2ms 为主判据）。

### 2.3 候选 C（packed 直传）——上限最高，含 B 的全部 Java 收益 + JNI 面

- 新 collect：palette 预编码 + `System.arraycopy` 拼接 storage（bits4×79.6 节×2KB ≈ 160KB + paletteIds ~3KB + meta 432 int）⇒ **collect_new ≈ 0.1-0.3ms/chunk**（数组拷贝 80 次×2KB + 小循环，指令/带宽均 ~0.1ms 级）。
- native 侧：进拷 3.5MB→~165KB（省 ~0.3-1.0ms，pin/copy 未定给带宽）；内核 fill 读流 3.5MB→165KB（省 ~0.3ms 带宽）但加 Rust 解码 326k×~5-8 条 ≈ +0.2-0.4ms；出参不变。**native_new ≈ 1.4-1.9ms**（含 A-① 表内联随行）。
- **C 后 ON 路径每 chunk 新成本区间 ≈ 1.5-2.2 ms**（collect 0.1-0.3 + native 1.4-1.9）。
- e2e 预期（1:1 + 0.3-1.0 折系数带）：gap = (1.5~2.2 − 5.6)×2025 = −6.9~−8.3ms→**ON−OFF ≈ −2.1 ~ −8.3s**（保守 −2.1、中位 ~−5s）。⚠️ 该预测强烈依赖 vanilla 5.6ms 锚 + 1:1 兑现假设，实测前按量级读。
- 与 A 关系不变：A-① 被 C 吸收（lookup 仍在，直接索引改造随 C 做）；A-② 正交。

### 2.4 候选 A（内核 fill 降维）——真值确认，量级下修

- A-① lookup：非 air 实测 32.6%（288k 格，b1 假设 ≤50 万）→ 25-50µs/chunk（b1 上界 40-80 下修 ~0.6×）。
- A-② fill×sky_fall 融合：sky15 区间格 592k 实测（b1 推 30-60 万，吻合）→ 上限 100-200µs 成立。
- A-③ 清零：memset 实测 **23.6µs**（b1 推 30-90µs）→ 占内核 1.6%，更坐实「无正收益路径，维持现状」。
- **A 合计 ≈ 125-250µs/chunk，e2e 0.25-0.5s（1:1）**——单独仍远不达标（b1 结论维持），价值 = 随 C 的填充件 + A-② 独立小赢。
