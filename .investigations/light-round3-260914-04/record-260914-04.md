## 5. 过程错误（五段式，详录供知识库）

- **W1 packed 收集漏读 writeLongArray 长度前缀**：现象 = 解码值恒撞 idx=15 v=8 + 流尾残留 bufLeft=2 + nativeAvg 反升伪装「packed 更慢」；根因 = B 路有 readVarInt 而 packed 路算了 n 没读前缀（帧整体错位 2 字节，w0 前两字节 0x80 0x02 = VarInt(256) 本体）；定位 = 合成帧单测排除 Rust 本体 → 分层 rc（-6/-2）定层 → Java 原始帧 dump 一锤定音；修复 = 补 readVarInt + 校验 nLen==n；教训 = **「部分成功」比全红更危险**（singular 节不经位流全免疫 → 全 singular chunk 成功 + 对拍 4 chunk 假绿；协议解析改动必须用「含位流节」的用例覆盖，只含 singular 的成功不构成帧解析证据）。
- **W2 DUALP 初值自关闭**：`WG_DUALP_DIFF = -1`（未启用语义）但门控判 `>= 0` → 输出层对拍从未运行；定位 = r3 臂缺 DUALP 行 + nativeAvg 反常（4.36>2.86）→ 两信号交叉锁定 packed 未生效，反推对拍门也没跑；修复 = 初值 0。教训 = 状态机初值与门控谓词必须成对核对（#81 家族）。
- **W3 e2e 脚本返回值污染**：Run-Arm 内 Write-Output 与 return 数值并存 → 汇总解析把 [ARM] 行当数字；修复 = [Console]::WriteLine。教训 = PowerShell 函数「输出流即返回值」，日志与返回必须分离。
- **W4 native 预测偏差**：r7/r8 native 3.2-3.7ms 高于预测 2.2——r9 收尾后 2.65；差异含首 200 chunk 的 4 个回退 chunk 全价 + 批内方差；教训 = 含回退路径的均值读数须以「回退计数 = 0」为前提（paldump 采样 0 节是零回退的廉价直证）。
