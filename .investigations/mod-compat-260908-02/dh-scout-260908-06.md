## 1. distantGeneratorMode 键名 / 可选值 / 默认值

**【一手·jar 常量池】3.2.0 确切键名仍为 `distantGeneratorMode`**（camelCase，单键，位于 toml 的 `generation.mode` 分类路径下，同组还有 `enableDistantGeneration` = `generation.enable`）。
出处: `com/seibel/distanthorizons/core/config/Config$Common$WorldGenerator.class` 字段名 `distantGeneratorMode` + 配置路径字符串 `generation.mode` / `generation.enable`。

**【一手·重要修正】3.2.0 枚举值 ≠ FEATURE_GENERATOR/INTERNAL**。`EDhApiDistantGeneratorMode.class` 的 values 顺序为:
1. `PRE_EXISTING_ONLY` — 只为已生成 chunk 建 LOD
2. `SURFACE` — 生成地表（不含树/结构）
3. `FEATURES` — "Generate everything except structures"（除结构外全量生成）
4. `INTERNAL_SERVER` — 让本地 server 生成/加载每个 chunk（最兼容、结构正确、会写 MC region 文件）

即 **2.x 时代的 `FEATURE_GENERATOR` 在 3.x 已拆分/改名为 `FEATURES`（+新增 SURFACE）**，`INTERNAL` 改名 `INTERNAL_SERVER`。任务书中的 "FEATURE_GENERATOR" 字面值在 3.2.0 不存在，直接写入该值会解析失败/回落默认。web 侧枚举 javadoc 同名佐证: https://distant-horizons-team.gitlab.io/distant-horizons/com/seibel/distanthorizons/api/enums/worldGeneration/EDhApiDistantGeneratorMode.html

**默认值【候选，jar 字节码级】**: `Config$Common$WorldGenerator.<clinit>` 中 `getstatic FEATURES` 先于 comment StringBuilder 出现，符合 `new ConfigEntry.Builder<>(EDhApiDistantGeneratorMode.FEATURES)` 模式 → 默认 = `FEATURES`。未做运行时 toml 落盘核对，置信度 candidate；首个客户端启动后直接读 `config/DistantHorizons.toml` 的 `distantGeneratorMode` 行即可廉价确认。

## 3. 单人（integrated server）下 FEATURE(S) 模式走线

**【一手】`GenerationEvent_forge.class` 存在 `INTERNAL_SERVER` 分支 + `InternalServerGenerator_forge` / `generateChunksViaInternalServer`** —— `INTERNAL_SERVER` 模式通过 Forge 侧 wrapper 驱动**本地 integrated server** 的真实 chunk 管线生成；`FEATURES` 模式走 `BatchGenerator`/`BatchGenerationEnvironment_forge` 的**进程内独立批量生成环境**（DH 自持 worldgen 调用，不排队 server chunk，不写 region 文件——枚举注释明示只有 INTERNAL_SERVER "DOES save generated chunks to Minecraft's region files"）。
对 CoreSwap 的含义: 若 Rust 已接管 integrated server 的 chunk 生成管线，则 **INTERNAL_SERVER 模式直接吃到 Rust 地形**；FEATURES 模式走 DH 内部生成路径，其输入是注册过的 biome/feature/noise 数据——CoreSwap 若只换 server 管线，FEATURES 模式**不会**经过 Rust。首选 INTERNAL_SERVER 验证「LOD 继承 Rust 地形」最稳。
**服务端安装问题**: DH 官方 Server Owners wiki（ https://gitlab.com/distant-horizons-team/distant-horizons/-/wikis/1-user-guide/1-frequently-asked-questions/5-server-owners/Server-Owners ）说明专服需装 DH 才能向远端客户端供 LOD；单人场景 integrated server 即本机两端，客户端装 DH 已覆盖两端（jar 为 fabric-forge 合一，server 逻辑同 jar 内）。@anchor.idk("3.2.0 内部 server-side 检测的具体开关类名未提取——不影响单人场景结论")。

## 4. 行为化日志签名（供 client_run.log 确认）

【一手·常量池】：
- `[DistantHorizons] Config initialised` — 配置初始化完成（INFO，启动期）
- `Batch Chunk Generator initialized` — `BatchGenerator` 初始化（生成器挂载，模式无关）
- 错误签名 `,no target step defined for generator mode: [`（后接模式名）——若模式→生成步骤映射失败会打此行，可用于发现无效模式值
- `Error starting future for chunk generation, error: [` — 生成 future 启动失败
- 进度显示组配置键 `generation.logInterval` / `generationProgressIncludeChunksPerSecond`（打开后周期性打生成进度+chunks/s——DEBUG/INFO 具体行文案 @anchor.idk("进度日志行精确文案未从常量池提取，需运行时确认")）
- 日志级别门: DH 有 `DhLoggerBuilder`/DEBUG_ID_REF 体系，DEBUG 行需在 DH 配置（logging 分类）开 debug 才可见。
