## 1. 接管拦截面（Java 侧）

接管链路图 [已验证-源码引用]：

```
BenchMod.onInitialize (BenchMod.java:15-43)
  └─ SERVER_STARTED: active = (replace || !anyProbe) && !vanilla   // L36
      ├─ CppBridge.init(server.getOverworld().getSeed())           // L38，overworld 句柄
      └─ CppBridge.initNether(server.getOverworld().getSeed())     // L40，nether 句柄（硬编码 nether.json）
            └─ CppWorldgen.initDim(seed, dir, "nether.json", "biome_params_nether.json", 256)  // CppBridge.java:120
                  └─ (JNI) wg_create → WorldgenHandle::create_for_dim

NoiseChunkGeneratorMixin.wgPopulateNoise（mixin/NoiseChunkGeneratorMixin.java:41-78）
  注入点 = NoiseChunkGenerator.populateNoise HEAD, cancellable
  判定条件（L56-77）：
    ① CppBridge.enabled（全局开关，init 成功即 true）      → 不满足 return（vanilla）
    ② overworld 形状: bottomY==-64 && height==384          → fillChunk(overworld 句柄) + cancel
    ③ netherShape: bottomY==0 && height==256
       && !wgIsEnd()（biomeSource instanceof TheEndBiomeSource，反射 ChunkGenerator.biomeSource）
       && CppBridge.netherActive()                          → fillChunkNether(nether 句柄) + cancel
    ④ 其余（形状不匹配 / end / mod 维度）→ 不 cancel → vanilla Java 管线
  wgBuildSurface（L82-98）：同形状判定，仅对已接管维度 cancel；其他维度放行 vanilla buildSurface
```

**关键事实：维度判定只有两类「形状指纹」（min_y/height 数值比较），没有任何 ResourceKey/LevelResource/dimension-type/registry-key 判断** [已验证-源码引用 NoiseChunkGeneratorMixin.java:57-60]。end 的排除靠 `wgIsEnd()` 反射 biomeSource 类型（L27-38），mod 维度完全不在判定逻辑里（既无名字也无 settings 识别）。

CppBridge 句柄数：恰好 2 个（handle=overworld、netherHandle=nether），initNether 是唯一第二个维度入口 [已验证-源码引用 CppBridge.java:21-25,116-131]。destroy 双置零 L371-378。

## 3. 维度数据面

- 资源层 = `runtime/1.20.1/java/src/main/resources/worldgen-data/`，noise_settings 只有 vanilla 7 个（overworld/nether/end/caves/amplified/floating_islands/large_biomes）[已验证-glob 实测]。**aether 等 mod 维度的 noise_settings/biome/density_function JSON 不在 CoreSwap 资源层，Rust 不可能读到** [已验证-源码引用 CoreSwapFixHelper.extractWorldgenDir 只解压本 mod jar 的 worldgen-data/，CoreSwapFixHelper.java:35-59]。
- wgDir 来源：jar 内 `worldgen-data/` 解压到 `<tmp>/coreswap-data/worldgen`，marker 校验 overworld.json（CoreSwapFixHelper.java:39）；blocks.json/biome_params*.json 在 wgDir/../（worldgen_handle.rs:305,310）[已验证-源码引用]。
- 理论通路（若未来打包 mod JSON）：create_for_dim(settings_name=任意文件名) 支持 mod 维度文件名（worldgen_handle.rs:137 注释明确写了「mod 维度自定义」），df 目录按 df_ns 隔离——**API 已具备，数据与判定未接** [已验证-源码引用]。

## 4. 反例豁免候选（水晶 0.8% / 混沌 0.02% 基本正常）

- **候选 A（最可能）：mod 维度形状不匹配任何接管指纹 → populateNoise 不 cancel → 走完整 vanilla Java 管线** [推测，但由判定逻辑强支持：mixin 只认 -64/384 与 0/256 两种形状（NoiseChunkGeneratorMixin.java:57-60,72），mod 维度若 min_y/height 不同则永远 vanilla]。0.02%~0.8% 残差可解释为 vanilla 本身的跨平台/浮点小噪声或与 Rust 输出的偶然交集。
- **候选 B：mod 维度形状恰好 = 0/256（同 nether）→ 被 nether 句柄错误接管** [推测]——若 aether 类维度是 0/256，会用 nether.json 数据生成（错 noise_settings/biome），应产生大面积损坏；水晶/混沌正常说明其形状大概率 ≠ 0/256 或 ≠ -64/384。
- **候选 C：	wgIsEnd() 反射在 Forge+Connector（Mojmap 字段名 biomeSource）下成立，但 mod 维度 biomeSource 非空类型不影响**——反射只排除 TheEndBiomeSource，对 mod 维度无豁免作用 [已验证-源码引用 NoiseChunkGeneratorMixin.java:27-38]。
- **候选 D：维度类型为非 noise generator（flat/custom）→ 根本不走 NoiseChunkGenerator.populateNoise → mixin 不触发** [推测；FlatChunkGenerator 等不继承 NoiseChunkGenerator，勘探未列 world gen type，需 worker 确认目标 mod 维度的 generator 类型]。

## 5. 末地子疑点（end 也 38% 失败）

- end.json noise_settings 存在于资源层 [已验证-glob]，但 **Java 侧无任何代码加载 end**：grep `end.json`/initDim 全仓，生产调用只有 overworld(init) 与 nether(initNether) [已验证-grep]。
- end 形状 = minY 0 / height 256 = netherShape [已验证-vanilla 1.20.1 事实，mixin 注释 L23 自认]；正常路径靠 `wgIsEnd()` 排除 → end 走 vanilla。
- **风险点：wgIsEnd() 反射失败时 catch 返回 false（L36「反射失败→不排除」）→ end 落入 nether 分支，被 nether.json 句柄接管 → end 用 nether 的 noise_settings/surface/biome_params 生成 = 大面积错误地形**。38% 裸 bedrock 与「错误 settings + fail-safe 填充」形态相容 [推测——需日志/复现确认：看是否有 `[Mixin] populateNoise(nether) intercepted` 出现在 end chunk；另 Forge+Connector 下 ChunkGenerator.biomeSource 字段名是否为 Mojmap `biomeSource` 未验证，若字段名不匹配即稳定反射失败]。
- 次要候选：`wgBuildSurface` cancel 判定同样依赖 wgIsEnd（L94），若误判会把 end 的 vanilla surface 也跳过而 Rust 未提供 end 表面 → 双重损坏 [推测]。

## 6. 结论一句话

接管判定 = 「chunk 形状指纹（min_y/height）匹配 + 该形状的句柄已 init」，全链只有 overworld/nether 两个白名单句柄、零维度 registry 识别；mod 维度数据不打包、end 仅靠脆弱的 biomeSource 反射豁免——与「非主世界维度大面积损坏、个别维度正常（形状不匹配→vanilla 放行）」现象分布一致。
