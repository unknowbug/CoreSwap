## W1 harness dll 自证正则失效 ⇒ C1 臂被误判 `ARM-VOID`

**现象**
- C1 判别臂（1.21.6 `probe-b2a-WBTEST`，radius 16）被运行台判为血统不符 ⇒ `ARM-VOID`（该臂按设计「不当证据」丢弃），但该臂日志内**确实存在**合法自证行。
- 真实自证行格式（`evidence/arm-summary-260912-02.txt:6` 原文，1.21.6 fix-bulk 项）：
  `[CppBridge] dll=E:\PYTHON\CoreSwap\.tmp\java-tmp\coreswap-native\worldgen.dll size=2457088 sha256=abd7d8893d22e030...`
  ——即 `dll=<path> size=<n> sha256=<hash>`，**三个字段**，path 与 hash 不相邻。

**根因**（机制层面）
- 模式写成了匹配 `dll= sha256=`（假定「`dll=` 后紧跟 `sha256=`」），与真实行格式不符 ⇒ `Select-String` 匹配失败/提取组落空 ⇒ 解析值退化为 `NONE` ⇒ 与 `$ExpectDll` 比较失败 ⇒ 误判 `ARM-VOID`。
- 后果性质：不是「漏判」，是**把有效臂当废臂丢弃**——比漏判更危险（可掩盖真差异，且丢弃行为看起来是「纪律执行」）。

**定位**（怎么发现的）
- 触发点 = 按 E1 教训「逐臂读 `[CppBridge] dll=` 自证行」时该臂被判 VOID；把模式对**真实日志行原文**跑一次即暴露（证据行 `evidence/arm-summary-260912-02.txt:6/:11/:16/:21/:26` 五臂同格式）。
- scout 独立复核记录：`scout-interpretation-A1.md:299`（D5）「`:82` 正则已修（**曾因 `dll= sha256=` 误标**）」。

**修复**
- 模式拆两步、以真实行锚定：先 `\[CppBridge\] dll=` 定位行，再 `sha256=([0-9a-fA-F]{16,})` 提取 hash —— `evidence/tool-run_1216_arm.ps1:79`（定位行）/:82（提取）；1.20.1 台同修 `evidence/tool-run_1201_arm.ps1:64-65`。
- 顺带按 scout D5 残留建议收口：`if ($dllOk)` 才写指纹，ARM-VOID 臂不再产出 fp（`tool-run_1216_arm.ps1:126-131`）。

**教训**（可复用判错经验）
- **自证门的正则 MUST 先对真实日志行验证一次**：先取 1 行原文（`file:line`），再写模式；不得凭接口「看起来应该长这样」写模式。
- 血统门误判的两个方向都要防：漏判（真差异放过）与**误判 VOID**（有效臂丢弃）；两种都在 `ARM-VOID`/`attested` 的**单行可复核输出**上留痕（`tool-run_1216_arm.ps1:139`）。

## W2 指纹归一化正则错误（旧式只剥时间戳、留线程名 ⇒ 跨臂伪差异）

**现象**
- 修复前 C1 臂 fp 行首为：`[Worker-Main-1/INFO] (Minecraft) [STDOUT]: [WG-CONTENT] chunk(…)`（`evidence/fp-1.21.6-probe-b2a-WBTEST.txt:1-5`）；
- 跨臂线程分配不同（Worker-Main-N）⇒ 同一内容产出**不同行** ⇒ 伪差异（违反 §9.7 载体可比性）。

**根因**
- 旧式 `-replace '^\[[^\]]*\]\s*',''` 只剥行首**第一个**方括号（时间戳 `[16:30:24]`），不剥其后的 `[Worker-Main-N/INFO] (Minecraft) [STDOUT]:` ⇒ 线程名与 logger 名被保留进指纹行。
- 深层：以「行首第 N 个方括号」为锚的归一化，在日志格式变化（多一级 logger）时**静默失效**（不报错、只产伪差异）。

**定位**
- scout 复核运行台源码：`scout-interpretation-A1.md:296`（D2）；
- 证据面：新旧 fp 行首形态直接可比（`fp-1.21.6-probe-b2a-WBTEST.txt:1` vs `fp-1.21.6-fix-bulk.content.txt:1` 归一化形 `[WG-CONTENT] chunk(-1,-1) hash=…`），judge 亦据此判定「修复前/后 fp 口径不同、不可直接比对」（`judge-260912-02.md:64` A13）。

**修复**
- 改为以**业务标记**为锚、剥掉其前全部前缀：`($_.Line -replace '^.*\[(WG-CONTENT(-WB)?)\]', '[$1]').Trim()` —— `evidence/tool-run_1201_arm.ps1:104`、`evidence/tool-run_1216_arm.ps1:127`。

**教训**
- **归一化正则 MUST 以业务标记为锚**，禁止以「行首第 N 个 token」为锚；锚到业务标记后，日志前缀再怎么变都不影响指纹。
- 新旧 fp 口径不同 ⇒ **禁止跨口径比对**（本块 `cmp` 清单确实未做修复前/后比对，属正确处理）；若要跨口径，须用同一规则**重生成**（`errors-260912-01.md:136-142` E6 同族）。

## W3 指纹层混用（Rust buf 层与 Java 读回层混在一份）

**现象**
- 旧运行台把 `[WG-CONTENT]`（**Rust buf 层**）与 `[WG-CONTENT-WB]`（**Java 读回层**）**收进同一 fp 文件**；
- C1 臂 `wb=0` ⇒ 该合并件实际只含 buf 层 49 行，却可能被当成「写回内容指纹」使用。

**根因**
- 工具侧未声明层；而两层 `hash=` 是**不同哈希域**（buf 层 = `CppBridge.java:487-493`；读回层 = `BulkWb.readbackHash:338-355`，引用见 `scout-interpretation-A1.md:295`）⇒ 混装即违反 §9.7 可比性三要素的「载体」项。
- 机制后果：层混装不会报错，只会让「等价」结论的**信息域**变得不可命名。

**定位**
- scout 复核：`scout-interpretation-A1.md:295`（D1）；实测该臂 fp「49 行全为 `[WG-CONTENT]`」；
- judge 独立复核 8+8 组对比：每节标题均声明层，工具侧亦有「不得跨层比对」注释，未发现实际跨层比（`judge-260912-02.md:95` D1）。

**修复**
- 增**分层落盘**：`.content.txt`（buf 层）/ `.wb.txt`（读回层），`evidence/tool-run_1201_arm.ps1:100-107`、`evidence/tool-run_1216_arm.ps1:120-131`；
- 合并件保留，仅用于与历史冻结件**字节兼容**（分层 sha 各自同一：`382c497b…` content / `356842cf…` wb（1.20.1）、`ae643ed8…` / `ae5ddee1…`（1.21.6），`evidence/arm-summary-260912-02.txt:36-51`）。

**教训**
- **一份指纹文件 = 一个载体层**；层声明 MUST 同时写进**文件名**与**工具源码注释**（不靠人记）。
- 「合并件只用于字节兼容、不作判据」这条边界要写在文件头，否则下一个会话会把合并件当判据用（本块靠 §9.7 声明与 judge 复核守住）。

## W4 早停截断（`ThrowAbortAt=3` + 10s 轮询把 C1 臂在 ~49 chunk 处掐断）

**现象**
- C1 臂 `status=EARLY-ABORT`；异常级联全部发生在同一秒（16:30:24），**49 chunk 后即停**；汇总行 `[WG-BULKWB] calls=` **缺失**。

**根因**（两环）
1. 工具早退判据 `ThrowAbortAt=3`（`tool-run_1216_arm.ps1:13/:100-101`）配合 10s 轮询粒度（`:96`）⇒ 第一次轮询读数时就可能已 ≥3 次抛 ⇒ 轮询精度决定「多快掐断」，与实际失败进度无关；
2. 早退后 `stop` 流程未等到 destroy/shutdown hook ⇒ `BulkWb.reportSummary()` 未执行 ⇒ 汇总行缺失（`scout-interpretation-A1.md:288` U6：**不是**「未启用分块编码器」，`LOG` 已开且 `:139` 的 `state_ids_size=` 行来自 LOG 门控）。

**定位**
- scout 复核 `scout-interpretation-A1.md:297`（D3）；判读依据 = 三处时间戳同秒 + 覆盖数停在 49；汇总行缺失的机制由 U6 定位（destroy hook 未完成）。

**修复**
- 本块**未改该旋钮**（它服务于 260912-01「等 `Task finished` 卡 40 分钟」的既有修复目的，属工具特性）；
- 处置 = **声明覆盖面**：该臂计数型判据只代表前 ~49 chunk，不得写「所有 chunk」；本块主判据改用 radius 160 修复后臂（625/607 行两层全量，`evidence/arm-summary-260912-02.txt`）。

**教训**
- **早退是工具特性，但会被读成覆盖面**：凡早退臂，判据 MUST 标注「只覆盖前 N chunk」；
- **汇总行缺失 ≠ 路径未启用**（U6 教训）——「没有证据」与「证据显示未发生」必须分开写。

**定位**
- worker 判据复核指出（`verify-260912-02.md:168` §5 第 1 项）；
- judge 在补跑件末段读到字面比对并据此判「完全闭合，但记录引用滞后」（`judge-260912-02.md:74` B2，引 `cmp-260912-02-att-raw.txt:95-101`/`:103-109`）。

**修复**
- 补跑两条**字面**比对（零构建零运行）：`evidence/cmp-260912-02-att-raw.txt:93-109`，两条均 `607/607 common=607 only-pre=0 only-post=0 identical=YES`；
- 记录改引字面行号（judge SHOULD-1 要求；`verify` §6.2 的传递表述保留但降为补充）。

**教训**
- 对比清单 MUST 由「**层 × 臂**」矩阵**机械生成**，禁止手写枚举（手写必然漏，且漏项在结论上不显形）；

2. 仓库内存在 **5 个 legacy「裸列表根」片段**（注释行后直接 `- id: …`）：`.artifacts/8576-24blocks/{aquifer-wateredge,biome-fix,biome-terracotta,followup,surface-plus1}/index-entry.yaml`（本件已读 `biome-fix` 一份核实：`:1-4` 为三行注释 + 顶格列表项）；
3. `collect_fragments()` 用 `glob('.artifacts/**/index-entry.yaml')` **递归收集**（`:59-60`）且**无 per-file 容错/跳过** ⇒ **一个不合规片段即中止全项目合并**（fail-fast 无隔离）。
- 附带副作用（同源）：`ENTRY_KEYS = ('id','path','kind','status')`（`:37`）⇒ 写回**丢弃注释**，会把带注释的权威条目降级为裸条目、并静默丢失结论摘要（根 `index.yaml:1190` 已警示）。

**定位**
- 直接复现（dryRun 即崩溃，栈指 `norm_entries`）+ 源码三点定位（`:52` 无类型分支 / `:59-60` 递归 glob / `:95` 调用点）+ 逐文件读 legacy 片段确认「裸列表根」形态 + 比对工具 sha（项目内副本 = 上游版）。

**修复**（本块 a+b 并行；均为**绕过**，非改工具——`merge_index.py` 属 RE-Framework 只读域）
- a) **手工应用 + 本地校验**：主会话把 260912-02 的 4 条（**带注释**）追加进根 `.artifacts/index.yaml`（本件作者已核到该 4 条位于 `:1462-1524`），并用本地校验脚本 `.tmp/shared-java-core-260912-02/check_index.py` 核对「片段 ↔ 根 index」的 `id/path/kind/status` **逐字段一致 + 幂等**（实测 `IDEMPOTENT-CONSISTENT`，根 index 260912-02 条目 = 4）；
- b) 片段置于**标准采集路径** `.artifacts/shared-java-core-260912-02/index-entry.yaml`（本件作者原写路径 `.artifacts/index-entry-260912-02.yaml`，主会话已迁入），工具修好后可直接采集（届时因 id/path/status 相同被判「已存在，跳过（幂等）」）。

**教训**
- **共享工具的输入契约 MUST 在执行前验证**（顶层是 mapping 还是 list？）：「工具报错」被误当成「我的片段写错了」的成本，高于先读 5 行源码的成本；建议上游给 `norm_entries` 加 `if isinstance(data, list): entries = data`，或改为**逐文件容错 + 跳过并报告**（一个坏输入不应让全局操作失败）。
- **工具的写回副作用必须在采用前核实**：只保留 4 字段 ⇒ 带注释条目会被降级、重跑会静默丢叙事 ⇒ 采用前 MUST 确认「注释是否为权威载体」并准备手工路径。
- **跨仓库工具（RE-Framework）不能假设在本项目内可用**：登记类工作须有 fallback（手工应用 + 幂等校验脚本）并在片段头写明「工具当前不可用 + 权威落在根 index」，否则下一个会话会重复踩同一栈。

| # | 判错经验 | 来源 |
|---|---|---|
| 1 | 自证门的正则 MUST 先对**真实日志行**验证一次；血统门「误判 VOID」与「漏判」同危 | W1 |
| 2 | 归一化 MUST 锚**业务标记**，禁止锚「行首第 N 个 token」 | W2 |

| 5 | 对比清单由「层 × 臂」矩阵机械生成；sha 传递只能当补充 | W5 |
| 6 | **等价性结论 MUST 与臂变量生效自证配对**（in-log / 逐臂 / 正负成对） | W6 |
| 7 | **计数 MUST 声明载体（一次 JVM 运行）**；同一判据的旧诊断必须继承（禁止把可控口径缺陷写成环境噪声） | W7 |
| 8 | **汇总数字入记录前回底本复算 + 绑定臂标签**（本族已复发：E4 → W8） | W8 |
