## 四、判读

1. **摆动带量化**：固定 `-Xmx2G` 后，peakPriv 仍有 **~110.9MB（~6.7%）极差**的 run 间摆动；peakWS ~7.0%。GC 侧稳态 used（lastUsedAfter）摆动小得多（~4.4%，~22MB）。即：**#119 固定 -Xmx 后，峰值进程内存并非钉死**——G1 堆高水位机制带来的摆动收窄但未消除，量级从 1.7× 降到 ~7%。
2. **口径建议（内存回归判据草案，candidate）**：
   - 载体必须固定 `-Xmx`（#119 结论，本块实证 pickup 行双通道自证可行）；
   - n≥3 同配置串行 run，取 peakPriv 极差带（本口径：~6.7%，绝对带 ~111MB）作为本底噪声带；
   - live-set 代理用 GC 停顿后 used 稳态值（本口径末段 ~381–417MB，lastUsedAfter ~480–502MB）；
   - **超出摆动带才算信号**——单次 run 的 peak 内存数字（尤其 ±100MB 内变化）不构成回归/优化证据。
   - **信号判定操作定义（judge C1 补）**：① 单次 run 超带（peakPriv > 本口径上界 ~1757MB 或 < 下界 ~1645MB，按 n=3 极差外推 ±0 缘裕量）只作**线索**不作信号；**连续 n≥2 超带**（同向）才立信号课题；② 带缘裕量：在 n=3 样本量下不设裕量，但**判据首次使用后 MUST 用首用 run 再校准带**（升 n=5 或按新极差重算）；③ 带本身绑定载体口径（§9.7 三要素），换 -Xmx/region/seed 须重测带，不得跨口径引用。
3. **峰值通道选择**：peakPriv 与 peakWS 极差比例几乎一致（6.7% vs 7.0%），peakPriv 含 native+堆 committed 更贴近进程真实足迹，建议回归判据以 **peakPriv 为主、peakWS 为辅**。

## 五、错误记录（五段式：r1/r2/r3 VOID）

**现象**：前置臂 r1/r2/r3 gc log 为 160 字节空壳（如 `gc-*-r6-18220.log` 盘上现存 160B），pauses/used 数据全缺；同时自证门第一版只扫 stdout，stderr 里的 `-Xmx` pickup 行未被门覆盖——门拦截判 **VOID**。

**根因**（机制层面，两处独立缺陷叠加）：
1. PowerShell **scope 语法吞变量**：脚本里 `$gcl:time` 被 PowerShell 解析为「drive-qualified 变量」（`$<drive>:<path>` 语法，如同 `$env:PATH`、`$function:x`），`gcl` 被当作 PSDrive 名去解析，而非变量 `$gcl` + 字面量 `:time`——gc log 路径变量取值为空，`-Xlog:gc:file=` 落到非法/空路径，log 成 160B 空壳。这不是 gc 参数写错，是 PowerShell 变量名的词法歧义。
2. 自证门**扫错了流**：`JAVA_TOOL_OPTIONS` 的 pickup 通告行由 JVM 打到 **stderr**，第一版门只匹配 stdout——`-Xmx` 实际未生效（或未实证生效）时门也放行，自证失效。

**定位**：读 VOID 臂产物发现 gc-*.log 恒为 160B；对照 `.log.err`（~6.9KB，VOID 臂）与 r4-r6 `.log.err`（~7.0KB）体积差追到 pickup 行流向；PS 侧用最小复现确认 `$gcl:time` 解析行为。

**修复**：① gc log 路径变量改 `${gcl}` 包裹（`${gcl}:time`）或换名避开冒号歧义；② 自证门改为同时扫 stdout+stderr 的 pickup 行，`xmxApplied` 计数 daemon+server 两条（=2 才放行）；③ 修复后**换新标签 r4-r6 重跑**，VOID 轮 r1-r3 留档不删不覆盖（#146）。

**教训**（判错经验，高价值）：
1. **PowerShell 变量后接冒号必须 `${}` 包裹**——`$var:xxx` 会被解析为 drive-qualified 变量（`$env:` / `$function:` 同族），静默取空不报错。凡「变量名 + 冒号 + 后缀」拼字符串场景一律 `${var}:xxx`。
2. **自证行的落物流向必须先实证再写门**：`JAVA_TOOL_OPTIONS` pickup 走 stderr 是 JVM 行为，不是想当然的 stdout——门禁覆盖面 = 被证通道的全集（stdout+stderr），漏一条流 = 假放行。
3. 判据价值：本次 VOID 判据（gc log 160B 空壳 + pickup 流未覆盖）本身是「测量有效性自证门」的可复用签名——**任何 JVM 参数注入类测量，先验证注入通道产物非空 + pickup 行在正确流上，再采数据**。
