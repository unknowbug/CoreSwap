### 1.3 级联机制（b1 框架的核心推论，本轮新明确）

Java forEach（PlacedFeature.java L57）与 Rust visit DFS（placement.rs:469-474）都是**单一流串行**：
`树1 base 抽样（count→x→z）→ 树1 generate（内部 N 次 draw）→ 树2 base 抽样 → …`
因此 §1.2 任一分叉源在树 i 内造成的消费次数差，会**级联平移树 i+1…树 10/11 的 base (x,z)**（forest 的 trees_birch_and_oak placed count=10/11，trees_birch_and_oak.json L4-18；plains 为 0/1，trees_plains.json L4-18）。v19 单 chunk（37,-16）有 28/51 根 log = 一个 10-11 位置的 run 内的树族，级联窗口足够。

## 2. v19 双签名在 b1 框架下的自洽性裁决

### 2.1 x/z 整体错位——自洽（有明确演化路径）

1. decorator seed 一致 → 第一次 count draw 一致（weighted_list 9/10 抽 10、1/10 抽 11）。
2. 树 1 的 base (x,z) = 树 1 的 in_square 两抽，**此时流尚未分叉 → 树 1 base 两边应一致**。
3. 树 1 generate 内部经 D-1~D-4 任一分叉源消费次数漂移 → 树 2 起 base 全部平移。
4. 预期签名：第一个（或前几个）base 重合，后续全部错位，重合叶块少量（v19 common=114，log 列共 6 列重合——量级相容但**未证明是树 1**，见探针 P2）。

### 2.2 birch 缺失——b1 框架内**弱自洽**，存在更强竞争解释

- b1 内解释：trees_birch_and_oak 的种类选择 = 每次尝试 1 抽 nextFloat（0.2 birch / 0.1 fancy / default oak）。流分叉后 rust 的抽法序列整体漂移，10 次尝试全落 oak 概率 ≈ 0.8¹⁰≈10.7%（独立近似，实际流相关非独立）——**可能但弱**；java 55 birch 叶 ≈ 1-2 棵 birch。
- 竞争解释（b2 域，非本轮假设但如实陈述）：birch 只来自 `minecraft:trees_birch_and_oak`（forest biome feature，biome\forest.json:81）。若 rust 侧该 chunk 的 3×3 biome 并集（worldgen_handle.rs:932-944，Y 切片 [0,64,128] 近似 = IDK-1 自认）**漏采 forest**，则该 feature 根本不进 int_set → birch 恒 0 + 整个 feature 的 p 集不同 → 同 step 其它树 feature 的执行序与流基点也变 → **x/z 错位与 birch 缺失一次性全解释，无需级联**。260905-08 b6 已论证「p 不同 = 本 feature 错位」机制。
- 裁决：**v19 双签名在 b1 框架下自洽（经 §1.3 级联路径），但 birch 签名对 b2 同样（更强）自洽；两假设对 x/z 错位的判别点 = 「树 1 base 是否重合」（探针 P2）与「forest 是否在 rust 该 chunk 的 feature 集」（探针 P1）**。b1 不被静态证据否定，也不能被静态证据单独确证——必须运行时探针。

## 3. 结论

**plausible（draft，Degraded）**：
- b1 的抽样公式层（count/in_square/selector/树 placer 消费序）静态一致，无新增分叉；
- b1 成立的唯一路径 = §1.2 D-1~D-4 消费结果分叉 × §1.3 级联机制，该机制静态可确证存在（代码路径一手读实）；
- v19 双签名在 b1 下自洽，但 birch 签名存在更简竞争解释（b2 feature 集差）；探针 P1/P2 可一次性判别。
