## 逐项结论

### 项 1：通道②降级——PASS（带两处 CONCERN，见下）

**逻辑面成立**：
- 483 焦点柱：Rust live（vivo mod = Java 特征长在 Rust 地形上，#66 执行语义）2/2 Y，直接证明「今日 1.0.26 dll 的 Rust 地形在 483 柱上，Java 放置谓词可通过」——这是对通道②核心主张（§6 推断清单第一条「483 柱今地形已变致系统性 N」）的**反直证**，比原文 §4.1-2 的「观测盲区」论断被正面填补。
- 500,75,-234 柱：两臂脚下地面方块一致（用户受控确认）→ 唯一直证支柱（h19→h13）失去了「与 Vanilla 对齐相关」的解释位。

**CONCERN 1a——「基本出局」措辞过强，建议改为「降 draft 弱化，未排除」**：
- 覆盖面：仅 483、500-234 两根焦点柱 + 脚下层（地面方块）采样。通道②的原始形态是「系统性地形输入差」，两柱脚下一致否证的是其**系统性变体在这两柱的存在**，不否证更弱形态（如非焦点柱的局部差、地表以下/空气列输入差）。
- h 指纹只是树基高度代理（原 §4.1-2 已自认），脚下方块一致 ≠ 全列逐位一致；真正的机制级闭合仍是 §7.2 地形直比（block_probe vs native 列逐位 diff），该条应**保留为降级的确认性廉价复核**（非必须前置，但列入待办可把「无直证」升级为「有反直证」）。
- 样本量：live 侧 483 为 2/2、500-234 为单事件观察，n 极小；降级方向正确，但置信度不应表述为「出局」，建议给「通道② 参与 483 类分歧：draft 弱化，置信 ~0.15-0.25」（从 0.55 降，但不归零——两柱样本 + h 代理指纹两重边界摆在那）。

**CONCERN 1b——新证据本身未落盘**：四张截图与用户受控观察记录目前只存在于对话转述中（.investigations/jungle-l/ 下无对应观察记录文件）。按 core.artifact 契约，结论引用的实机观察 MUST 先落盘（截图归档 + 观察记录：时间/tp 坐标/Targeted 方块/脚下方块/两臂对照），否则本方向性更新的证据链不完整。**建议：更新判定文档前先补观察记录文件**（如 `live-observation-260906-09.md`）。

### 项 2：live Y vs pregen N 互翻归通道①——PASS（带一处表述建议）

逻辑闭合性核查：
- 前提：Rust 地形层同 seed 同 dll 应 run 确定（#67 机制：非确定在特征层执行序）。该前提本轮未被直接重验，但 500-234 两臂脚下一致 + live 与 pregen 同 dll（1.0.26 四查 PASS）对其构成旁证。
- 推理：同执行体（同为 1.0.26 vivo modded）同 seed，live 2/2 Y vs pregen 2/2 N → 翻转只能来自 run 间可变因素 = 特征流执行序（通道①机制）。**成立**。
- 这同时闭合了原 §4.3-4「纯通道①对『为什么恰好换 dll 才开始双缺』无言」的短板：905-13 Y vs 今日 N 的「版本相关翻转」不再需要 dll 差异参与——同 dll 内部 live/pregen 即互翻，版本相关性被稀释为 run 采样波动。

**表述建议**：称「第四组直证」可以，但应附一行条件标注（#66 判据 3 精神）：live 与 pregen 的生成环境并发度不同，互翻样本严格说是「同执行体族、不同生成语境」的 run 对——这不削弱归通道①的结论（并发差异正是通道①机制的输入），但引用时应写明「live vs pregen 跨语境互翻」，避免被未来读者当作同语境 run 对。

### 项 3：500-234 重定性表述——PASS（措辞微调）

- 「dll 版本间漂移（260905-13 旧 dll vs 1.0.26），与 Vanilla 对齐无关」——定性准确，正确地把工程内部回归线索与对齐叙事分离，符合 §9.7 口径纪律。
- 「旧 dll 地面若真低 6 格，今 dll 已与 Java 一致 → 版本间已修复/变更」——推理成立但注意：今 dll 与 Java 一致仅在该柱脚下层受控确认（单柱、单层），措辞建议限定为「**该柱上**今 dll 地面已与 Java 一致」，并保留「旧 dll 地形是否真低 6 格」的推定性质（h 差是树基高代理，树基差 ≠ 地面整列低 6 格——候选还有 surface rule 输出差、树放置 y 计算输入差等，机制未核实，维持 draft 标注）。
