# 260905-13 jungle-l 工作块错误台账（临时排查记录，主会话维护）

## E1: WgDiag 首跑三核验全败（banner=0 / 目标外 24109 行 / 过滤未生效）

- **现象**：job pwsh-1（wgdiag_firstrun.ps1）跑完：[DIAG] banner 0 行；诊断行 24109 行全部无 chunk 过滤；SEEDLOG population 1154 行正常。
- **根因**：`JAVA_TOOL_OPTIONS="-DWG_DIAGCHUNK=29,-16"` 创建的是**名为 `WG_DIAGCHUNK` 的 sysprop**；WgDiag.java:28-29 读的是 sysprop `wg.diagchunk` 或 **env** `WG_DIAGCHUNK`。JAVA_TOOL_OPTIONS 的 -D 不创建环境变量 → TARGET 未设置 → 按「未设目标=旧行为全量」设计走全量，banner（#20 防死参数哨兵）按设计不打。**mixin 代码无罪，是采集脚本通道错。**
- **定位**：三核验失败 → 读 WgDiag.java static 块 + build.gradle 映射表逐行核对。
- **修复**：v2 脚本改 `-Dwg.diagchunk=29,-16`；并按 #8/#19 家族规则补 build.gradle:83 `-Pdiagchunk → -Dwg.diagchunk` 映射行（原本缺失，`-Pdiagchunk` 在首跑中也是死参数）。
- **教训**：sysprop 名与 env 名是**两个命名域**，`-DFOO=1` 只建 sysprop `FOO`；「mixin 读 sysprop 但 -D 名大小写/点号错位」= 死参数第四形态（#8/#19/#20 家族）。

## E2: rcon 拒连（forceload ConnectionRefused ×3）

- **现象**：job pwsh-1 中 `forceload add` 三次拒连。
- **根因**：server 日志 `java.net.BindException: Address already in use: bind` @ RconListener——**rcon 端口 25575 被占**，setupServer 抛异常 → server 在 Done 后即退出。SEEDLOG/DIAG 行来自 spawn 预生成阶段，采集窗口根本没开。
- **定位**：日志尾栈 + `Get-NetTCPConnection -LocalPort 25575`（事后空——瞬时冲突，疑残留 java 进程退出时序）。
- **修复**：v2 脚本启动前 Stop-Process java + 端口占用 WARN 检查。
- **教训**：「Done ( 出现」≠「采集窗口开着」——rcon bind 失败会把 server 变成「活着但马上死」；长跑采集脚本应在 Done 后立即探测 rcon 连通性再 forceload。

## E3: `-p worldgen` 薄壳构建不重建 rlib（#23 家族再证）

- **现象**：J1 修复 + TREESET/CORN 打点后 `cargo build --offline -p worldgen --release` 显示 Finished，但 `libWorldgenRust.rlib` mtime 仍 21:59；单编 exe 字符串哨兵 `TREESET` = False。
- **根因**：`-p worldgen` 只保证薄壳包新，core 包（WorldgenRust）在 cargo 看来 fresh（改动时间戳未被识别——与 #6 mtime 红旗同族）→ rlib 陈旧。
- **修复**：显式 `cargo build --offline -p WorldgenRust --release` 后重单编 exe，哨兵 True；重跑采集 TREESET 15 行正常。
- **教训**：**内容指纹哨兵（exe 内搜新字符串）是判新鲜的唯一可靠手段**，mtime 两面都不可信（#6 保留 mtime / 本例 cargo 未重建）；diagnose 顺序 = 先哨兵后重编。

## E4: fastutil `getObject(int)` 编译错（映射 jar 版本差异）

- **现象**：TreeDecoratorGeneratorMixin 编译「找不到符号 getObject(int)」。
- **修复**：改 `get(int)`。
- **教训**：loom 映射 jar 的 fastutil 版本 API 与上游文档可能有出入，mixin 代码用 List 标准接口方法最稳。

## E5: WgDiag.curAllowed 永假——setPopulationSeed 入参是 chunk 起始 block 坐标（跨探针坐标语义 #17 家族）

- **现象**：v2 采集 banner=1、过滤生效（全量 24109→目标 30 行），但 [THJ]/[TREESET]/[CORN-*] 全零；[CNT]/[SQX] 正常 30 行。
- **根因**：`ChunkRandom.setPopulationSeed` 的 (x,z) 入参 = **chunk 起始 block 坐标**（实测 v2 log: `population ... chunk 464 -256`，即 chunk (29,-16)×16），WgDiag.setCurrent 原样存入 ThreadLocal，curAllowed 直接与 chunk 坐标 (29,-16) 比较永不相等。posAllowed 因自带 `>>4` 侥幸正确。
- **定位**：诊断行构成分解（CNT 有 THJ 无）→ 唯一差异是 curAllowed(posAllowed) → 顺着 ThreadLocal 写入源找到 population 行坐标语义反证。
- **修复**：WgDiag.curAllowed 改 `(a[0]>>4)==TARGET_X && (a[1]>>4)==TARGET_Z`。
- **教训**：①「同一个 chunk」在 MC 里至少有 block/chunk 两套坐标 + 起始/中心两种锚点，ThreadLocal 传递必须钉死语义（#17 跨探针对比坐标钉死律的 mixin 内部版）；②「过滤生效但目标零输出」= 坐标语义错位的标准签名——对照打点（posAllowed 系）有输出而同源打点（curAllowed 系）全零，先查两条门的坐标换算差异。
