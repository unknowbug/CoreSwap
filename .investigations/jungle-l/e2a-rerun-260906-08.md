## 判读（draft）

1. **同 seed 同代码同协议 → 不同 mega 集**在「同执行体、同加载方式」内部成立——run 级非确定性坐实（judge 260906-07 预设判据命中其第二分支：「若同协议两 run 就翻，叙事改为 run 级非确定」）。
2. 与 .b1/R1（执行序依赖）**兼容且相互支持**：pregen 是多线程 worker 调度，每 run 的 chunk FEATURES 完成序本身随机（E0 矩阵已证调度序非空间序）→ 执行序 run 间漂移 → 邻块实况状态 run 间不同 → mega 集 run 间翻转。**「run 级非确定」很可能就是 B1 机制的表现面，而非 B1 降权**（judge 措辞「B1 机制降权」需重新评估：降权的应是对「单一 Java 基线」的执念，不是机制本身）。
3. 对既有结论链的冲击（§15.4 候选清单，待 judge）：
   - 「Java pregen 15 棵基线集」失去唯一性——任何单 run Java 集都只是分布的一个样本；
   - 「pregen vs 实机 2/11 分歧」「pregen vs -Vanilla 单点翻转」的对比基线全部要在 run 间分布语境下重述；
   - E2b（分批 forceload）单 run 判别力下降：与基线差异已不能唯一归因于分批（同协议 run 间就翻）。E2b 需要多 run 采样或改判据。
4. §9.7 口径声明：载体 = 同执行体（gradle runServer vanilla）、同协议、两 run 的 [MJT0] 全序列对比；覆盖面 = chunks 27..31,-18..-14；与 -Vanilla 客户端/实机/Rust 各口径不可比。
