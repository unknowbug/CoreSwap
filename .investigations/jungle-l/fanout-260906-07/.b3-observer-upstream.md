## 1. 子假设陈述 + 机制链条（两子假设分开）

### 1.1 B3 — 实机人工观察误差

**陈述**：260906-05 的 11 点实机真值（用户飞行目测，j5_cross_260906-06.py:3-9）中，2 个分歧点之一或全部是**观察端误差**——漏看已存在的树（假阴性）或把邻位/远处树记错坐标（错位），而非 Java 两侧放置真的不同。

**机制链条**：
1. 用户实机飞行目测 → 人眼/记忆对「这棵 mega 的树干基座坐标」量化精度有限（同表已有 2 个 `NA=近似命中(邻位)` 点：(436,70,-232)、(445,71,-222)，j5_cross_260906-06.py:7——观察精度 ~1-2 格在该数据集内有先例）；
2. 记录时以记忆坐标（可能凭 F3 站位坐标而非树干逐格对齐）回填真值表 → 引入 ±1-2 格/看错棵的翻转可能；
3. 若翻转发生，交叉表把观察误差记成了「实机/pregen 分歧」，污染结论 B 的分歧率。

**边界**：B3 是**观察端**假设，不触碰 Java 生成机制；被 B3 解释掉的分歧点应从「pregen 与实机基线不同集」的证据里剔除。

### 1.2 R2 — 上游流差（chunk 生成入口/缓存/调度层不同）

**陈述**：实机 chunk 的产出可能根本**不是与 pregen 同一次生成流的产物**——实机观察到的 chunk 可能命中「region 文件里历史生成的缓存 chunk」（早前访问时已生成并保存），或经过与 forceload 批量 pregen 不同的入口（玩家移动驱动的逐 chunk ticket 请求、spawn 预生成、已生成 chunk 复用）产出。两股流走的虽是同一 ChunkGenerator（.b1 边界内已核），但**进入 feature 阶段时邻域 chunk 的实况集合不同**，can_replace 读到的邻居状态不同 → mega 落点集合可以不同。

**机制链条**：
1. **入口差**：pregen = forceload 批量请求（本 run 5×5 全序列，j5-baseline-260906-06.md:4）；实机 = 玩家移动逐 chunk spiral 请求 + ticket level 逐块升降。两者决定 feature 阶段执行时刻各 chunk 的**邻域完成度**不同（注意：这本身是 .b1 的执行序命题；R2 独有贡献在 2、3）；
2. **缓存复用**：实机世界是长期世界——目标 25 chunk 若在早前游戏时段已被访问过，本次飞行看到的树是 **region 文件里的存量方块**，与今日 pregen run 的生成流无因果关联。跨 run 非确定性已被基线独立证实（同 seed 不同 run 的 Java 自身 placement 非确定，j5-baseline-260906-06.md:17「E10 方向性结论被强化」）——缓存 chunk 正是「另一个 run 的产物」被复用的载体；
3. **spawn 预生成/已生成复用**：服务器启动 spawn 区预生成、实机端 mod（如 spark/pregen 类）等都会引入第三条上游流；任何一条不同 ⇒ 同 seed 不同结果集，且**双向**散布（实机Y/pregenN 与 实机N/pregenY 同时出现）与「两股独立流各自非确定」的模型天然吻合，无需逐点找机制。

**与 .b1 的分界**：.b1 = 同一次生成流**内部**，feature 阶段跨 chunk 读取的**时序**差异；R2 = 生成流**本身是不是同一次**（入口/缓存/调度）。判别上：若证明实机 chunk 命中缓存（不是本次生成），则 .b1 的时序机制对分歧点不适用（根本没有「本次生成」），R2 直接接管解释。

## 2. 定量论证：2/11 分歧率对 B3 的支持/反对

**模型 A：随机观察翻转**。设用户对每个点位的 Y/N 判断错误率为 ε（独立同分布）。11 点中期望分歧数 = 11ε（pregen 侧视为无误差参照）。观测 2 → ε̂ ≈ 2/11 ≈ **18%/点**。
- 反对方向：18% 的「把一棵 11~30 格高的 mega jungle tree 看没/看有」错误率远超目测大树的常识先例；且错误率若系统性是 ε~18%，9 个一致点里期望仍有 ~1.6 个隐藏翻转，分歧应表现为**高错误率、低信度**的整体噪声，而不是 11 点里 9 点严格命中（位置+高度逐位，j5-baseline-260906-06.md:27）+ 仅 2 点分歧的**尾部稀疏**形态。一致 5 棵严格命中 h 值都对上了（高度靠眼估不会逐位对），说明用户观察在**多数点上达到了格级精度**——18% 均匀翻转率与该精度自相矛盾。
- **双向性的决定性检验**：随机漏看（假阴性）只能产生「实机 N / 真 Y」单向误差；(469,71,-230) 是「实机 **Y** / pregen N」——要求用户**凭空看到一棵不存在的 19 格高树**，或把它与邻位树混淆。查 pregen 15 棵清单（j5_cross_260906-06.py:12-14），距 (469,71,-230) 最近的 pregen 树是 (483,71,-230) h18，**水平距 14 格**；(505,72,-261) 最近的邻位是 (494,72,-233)，距 ~30 格。mega jungle 树冠半径 ~5-7 格，14 格间距不存在「看错棵」混淆可能。**⇒ B3 无法解释 (469,71,-230)，最多解释 (505,72,-261) 一个点（漏看方向允许）**。
- 结论：B3 可解释的分歧上限 = 1/11（漏看 (505)），且需要「30 格高 h30 的树被漏看」这一低先验事件（该树若存在，树冠直径 ~13 格，飞行目测极难漏）。B3 单独作为根因的似然**低**；作为 (505) 点的辅助修正仍值得复验排除。

**对结论 B 的净影响**：若 B3 复验排除 (505) 的漏看 → 分歧率降至 1/11 但**方向变为单向（实机Y/pregenN）**；若 R2 实证缓存复用 → 2/11 全部由「两股独立流」解释，B3 完全退出。两实验正交，可同时执行。

## 3. 判别实验设计

### 3.1 B3 实验：(469,71,-230) 与 (505,72,-261) 截图级复验（给用户的指令）

1. 进入实机世界（与 260906-05 同一存档），`/gamemode spectator`（或 creative + `/tp @s 469 80 -230`），开启 **F3**；
2. 站到坐标 (469,71,-230) 的方块柱上空（F3 XYZ 逐位对齐 469 / -230，Y 取地表上方 8-10 格俯视）：
   - 截图 1：俯视（对准树干基座 2×2 丛林木位置）；
   - 截图 2：地面平视树干全景（能数清主干高度）；
   - 记录：树干基座最小角坐标（x,z 各是哪格）、主干顶 y；
3. 同法复验 (505,72,-261)（tp 505 80 -261）：**若该点实机确实有树** → (505) 是 260906-05 记录错误（B3 部分成立）；**确认无树** → B3 对该点也排除；
4. 在 (469,71,-230) 半径 16 格内环飞一圈确认没有第二棵 mega（排除「看错棵」残余可能，对照 §2 的 14 格间距论证）；
5. 把两张截图 + F3 坐标发回，主会话与 pregen MJT0 集/rust ca_min=on 清单（rust 侧预言该点 Y h=19，j5_cross_260906-06.py:16）三方对拍。

**判据**：(469) 有树坐实（预期概率高，因 rust ca_min=on 独立预言同点 Y）→ B3 排除、分歧真实；(505) 复验翻转 → B3 部分成立，分歧表修正。

### 3.2 R2 实验：判别实机 chunk 是否命中 pregen 缓存 / 是否同一生成流

**实验 R2-a（region 文件考古，离线，首选）**：
1. 复制实机存档 `world/region/r.<rx>.<rz>.mca`（覆盖 chunk (29,-16) 即 region r.0.-2；含 (505,72,-261) 的 chunk (31,-17) 在 r.0.-2）到临时区；
2. 用 NBT 解析（Amulet 或 python nbt 脚本，落 .tmp/jungle-l-260906/）读取两 chunk 的方块段，导出 mega jungle trunk（jungle_log，axis=y，连柱 ≥11 格）清单；
3. **判据**：实机 region 中 (469,71,-230) 有/无 jungle 主干 + (505,72,-261) 有/无——直接给出「存档真值」，绕开一切目测误差。若存档真值 = 实机目测 → 观察端干净，分歧真实存在；若存档 ≠ 目测 → B3 实证。
4. 附加字段：chunk 的 `InhabitedTime` 与 `LastUpdate` tag——若目标 chunk InhabitedTime > 0 且非本次会话生成，即为**缓存复用实证**（该 chunk 是历史 run 产物，R2 机制 2 成立）。

**实验 R2-b（SEEDLOG 实机重访，在线）**：
1. 实机端挂同款 SEEDLOG 探针 jar（gradle runClient 或装探针 mod）；
2. **先删除/远离目标 25 chunk 再重访**（保证触发重新生成而非加载缓存），观察客户端/服务端日志：
   - 出现 `[SEEDLOG] population ... chunk 464 -256`（等目标 chunk 行）→ chunk 正在**重新生成**（未命中缓存）；
   - 全程无 population 行但树可见 → 看到的是**缓存 chunk**（R2 缓存复用实证）；
3. 若触发重生成：grep 本次日志 `[MJTD] p=(469` / `[MJTG] p=(505`，直接读实机生成流里这两点的落地门判定（pregen 侧：(469) 零 MJTD/MJTG 命中、(505) 有 31 处命中且成功——judge 260906-07 勘误后口径，见 §0）。实机 MJTG 在 (469) ok=true 而 pregen 无此行 → 「同 generator 不同流不同结果」从推断升级为**双端日志直证**；
4. 比对两次日志的 `[SEEDLOG] population <pop> chunk <x> <z>` 种子值：同 chunk 两流 pop 值不同 ⇒ 上游流分叉的最直接数据层证据（§9.4 意义上的 trace 级新证据）。

**实验 R2-c（对照，低成本）**：服务器 pregen run 之前先检查 `run/world/region` 是否已有目标 region 文件——若 pregen run 当时也是复用了存量 region，「pregen 基线」本身就不是纯新流（基线口径污染，需删 world 重跑，符合 seed 三查纪律：删 `run\world` 强制重生成）。

## 4. 解释力与替代解释

| 现象 | B3 | R2 | .b1（执行序） | .b2（环境差） |
|---|---|---|---|---|
| (469) 实机Y/pregenN | ✗（需幻觉 19 格高树，§2） | ✓（两股独立流，各自非确定） | ✓（邻 chunk 读取实况差） | ✓ |
| (505) 实机N/pregenY | ✓ 可解释（漏看，低先验） | ✓ | ✓ | ✓ |
| 9 点严格一致 | 中性（要求观察精度高） | **张力**：若两流完全独立，9/11 一致是巧合性偏高，需「流分叉影响面小（仅边缘 chunk 受邻域完成度影响）」辅助假设 | ✓（多数 chunk 邻域完成度等价） | ✓ |
| 双向分歧形态 | ✗（单向） | ✓ 天然吻合 | ✓ | ✓ |

- **R2 的最大张力**：若实机 chunk 全是历史缓存、与 pregen 流完全独立，为何 11 点里 9 点逐位一致？最经济的消解：mega 放置对上游流的敏感面**窄**——只有邻域完成度恰在临界态的 chunk（目标 chunk (29,-16) 与 (31,-17) 一带）受影响，9 个稳定点两流等价。该消解本身可由 R2-a 的 InhabitedTime 分布检验（受影响 chunk 是否恰为最近生成/最久未访问的边缘 chunk）。
- **替代解释（未排除清单）**：.b2 环境差（Fabric/Connector 侧 worldgen patch）仍可产生同形态双向分歧，R2 所有实验不能区分「缓存流差」与「mod 注入差」——需 .b2 的环境清单判别；.b1 执行序对「重访触发重新生成」场景（R2-b 路径）仍竞争有效。
