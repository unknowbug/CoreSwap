### D27. 攒批摊销假设证伪：摊销封顶 ~13%，解释器式 kernel 单点求值成本 ~0.22ms/pt 主导，现引擎形态下 GPU 无解（260908-01，candidate）

### 现象
- Phase 1（GPU 管线接入课题，260907-10 用户拍板启动）摊销曲线实测（seed=-8248318472910187742，corner 768 点/chunk，gpu_ffi_fill 同步 fill 含 readback，严格串行，RTX 4060 Laptop，7 轮中位数）：
  | n（点） | chunks | median | per-pt | per-chunk(768pt 折算) |
  |---|---|---|---|---|
  | 6144 | 8 | 1593.5ms | 0.2594ms | 199.2ms |
  | 49152 | 64 | 11959.5ms | 0.2433ms | 186.9ms |
  | 196608 | 256 | 43464.1ms | 0.2211ms | 169.8ms |
- 关键形态：**边际成本平坦**——批次从 8 chunks 扩到 256 chunks（32 倍），per-pt 仅 0.259→0.221ms（摊薄封顶 ~13%）；独立复跑 256 chunks per-pt 0.2197（偏差 <1%），与 260903-16 旧读数 0.233 结构一致。GPU 169.8ms/chunk vs Rust CPU 8 线程 ~4.5ms = **慢 ~38×**；vs 单线程 27.69ms = 慢 ~6×。channels 路线更差（345-361ms/chunk @n=1，D25 家族方向）。

### 根因
- **「dispatch/readback 固定成本可被攒批摊销」的瓶颈假设被边际平坦证伪**：n=768 时固定成本已基本摊没，扩批的边际收益趋零（~13% 封顶）——dispatch/readback 不是主项。
- 带宽也排除：n=196608 上传 6.8GB / 43.5s ≈ **0.16GB/s ≪ PCIe ~16GB/s**——split 上传远未饱和（角点形态 26.6MB/chunk，非 D24 逐块形态 3.4GB/chunk 的带宽死局）。**对 D24 是形态限定而非推翻**（§15.4 无冲突）：D24 结论「带宽死局」只在逐 block 形态成立，角点批量形态瓶颈更上游。
- 残余 ~0.22ms/pt 归属**解释器式 kernel 的单点求值成本**（judge 条件 4 措辞收窄：微观成分——纯算术吞吐 vs 解释器分派/sync/workgroup/f64 残留——本轮数据未分解，不过度声明机制归因；但无论哪个成分主导，攒批均救不了）。与 D26「每点慢是结构性成本、非单点优化可解」互为印证。
- 门槛核算（judge 条件 1，两口径二分，禁止混用）：摊销口径（<1ms/chunk 总预算含计算）需 per-pt <1.3μs = 当前 **~170×**；重议门槛原义（摊销 <1ms **且** 计算不劣于 CPU 4.5ms/chunk）计算侧需 <5.86μs/pt = 当前 **~38×**。两口径定性一致：均远超「接入现有引擎」范畴，达门槛等价 C2ME 式专用 kernel 重设计（每 DF 类型专项化 + 网格预填充原生实现）——**新立项级**，现引擎形态下无解。

### 定位
- n-scan 探针（`.tmp/gpu_n_scan.exe`，bin-diag/gpu_n_scan.rs，rustc 单编 rlib 96a33b09；exe LastWriteTime 2026-09-07 23:21:16 与测量时段自洽）：4 档 n（768/6144/49152/196608）× 7 轮取中位数 → 边际差分暴露「摊销封顶」形态（0.2534/0.2410/0.2137 ms/pt 递减趋缓）。
- 前置健康验证：gpu_ffi.dll fresh 重出（sha 14096A5A...B9D53，build.ps1 -Ffi）+ 三件套复验全绿（corner 96.08%/9.18e-6 探针口径；channels 逐通道 major=0 跨 3 域）——排除「陈旧产物假阴性」（#29 家族教训前置应用）。
- 复现性验证：独立两轮 256 chunks（0.2211/0.2197，<1% 偏差）+ 历史 260903-16 读数 0.233 结构一致（§9.7 三要素：载体/覆盖面/可比性齐备）。复跑全程原始输出落盘 `cmd-output/gpu-n-scan-fresh-rerun.log`（judge 条件 2）。
- judge 审查（review-gpu-phase1-amortization-260907-11.md，PASS-with-conditions，5 条件已应用）：算术复核全对 + 两口径二分修正 + 微归因措辞收窄 + 原始输出落盘 + .artifacts 登记。

### 修复
- **非代码 bug，是方案级负面结论**（D24/D25/D27 家族负面结论第三例）：「接入现有 GPU 引擎」路线无解，负面结论落盘，维持搁置建议（回 CPU 主线，8 线程 ~7× Java 已在盘）。
- 若未来突破，唯一路径 = C2ME 式专用 kernel 重设计（每 DF 类型专项化 + 网格预填充原生实现，~38× 起步门槛）——新立项级，须另走 Phase 0，不在「接入」范畴。
- 三选一待用户拍板（verdict-260908-01）：① 负面结论落盘维持搁置；② 新立项专用 kernel 重设计；③ 目标重定义（GPU 只服务特定子管线/离线预生成场景）。

### 教训
1. **「dispatch/readback 摊销」类瓶颈假设必须用摊销曲线实测检验，先于任何架构投入**——本项目两次 GPU 立项（260903 逐块、260907 攒批）分别死于带宽死局与摊销不可达，两次的瓶颈假设（喂数据太慢 / 固定成本没摊掉）都被实测第一轮数据直接证伪。判据：**扩批 32 倍而 per-pt 只降 13% = 摊销假设死**，一轮 n-scan 即可判，成本远低于任何 kernel 优化。
2. **CPU 基线越快，GPU 回本门槛越高（38× 外推）**——重议门槛原义「计算不劣于 CPU」的分母是 Rust CPU 8 线程 4.5ms/chunk；CPU 侧每优化一次（本例单线程 27.69→8 线程 4.5），GPU 侧门槛同步抬高。GPU 立项核算必须用**当前** CPU 基线，历史门槛数字（按更慢 CPU 算的）不可直接续推。
3. **带宽结论不可跨采样形态互迁（D24 形态限定）**——「split 上传带宽死局」（D24，逐块 3.4GB/chunk）与「上传 0.16GB/s 远未饱和」（D27，角点 26.6MB/chunk）同引擎同 shader 同数据结构，仅采样密度不同即结论反转。任何「带宽是/不是瓶颈」结论 MUST 附采样形态声明（每点数据量 × 点数）。
4. **门槛核算多口径必须二分声明**——170×（总预算口径）与 38×（门槛原义口径）差 4.5 倍，混用会高估/低估可达性；judge 条件 1 修正的正是这个口径混用。定量门槛结论 MUST 每个数字绑口径。
5. 微观归因（kernel 内部哪个成分主导）未分解不妨碍方案级决策——「无论哪个成分主导，攒批都救不了」的决策鲁棒性比归因完整性优先；但表述要收窄到数据能支撑的层级（「单点求值成本」而非「计算吞吐上限」）。

**速查表补充行**（追加到速查表末尾，D26 行之后）：
| 攒批摊销不可达（D27） | **dispatch/readback 固定成本不是主项**——扩批 32×（8→256 chunks）per-pt 仅 0.259→0.221ms（封顶 ~13%），残余 ~0.22ms/pt = 解释器式 kernel 单点求值成本（微成分未分解）；带宽 0.16GB/s ≪ PCIe（角点形态，对 D24 逐块带宽死局为形态限定非推翻）。GPU vs CPU 8 线程慢 ~38×（门槛原义）/ ~170×（总预算口径，两口径二分）→ 现引擎形态下无解，达门槛 = C2ME 式专用 kernel 重设计（新立项级）。**摊销曲线实测先于架构投入；GPU 门槛随 CPU 基线优化同步抬高；带宽结论须附采样形态声明** |

### GPU 光照不立项简记（260908-01，candidate）

**结论：光照子系统不做 GPU 接入立项。三条组合理由：**

1. **装光影（Iris/Oculus）用户：瓶颈在客户端渲染 GPU，光照计算收益不体现在 FPS**——光照引擎自身优化对这类用户无 FPS 感知。⚠️ 来源声明：用户口头回忆「当时评估过光影接管」（260908-01 现场回忆），**台账查无记录**，按用户现场回忆记录；精确化为「光照计算本身不被光影接管，只是优化收益不体现在 FPS」（光影占用的是渲染 GPU，worldgen 光照是 CPU 侧计算，两者不竞争同一资源，但用户感知的帧率瓶颈在渲染侧）。**非光照侧直接探针实测，属口头回忆级证据。**
2. **不装光影用户：光照计算 GPU 亲和性差**——光照传播 = BFS 不规则迭代（数据依赖驱动的波前，负载不可静态均分）+ 数据量小（~百 KB/chunk 量级），dispatch/readback 固定成本相对计算量占比极高，攒批摊销空间与 D27 同款受限。
3. **Phase 1 实测外推**：D27 证明本项目 CPU 光照/worldgen 内核已足够快（GPU 侧需 ~38×-170× 才回本），光照内核同属「CPU 已快、GPU 门槛极高」形态。**外推级证据（非光照侧直接探针实测）**，但方向与 ①② 一致。

旁证（弱，未核实）：C2ME 的 GPU 路线只做 noise/density，未做光照——与「光照 GPU 亲和性差」的判断方向一致，仅作旁证，未独立查证。

**诚实声明**：三条理由中 ①为用户口头回忆（台账无记录）③为 D27 外推，均非光照侧直接探针/基准实测；若未来要正式立项/否决光照 GPU 化，应先做一次光照内核 CPU 基准 + GPU 亲和性微测钉住主导成本（D26/D27 教训：先 benchmark 再立项）。
