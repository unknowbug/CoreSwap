### §15.4 取代记录：发现 #101 部分证伪——「单读 51ns 近下限」系摊销值非独立单价（260909-06）

- **supersedes**：发现 #101（残差归因「读量放大 vs 单读贵」判别式，260909-04）之判据第 ① 步「总成本 ÷ 读数 ≈ 单读价（51ns = 近下限 → 单读不贵）」；**superseded-by**：本条（260909-06 探针轮）。
- **推翻理由（一行）**：51ns 实为「残差 ÷ 读数」的**摊销推算值**（含 miss 重生成成本摊入 + mutex lock/hash/Arc 同步结构成本），不是独立实测的单读原语价——把它当「近下限」引用即循环论证（残差里混着 miss 重生成，除回读数又得出「单读便宜」）。
- **修正后事实**：memo-review-260909-05 Step 2 判定 1——98% 点级重复读每次都重付 mutex+hash+Arc 同步结构成本，「消每读同步开销」与「读量语义固有」是两层，#101 混层。
- **判据（取代 #101 判据①）**：**摊销单价（总成本÷读数）不得当独立实测单价引用，更不得用它证明「单价低」**——若读数本身被同一残差源放大（如 miss 重生成摊入），商值与「原语下限」的比较无效；独立单价须单独微测（#21 形态：复刻调用形态）或声明摊销口径。
- **范围声明**：#101 判据②（读数跨臂比值 114× 定放大）与③（per-feature 归因同构）未被推翻，继续有效；仅①的单价解释被取代。
- **来源定位**：`.investigations/camin-perf/memo-review-260909-05.md` §Step 2 + `probe-260909-06.md`（#101 正文位于本文件 #101 条，原文不改）。

## 草稿 3：新发现候选（追加到 workflow-patterns.md 末尾 = #102/#103/#104；build-tooling.md 末尾 = #45）

### 发现 #102（最高价值）: 缓存 clear-all 惩罚的落点核对——「谁写谁读」之外必须加核「clear 波及面」，features 侧快照与容量是互补杠杆非二选一（260909-06）

- **时间/置信度/module**：260909-06（实际 2026-09-09 21:51 起）；candidate（CAP 256/2048/65536 三轮配对交错 + B3a 快照 on/off 双臂 hash 逐位不变 + 交错 ×3 实证；待复用再升）；workflow-patterns / 性能归因（缓存接线域）。
- **来源定位**：`.investigations/camin-perf/probe-260909-06.md`；载体 = bin-diag camin_bench（WG_CA_CAP 臂 + B3a 3×3 Rc 快照）。
- **观察**：features 侧 per-read 同步消除（B3a 快照：快照命中零锁零 hash）只消 per-read 同步成本（~2%），**不消 clear-all 惩罚**——clear-all 惩罚打在**主管线缓存优先读路径**（#100 的 fill_chunk_blocks 缓存命中读被 clear 波及，命中失效→地形重算），两臂数据实锤：B3a@256 vs B3a@2048 交错 ×3 仍差 ~11%（171.5/169.2/174.0 vs 152.9/153.2/154.0）。容量杠杆（CAP 2048 等效无 clear-all）与快照杠杆（per-read 去同步）各治一路，互补。
- **证据**：CAP 256→2048 稳定 ~10% 增益（三轮交错方向一致）；2048≈65536（更大无增益）；B3a 单独仅 ~2%（三轮全赢但小）；恒等式自检 cap256−cap2048=3.5s ≈ 34 interior miss 差 × 112ms fill 单价。
- **判据（MUST）**：缓存类优化立项/验收 MUST 核对三面：**谁写（回填）+ 谁读（命中路径）+ clear/失效波及面（失效打在哪条读路径上）**——只治命中侧同步或只治写侧，clear 波及的另一条读路径照旧付费。#100「两侧接线」判据的第三面延伸。
- **家族索引**：#100（谁写谁读，本条加第三面）、#101（被取代后其②③残效）、#47（行为不变 hash 门）。

### 发现 #103: 新 binary 单跑 wall 对比历史数据会被机器噪声带 ±10% 污染——新旧二进制同批配对交错是唯一有效 A/B 口径（260909-06）

### 发现 #104: region 尾缘语义成本在小 region bench 中占比虚高——邻 chunk 语义类残差 MUST 报告 region 规模敏感性（260909-06）

- **时间/置信度/module**：260909-06；candidate（16×16 vs 32×32 规模扫描各一组，单 region 口径）；workflow-patterns / 验证可比性（§9.7 覆盖面具体化）。
- **来源定位**：`.investigations/camin-perf/probe-260909-06.md`（残差分解 (b) + 32×32 摊薄验证节）。
- **观察**：ca_min on 的尾缘邻 chunk 重生成属语义固有（region 边界外邻列在 off 臂永不生成），16×16 时 39-41 次 edge miss × 112ms ≈ 17.6ms/chunk，占残差大头（残差 ~30ms，26%）；32×32 摊薄后残差降至 15.2ms/chunk（9.3%）——同一机制，region 边长翻倍占比近半。
- **证据**：16×16 残差 ~30ms/chunk vs 32×32 15.2ms/chunk（B3a@2048 on 178.5 vs off 163.3）；edge miss 只出现在 cx=15/cz=15 行列。
- **判据（MUST）**：凡残差归因含「邻 chunk 语义」（ca_min 类跨 chunk 读、边界修复、邻居依赖），bench 结论 MUST 附 **region 规模敏感性**（至少两个边长）或声明「小 region 口径下该项占比虚高，连续生成场景按边际摊薄」；否则优化门槛核算（#83 场景分母）建立在虚高分母上。
- **家族索引**：#83（性能分母分场景——本条为 region 规模维）、#72（口径疑点先看不自洽——尾缘占比随规模跳变即此类签名）。

### 发现 #45（build-tooling）: PowerShell `-like '*[CA-NT]*'` 通配符字符类坑——`[...]` 是字符集不是字面量，日志过滤混行污染求和（260909-06）

- **时间/置信度/module**：260909-06；确定（首求和作废重算实测）；build-tooling / PowerShell 坑。
- **来源定位**：`.investigations/camin-perf/probe-260909-06.md` 恒等式自检节末；载体 = 诊断日志求和脚本（.tmp）。
- **现象**：用 `Select-String -Pattern '*[CA-NT]*'` 风格（-like `'*[CA-NT]*'`）过滤含 `[CA-NT]` 标签的诊断日志行，结果混入了 `[CA-MEMO-TOP]` 等其他标签行，计数求和虚高，首版汇总作废。
- **根因（机制）**：PowerShell 通配符语法里 `[...]` 是**字符类**（匹配括内任一字符），`*[CA-NT]*` = 「含 C 或 A 或 - 或 N 或 T 的任意行」——不是字面子串 `[CA-NT]`。诊断日志标签恰好全用大写字母，过滤器退化为「几乎匹配所有行」。
- **定位**：求和与手数行数不符 → 打印被选中行样本发现 MEMO-TOP 行混入 → 逐字符核对通配符语义。
- **修复**：字面过滤改 `.Contains('[CA-NT]')`（或 `-like '*\[*CA-NT*\]*'` 转义，或改用 `-SimpleMatch`）。
- **教训/判据**：PowerShell 通配符里出现 `[` 一律先想字符类；对**含方括号标签的日志**做计数/求和类汇总，过滤后必须打印样本行核纯度（混行即作废，与 #13 sanity 家族同型）。
- **家族索引**：#41（PowerShell 管道/通配符语义坑家族）、#13（过滤/证据先 sanity）。
