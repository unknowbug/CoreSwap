### 4.1 本块新定位：计数载体缺陷是 **1.20.1 独有**（修正 260912-02 的隐含范围）

`gradle --dry-run` 任务图直证（两版对照）：

| 项目 | 任务图 | 结论 |
|---|---|---|
| 1.20.1 裸 `runServer` | `:runServer` **+** `:content-test:runServer` | ⚠️ **双命中** ⇒ 两次 JVM 一次日志（**260912-02 C-17 的真实机制**） |
| 1.20.1 `:runServer` | 仅 `:runServer` | ✅ 单 run |

| 1.21.6 `:runServer` | 仅 `:runServer` | ✅ 单 run |

**机制（本块新定位）**：**判别此类问题不能看目录，必须看任务图**——`versions\1.21.6\java\settings.gradle:13` 的 `include 'content-test'` 会让 Gradle **自动创建一个空子工程**（`gradle :content-test:tasks` → `BUILD SUCCESSFUL`，可列出 help 任务），但该子工程**没有 loom 插件**（`versions\1.21.6\java\content-test\` **目录根本不存在**，`Test-Path` = False；`git ls-files` = 0 条）⇒ **`runServer` 任务不存在** ⇒ 裸 `runServer` 只命中根工程一个任务。
**结论（无双命中）仍正确**，且由**任务图双向直证**（不依赖目录存在性这一层）：1.21.6 `--dry-run runServer` = 仅 `:runServer`；1.20.1 = `:runServer` + `:content-test:runServer`。
**处置**：本块运行台仍显式用 `:runServer`（防御性）；**登记该不对称性**，防下游把 1.20.1 的载体缺陷再误记到 1.21.6（260912-02 W7 家族）。
> ⚠️ **判错经验（judge MUST-1 更正，2026-09-13）**：本记录初版曾称「1.21.6 的 `content-test` 目录**为空**」——**错**，真实是**目录不存在**。**结论对而解释错**：靠任务图得出了正确结论，却事后用「目录为空」这一未经核实的措辞去解释。**判据 = `include` 与目录存在性解耦**（Gradle 自动建空子工程）⇒ 此类问题 MUST 以**任务图**为判别依据，**不得以目录存在性/内容推断**（#112 预登记读法纪律 + 本块 W3 自身教训的双重复发）。

## 5. 指纹取点（#115/#130 判据：取点层 MUST 写进结论）

| 层 | 日志标签 | 取点位置 | 语义 |
|---|---|---|---|
| Rust buf 层 | `[WG-CONTENT]` | `writeChunk` 之前（对 Rust 侧 `buf` 只读计算） | 引擎**原生输出** |
| Java 写回读回层 | `[WG-CONTENT-WB]` | Java 写回**之后**读回 | **写回结果**（能捕获写帧错误） |

- **两层 hash 域不同，禁止跨层比对**（本块严格同层比较）。
- **边界（诚实声明）**：两层指纹**对写回内容面敏感，但观察面有限** —— 不可单独支撑「无回归」，故本块与「异常面同档（`nonWmi=0`）+ 执行体三元组 + 构建绿」并列陈述（承 260912-02 §F29）。
- 注（§4 ④）：本块「三臂 sha 同一」是**文件级**证据（`Get-FileHash` 对已排序文件），故**蕴含**多重集相等；260912-02 的「序列永不相同」是**跨 run 异步流水线顺序**现象，与本块三臂（同参数族、逐臂删 world 同起点）不构成矛盾——本块不主张「顺序确定性」，只主张**内容同一**，判据形式为 multiset + sha。
