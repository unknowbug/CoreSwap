## 2. 豁免子句逐条检验（§3.4，#171 合读）

### 2.1 `coreswap.bulkwb`

- **①探针专用路径**：**不成立**。这不是探针输出导向参数，是**生产行为主开关**（260913-01 用户裁决翻转 `BULKWB_ON` 的 judge 前置就是「回退开关在位」）。260918-04 自身也承认「非纯探针」。
- **②缺省值即权威**：**不成立**。缺省（`true`）下开关的**设计内用法 = 传非缺省值 `0` 做即时回退/A/B**（07:206/1240/1345、10-timewise 3143、WgCompat.java:10 javadoc）。「不传 = 传默认」只覆盖缺省方向；**回退方向（`bulkwb=0`）的覆盖无缺省可替代**——回退语义的存在本身就是「缺省非权威」的直接证据。
- 结论：①②均不成立（无论读作 AND——任务书/#171「两条合读」——还是 t4 §3.4 原文「任一」，双重不满足）⇒ **DEFECT-MISSING-MAPPING**。

### 2.2 `coreswap.skipair`

- **①探针专用路径**：**不成立**。同样是生产写回路径开关（A1a 跳空气优化），非探针。
- **②缺省值即权威**：**不成立，且双版各有非缺省用法**。1.21.6 缺省 `false`，javadoc（1.21.6 WgCompat.java:13-14）明写 `-Dcoreswap.skipair=1` **强制开启做自身 A/B**——非缺省方向是登记在案的用法；1.20.1 缺省 `true`，非缺省方向 = `-Dcoreswap.skipair=0` 回退（07:1345）。两版都存在缺省不可替代的显式覆盖用法。
- 结论：①②均不成立 ⇒ **DEFECT-MISSING-MAPPING**。

### 2.3 对既有 SCOPED 判定（260918-04 :24）的回应

其理由两点：a)「无 `-P` 映射先例 + 缺省权威」；b)「javadoc 未宣传 `-P`」的族内分界（:25）。回应：

- b) 的分界把「文档是否宣传过」当判据——这正是 T4 已否决的 b1 原判据（#171：javadoc 措辞是意图表达，**结构性事实优先**）。同族 4 项映射在位、本体缺失，不对称是可 grep 的结构事实，不因 javadoc 措辞消失。

## 3. 严重度论据：回退开关的 MUST 级仪器不可达

- **260913-01 BULKWB_ON 翻转的 judge 条件 = 「回退开关 `-Dcoreswap.bulkwb=0` 保留即时回退」在位**（1.21.6 10-timewise:112、07:1444/1468）。该回退开关是这条 confirmed 结论的**安全前提仪器**。
- 但「在位」目前只在**源码语义层**成立：两版 build.gradle 均无 `-P` 映射，而 gradle CLI 的裸 `-D` **不会自动进入 fork 的 runServer JVM**（进 JVM 的通道 = `run.vmArg` 行，即只有 -P 映射行注入；这是 B6-1 全部门禁设计的前提口径）。同族诊断开关全部可 `-P` 启用、唯独回退主开关不可 = **回退通道在 gradle 单命令口径下不可达**——与 bulkwblog 当年判 DEFECT 的理由**同构**（「MUST 级判据的唯一仪器，生产写回链上不可达」→ t4-adjudication-1216 §2.1 #8）。
- 1.20.1 是出货线：生产现场若 bulk 路径出问题，操作者的自然动作是 `gradle runServer -P<something>=...` 一键回退；实际只能改脚本/运行配置。回退开关的**可达性缺口 = 严重度最高的缺失**（回退开关的意义就在紧急时刻的低摩擦可达）。
- skipair 在 1.21.6 的非缺省用法（`=1` 做 A/B）同理：该版 SKIPAIR_ON=false 待验证翻转，翻转前置 A/B 臂需要此开关可经 -P 注入——现在不可，翻转前置仪器缺口。
