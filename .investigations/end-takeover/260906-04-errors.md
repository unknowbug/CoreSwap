# end 接管开发块错误台账（260906-04，五段式）

> 课题：G1-G4 开发；标签 260906-04（Get-Date 锚定 2026-09-06 15:43）。

## E1 — density_builder 新分支放在 catch-all 之后（永不命中）

- **现象**：`create_for_dim("end")` panic `resolve minecraft:end/sloped_cheese failed: unsupported density type 'minecraft:end_islands'`——分支明明已写。
- **根因**：新 match arm 插在 `_ => return Err(...)` 之后。Rust match 按序匹配，catch-all 先命中（与 Java switch-case 同类陷阱；Rust 编译器对 unreachable pattern 只告警不报错，而 `_ =>` 在前时新 arm 不算 unreachable，静默吞掉）。
- **定位**：read density_builder.rs L385-395 直接目视确认顺序。
- **修复**：end_islands arm 移到 `_ =>` 之前。
- **教训**：给大 match 加分支时禁止落在 catch-all 之后；「编译过 + 告警不新增」不等于「命中」，新增分支必须有运行时命中证据。

## E2 — ChunkRandom 种子派生乘法 debug 溢出 panic

- **现象**：fill 大坐标 chunk（100,100）panic `attempt to multiply with overflow` @ chunkrandom.rs set_population_seed/set_carver_seed。
- **根因**：Java long 乘法天然回绕，Rust debug profile 算术溢出 panic；`next_long()` 可取满 i64 域，`chunk_x * l` 超域必然。release 静默回绕（语义碰巧正确），debug 才暴露——此前 overworld/nether 未炸只因测试 chunk 坐标小。
- **定位**：panic 行号直指；读源确认三处 `*`/`+`。
- **修复**：`set_population_seed`/`set_carver_seed` 改 `wrapping_mul`/`wrapping_add`（位模式与 Java 完全一致，非行为变更）。
- **教训**：复刻 Java long 算术一律 wrapping_*（ debug/release 同语义）；新维度大坐标/新 seed 首跑必须 debug profile 过一遍（debug 溢出断言是免费的 Java 回绕审计器）。

## E3 — 空列 heightmap 哨兵 i32::MIN 直入 build_surface（end 特有）

- **现象**：benchseed fill 外围 chunk panic `attempt to subtract with overflow` @ biome.rs:349（`block_y - 2`，block_y=i32::MIN）。
- **根因**：`ChunkDensity.surface_height` 空列哨兵 = i32::MIN（terrain.rs:241「无 solid」）；end 外岛空域大量全空气列，`o = heightmap+1` 把 MIN 喂进 biome 采样链。overworld 列必有基岩永不触发——维度特有路径缺陷。Java 语义：WORLD_SURFACE_WG 空列 get = bottom-1。
- **定位**：RUST_BACKTRACE=1（closure 链 build_surface closure$1 → biomeCellKey closure）；再 grep surface_height 定义见哨兵注释。
- **修复**：fill_terrain_column 消费点统一映射 `MIN → min_y - 1`（Java Heightmap 空列语义；消费点映射使 features/placement 等其他消费者同样受益）。
- **教训**：哨兵值跨模块传递前必须在边界声明/变换语义；「新维度新地形形态（全空气列）」是哨兵路径的天然压力测试——新维度首跑应覆盖空列 chunk。

## E5 — end 维度 chunk 形状误判 0/128（维度高度 ≠ 噪声高度）

- **现象**：生产环境 forceload end 后无 `[Mixin] populateNoise(end)`，只有一次性放行日志 `release to vanilla: settings=minecraft:end shape=0/256`。
- **根因**：首版 mixin 用 `bottomY==0 && height==128` 判 end 形状（照抄 noise_settings/end.json 的 noise.height=128）——但 chunk.getHeight() 返回**维度类型**高度，the_end 维度 = 256（与 nether 同形！）。end 与 nether 形状不可区分，settings id 是唯一判别（BUG-002 修复的同构延续）。
- **定位**：放行日志的 shape=0/256 直接给出实侧形状；对照 mixin 条件即见差。
- **修复**：end 判定改为 `bottomY==0 && height==256 && endActive && settings==minecraft:end`（形状变量改名 zeroShape 表达「与 nether 同形」事实）；fillChunkEnd 仍写 128 高度（8 sections，上半 vanilla 空 = 正确）。
- **教训**：`noise.height` ≠ 维度 `height`——形状判定只能用维度类型实测值，且维度间形状可能碰撞；新维度接入首查「与既有维度形状是否同形」（同形 → 只认 settings id）。

## 附：比对方法假阴性（非代码错）

- 多 seed 对拍第一轮全 FAIL：Java `%.17g` vs Rust `{:.17e}` 格式不同，Compare-Object 字符串比对假阴性（数值实际全等）。判据：跨语言数值对拍必须数值化比较（解析 double 后比），或两侧统一格式化函数。
