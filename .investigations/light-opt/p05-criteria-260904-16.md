## 1. 事实层（两臂勘探交叉结论，全部 draft 静态级）

- 光照 100% 在 vanilla 手里（Java 侧 grep light 零命中；C++ 无实现；生产主线 = Rust WorldgenRust）。
- 1.20.1 传播 = 双 FIFO 两阶段（decrease→increase），**非优先队列**；调度 = ThreadedLevelLightEngine 专用 "light" 邮箱线程，LIGHT 是唯一异步专用线程 status（range=1）。
- 接管缝两处：① ChunkStatus.LIGHT 任务层 ② ThreadedLevelLightEngine API 面（initializeLight/lightChunk/propagateLightSources）。
- 存储 = DataLayer 2048B nibble（y<<8|z<<4|x）+ 均质惰性；下游 = 生怪/方块 tick/渲染/advancement（寻路不读，静态 grep draft）。
- 缺口：wg_* C ABI 单 chunk 进出、无邻 chunk 读通道；接口三处（api.rs/jni_bridge.rs/CppWorldgen.java）需同步扩展。

## 2. 接管点决策（D1，推荐 B）

- **方案 A**：ChunkStatus.LIGHT 任务 HEAD-cancel 整体替换——控制面最大，但要自己重建 chunk 完成协议/LightingProvider 状态一致性（风险高）。
- **方案 B（推荐）**：保留 ThreadedLevelLightEngine 调度外壳与 CompletableFuture 协议，只把引擎内核（lightChunk 全量计算 + initializeLight 初始化）替换为 Rust 调用——vanilla 状态机/读档 isLightOn 语义/发包粒度全保留，风险面最小；有损发生在「内核算法」层，与「允许有损」定位一致。
- Rust 调用协议：传入目标 chunk + 邻 chunk（3×3，LIGHT range=1 语义）的 opacity 提取数组，返回双通道 nibble 数组（block/sky）——扩展 wg_* ABI（缺口 ② 闭环于此）。

## 4. 性能判据（基线方案）

- Java 基线：WorldGenBench（-PbenchProbe），**≥256 chunks 大样本 + 充分预热 + 排除冷启动 chunk + 取中位数**（端到端铁律）；bench 串行（发现 #28）；跑前删 run\world（发现 #19）；seed 三查全套。
- 口径声明（§9.7 三要素同行写）：载体 = 存档生成 e2e；覆盖面 = 单 seed N 区域；与历史 worldgen 课题数字**不可比**（不同阶段），仅本课题内部 A/B 可比。
- 目标（D3 待拍板，建议值）：**光照内核 ≥2× vanilla 光照耗时**，且 e2e 总生成时间不回退。内核耗时隔离方式 + 口径随 D3 一并定义：L4 并行下对比口径 = **批 wall**（并行 Rust 批耗时 vs vanilla 批耗时），不是单 chunk 耗时（吞吐 vs 延迟区分，AGENTS 四）。

## 5. 有损边界（允许的近似，L1-L4；不可损项强制）

允许：
- L1 全量重算替代增量 mailbox 队列（单 chunk lightChunk 直算，无 PRE/POST 增量语义依赖——只覆盖生成路径；运行时方块更新仍走 vanilla 原路径，不在本课题范围）。
- L2 遮蔽简化：getLightBlock opacity 查找表；忽略 VoxelShape 面级部分遮蔽。
- L3 sky light 用 ChunkSkyLightSources 高度图柱状填充 + BFS（算法同构、实现扁平化）；空 section 穿透批量写。
- L4 chunk 级并行计算（bench 串行测量）。

不可损（强制）：
- 存储格式（DataLayer nibble/序列化/isLightOn）与下游全部读接口不变。
- **客户端发包粒度/时机不变**（保守统一；scout A「可放宽」观察项否决）。
- **Rust 写入 DataLayer 须兼容 vanilla 增量引擎**：尊重均质惰性表示（data==null+defaultValue）语义——运行时方块更新仍走 vanilla checkBlock/runLightUpdates，会读 Rust 写过的 section（L1 的隐含前置，升格显式）。
- 顺序依赖 6 条（scout A 清单）：跨 chunk 边界传播需邻 chunk 真实 blocks；邻 chunk 高度图可用性；section 状态不变量；读档 lightCorrect 语义；客户端发包粒度不变。

P2 强制前置廉价验证（judge 第 5 项，MUST，实现前完成）：
- (a) 接管点类/方法签名在生产 **yarn/loom 生成源码**核对（scout A 证据来自 Mojmap/Forge 树，mixin 目标注释/行号不可迁移；yarn 名 = ServerLightingProvider/LightStorage 一族）。
- (b) DataLayer 索引 `y<<8|z<<4|x` + nibble 高低半字节归属——对已知 chunk dump 3 点实测（布局事故 #40 同族）。
- (c-g) LIGHT range=1/hasLoadDependencies 复核、getSkyDarken 链、ChunkSkyLightSources 序列化、空段读 15 语义、下游读者清单——随 P2 首里程碑顺带核；下游清单不当完备清单用，由 G3 行为测试兜底。

## 6. 风险与回退

- G1 不达标 → 收窄 L2（恢复 shape 遮蔽）或 L3（改逐 cell BFS 全精度）逐级回退，每级重测。
- 接管后 LightingProvider 状态不一致（scout B 缺口⑤）→ 方案 B 保留外壳，风险已收敛；仍需 G3 行为级把关。
- 邻 chunk 数据未就绪（hasLoadDependencies）→ 遵守 LIGHT 既有依赖语义，Rust 调用前置检查，缺失即回退 vanilla 路径并记录。
