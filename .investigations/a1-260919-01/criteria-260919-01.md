## 2. A1 正式判别判据（判别式继承 criteria-260917-04 §3，读法写死）

**数据通道（本块新增）**：C6-D 臂 `[LIGHT-DOMAIN]` task 行新增 `fillMs= nativeMs= wbMs=`
（per-center 均值，LIGHT_TIMING 门控）。fill = assemble 拼帧段；native = `lightComputeDomain`
JNI 调用全程（含内核计算）；wb = 写回段。

**占比定义（写死）**：per-task 占比 = (fillMs + nativeMs) / (fillMs + nativeMs + wbMs)。
主读法 = **全部 task 行占比的 P50**；记录项 = 均值。

| 读法（预登记写死，三分支全域覆盖） | 判定 |
|---|---|
| P50 占比 < 30% | **A1（原生光照延迟优化）无显著改善**——判据满足 |
| P50 占比 ≥ 30% | 有改善面——报数值（fill/native 分解 + 占比分布） |
| P50 与均值分居 30% 两侧 | **灰区**——双值如实上报，不挑读法，交 judge/用户 |

## 3. 自证硬门（任一缺失 → 该臂 VOID，非零退出断链 #160；不挑臂 #118）

逐臂（C6-L 与 C6-D 同门）：
1. `lightInit ok` ≥1；`[LIGHT-DOMAIN] hook armed` ≥1；`Done (` ≥1。
2. in-log `dll=` sha 前 8 位与 target/release dll 实测 sha 一致（执行体三元组 #36/#96）。
3. **world 身份门（#161）**：每臂 fresh world（rmtree + 重建）；level.dat（gzip NBT）
   seed 解出值 = 驱动目标 seed（260918-11 采集台同款门）。
4. **使能开关口径（#156 全使能开关清单）**：两臂均 `-PlightRust=1 -Pformprobe=1
   -Pformdrive=1 -PlightTiming=1`；C6-D 另加 `-Pdomainbatch=1`。逐臂行为化自证：
   C6-L `LIGHTPROBE-T` 行 ≥1 且 `[LIGHT-DOMAIN] task` 行 = 0；C6-D `[LIGHT-DOMAIN] task`
   行 ≥1 且成功 task 行（`fail` 缺省）**每行带 `fillMs=`**（新打点在位正自证）；成功 task 行
   缺 `fillMs=` ⇒ VOID（`fail≠null` 行不带计时字段 = 合法形态）。
5. fallback/degraded 计数如实报告（非零立案如实记录，按 260917-04 前例归因）。

## 5. 边界（idk 如实）

- wb 段含 `enqueueSectionData` 异步排队 + setLightOn，非纯写回成本——分解口径在此声明，
  占比判别只用 fill+native 对全任务的比，不受 wb 内部构成影响。
- 域批任务体在 `Util.getMainWorkerExecutor` 线程，fill 段读 `st.blocks9s`（提交线程已完成
  收集的快照）——纯内存拼帧，无容器访问（260916-01 修复后形态）。
- 判别结果为「改善面上限」口径：即使占比 ≥30%，实际可达改善还受 Ame 定位与实现成本约束，
  本判据只回答「有无显著改善面」。
