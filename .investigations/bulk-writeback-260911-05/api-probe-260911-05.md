## 1. 结论：路线从「5 参构造器」改为「公开的 packet 导入通道」（**仍无需 mixin**）

| 候选路线 | 结论 | 依据 |
|---|---|---|
| **R-A：`new PalettedContainer(idList, provider, dataProvider, storage, paletteEntries)`（5 参 public 构造器）** | ❌ **不可用** | 其第 3 参类型 `PalettedContainer.DataProvider` 是**包私有 record**（`PalettedContainer.java:398` `record DataProvider<T>(...)` 无修饰符）⇒ `wg.bench` 包外**无法命名该类型**，javac 拒（`DataProvider is not public in PalettedContainer; cannot be accessed from outside package`）。`createDataProvider(...)` 虽 public，但返回值类型同样不可命名 ⇒ 无法传参 |
| **R-B：`@Accessor`/`@Invoker` mixin 拿 `PalettedContainer.data`** | ⚠️ 可行但**不再需要**（P2 作废） | accessor 声明必须命名 `PalettedContainer.Data<BlockState>`（同样包私有）⇒ 需 Forge **access transformer**（本项目是 Forge/SRG 线）⇒ 增构建复杂度 |
| **R-C（采用）：公开的 `readPacket(PacketByteBuf)` 导入通道** | ✅ **可用，且优于 R-A** | `PalettedContainer.readPacket` 是 **public**（`:203-215`）；storage longs **由我们直接打包**（连 per-position 容器写都省掉）；位布局由 MC 自己的 `PackedIntegerArray` 保证 |

**R-C 为什么比原计划的 R-A 更好**：R-A 仍需 `PackedIntegerArray.set` 逐点写 4096 次进容器；R-C 我们只构造 `long[]` 一次并整段导入。

## 2. `readPacket` 的精确 buffer 契约（逐字节，来自源码）

```
readPacket(buf):
  int i = buf.readByte();                      // :207  请求位宽（不是最终位宽）
  Data<T> data = getCompatibleData(this.data, i);   // :208 按 i 选 provider（见 §3 表）
  data.palette.readPacket(buf);                // :209 palette 项
  buf.readLongArray(data.storage.getData());   // :210 存储（长度必须精确等于 storage.getData().length）
  this.data = data;
```

| 请求位宽 `i` | provider（`BLOCK_STATE` 的 switch，`:420-430`） | palette 段字节 | **storage 位宽** | **storage 值域** |
|---|---|---|---|---|
| 0 | `SINGULAR`（bits 0） | `VarInt rawStateId`（`SingularPalette:67-68`） | 0（`EmptyPaletteStorage`） | —（写 0 个 long） |
| 1,2,3,4 | `ARRAY`（bits **恒为 4**） | `VarInt size` + `size×VarInt rawStateId`（`ArrayPalette:100-106`） | **4** | **局部 palette 索引** |
| 5,6,7,8 | `BI_MAP`（bits = i） | `VarInt size` + `size×VarInt rawStateId`（`BiMapPalette:74-81`） | i | **局部 palette 索引** |
| ≥9 | `ID_LIST` | **无字节**（`IdListPalette:45-46` 空实现） | `ceilLog2(idList.size())` = `ceilLog2(Block.STATE_IDS.size())`（`:427`） | **全局 state id**（`IdListPalette.index` = `idList.getRawId(object)`，`:24-26`） |

⇒ **Java 必须自己复刻这 6 行 switch**（因为 provider 类型不可命名），这是「三支」的全部内容；且 `size` 必须 ≤ 该 palette 容量（ARRAY 16 / BI_MAP `1<<bits`）。

## 3. 其余已确认的公开面

## 4. 定稿实现骨架（D1 / R-C）

```java
// 每 section：src = buf[s*4096 .. (s+1)*4096)  （y-major ⇒ 恰好连续切片，内部布局 = section 布局，零转换）
// ① 去重：raw id 域 16384 ⇒ ThreadLocal int[16384] 直映射（-1=未见），配 stamp 数组避免每 section 清 16384 项
// ② 得 distinct / paletteRawIds[] / paletteStates[] / localIdx[4096]
// ③ bits = distinct<=1 ? 0 : MathHelper.ceilLog2(distinct)
// ④ storageBits = switch: 0→0, 1..4→4, 5..8→bits, ≥9→ceilLog2(Block.STATE_IDS.size())
//    PackedIntegerArray pa = new PackedIntegerArray(storageBits, 4096);
//    for pos: pa.set(pos, idlistMode ? Block.STATE_IDS.getRawId(state) : localIdx[pos]);
// ⑤ PacketByteBuf b = TL_BUF.get().clear(); b.writeByte(bits); <palette 段按 §2 表>; b.writeLongArray(pa.getData());
// ⑥ PalettedContainer<BlockState> pc = new PalettedContainer<>(Block.STATE_IDS, Blocks.AIR.getDefaultState(), PaletteProvider.BLOCK_STATE);
//    pc.readPacket(b);
// ⑦ chunk.getSectionArray()[s] = new ChunkSection(pc, old.getBiomeContainer());
```

**捷径（常见态）**：`distinct == 1 && state == AIR` ⇒ 直接用 3 参构造器建全空气容器（air section 极常见），跳过 buffer。

## 5. 仍需运行期取值的项（由实现自带诊断首跑打印，不单独烧 gradle 周期）

1. `Block.STATE_IDS.size()` 与 `MathHelper.ceilLog2(...)` ⇒ ID_LIST 的实际位宽（预期 12-13）。
2. **ID_LIST 是否真触发**：vanilla 地形单 section 通常 20-80 个 state ⇒ >256 基本不可达；加**计数器**，触发即打印（若从未触发 = 死代码，风险≈0；但验证仍须专门找高多样性 section 压这一支）。
3. `calculateCounts()` 24 section/chunk 的实测成本（R1 消解已由构造器保证，此处只测成本）。
4. `PacketByteBuf` 复用（ThreadLocal + `clear()`）与 buffer 分配成本（ID_LIST 上限 ≈ 1+6144 字节/section）。
