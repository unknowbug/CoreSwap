## 二、C++ dll 11× 并发课题的生产相关性

**结论：C++ 11× 课题与当前生产主路径已脱钩——生产 worldgen 是 Rust cdylib（1.0.19 起），Rust 侧无 11× 争用（实测 4.65× 扩展）。C++ 11× 及其「下一真课题=长串行依赖链无损修复」应降级为 C++ 历史轨归档，不再作为活跃性能课题。**

- 生产路径 = Rust：`README.md`「Project Adjustment (2026-08-30): Core rewritten in Rust——one worldgen.dll（JNI 桥 + 引擎）单 Rust cdylib，C++ line archived」；版本线 1.0.19 起 Rust（README Notes「since 1.0.19 the native core is Rust」）；07 篇 L696-710「Rust cdylib（C ABI）→ C++ JNI 桥（worldgen.dll）→ mod 加载」三层链路；09 篇 L224 cppReplace 只接管 populateNoise+buildSurface（Java carvers/features 照跑）。
- Rust 并发无 11×：`.artifacts/dfc-direct-port/index.yaml` mt_fill T=1 790ms→T=8 170ms（**4.65× 扩展**，mismatch=0/16）——「Rust 无 C++ 11× 争用」有运行证据。
- C++ 11× 的机制定位（SplineDF 虚调用 ❌、长串行依赖链主导）全部落在 C++ engine 侧：`.investigations/worldgen-mt-scaling/density-latency-rootcause.md` §五（BASE 10.03× vs SERIAL 10.25×，locFn 非主导）+ 末节「指向下一真课题：production 并发争用的无损修复」——该「production」指 C++ production，非现役 Rust。
- ⚠️ 指向矛盾（需裁决，见第三节 P1）：NEXT_SESSION.md:22 仍把「CPU DFC 直排（替换 production SplineDF 树遍历虚调用，根源定位见 density-latency-rootcause.md）」列为性能主线，**但 Rust 侧 DFC 直排方向已关闭**（`.artifacts/dfc-direct-port/index.yaml`：「density 非瓶颈，biome 是热点，方向可关闭，证据链完整」），且其依据前提（虚调用=11× 元凶）已被 C++ 侧 DEVIRT 证伪（同 index，judge 发现 3）。NEXT_SESSION.md:27 自己也要求「对既有『SplineDF 虚调用是根源』定位做一次廉价独立验证（勿当公理）」。
