## A. 判据清单（可机械检查，每条注明来源）

| # | 判据 | 机械检查形式 | 来源 |
|---|---|---|---|
| **J1 数据量预算** | 每点上传数据量 × 点数须使上传时间占该环节预算 <~10%：逐块形态（8672 floats/pt × 98304 pt = 3.4GB/chunk）死局；角点形态（26.6MB/chunk）可行。粗门槛：<~100MB/chunk 或 ≪ PCIe 有效带宽 | 算术：`(每点 floats × 4B × 点数/chunk) / (PCIe ~16GB/s × 0.1)` 是否在预算内 | D24（带宽死局实证）、D27（角点形态 0.16GB/s 未饱和） |
| **J2 采样形态声明** | 任何带宽/摊销结论必须附采样形态（每点数据量 × 点数）；跨形态结论不可互迁 | 检查核算是否绑定单一形态声明 | D27 教训 3（带宽结论形态限定） |
| **J3 kernel 形态：禁止解释器式** | 介入点的 kernel 须为「每类型专项化 + 每 work item 算 1 个网格角点/1 个单元」的专用形态（C2ME OpenCLCGen 式），不能是通用解释器分派（单点 0.22ms/pt 主导） | 检查 kernel 设计：是否单 pass 求值任意点、有无逐节点分派循环 | D27（解释器单点成本主导）、G4/G5（解释器 = 小代码+数据是 CPU 正确形态，GPU 要专项化） |
| **J4 两阶段预填充结构** | interpolated/网格类环节必须两阶段（角点/单元预填充 buffer + CPU 或轻 kernel 插值），禁止单 pass 8 角点内联展开 | 检查是否存在 prefill kernel + 消费 kernel 两段 | G4（C2ME 网格预填充正解）、G2/G3（展开式编译爆炸） |
| **J5 结构兼容性（坐标参数化）** | 该环节的 GPU 数据布局必须是「共享实例 + 每点坐标参数」；若为「实例绑定固定坐标的冗余分组」（角点分组噪声），无法求任意点 → 不通过 | 检查噪声实例是否按坐标参数化（D25：8 份冗余实例 @c0..c7 绑定固定角点坐标） | D25（结构不兼容）、D12（结构共享与参数实例化分离） |
| **J6 回本门槛：当前 CPU 基线二分口径** | GPU 计算须不劣于**当前** CPU 基线（门槛随 CPU 优化同步抬高；本项目两口径：摊销口径 ~170×、门槛原义 ~38×，相对 8 线程 4.5ms/chunk）。且分母禁止用历史数字 | 算术：`GPU per-pt vs 当前 CPU per-chunk` 两口径分别核算，禁止混用 | D27 教训 2/4（门槛抬高 + 两口径二分）、verdict 口径注记（T=10 下界） |
| **J7 攒批摊销前置实测** | 立项前先跑一轮 n-scan 摊销曲线（4 档 × 7 轮中位数）；扩批 32× 而 per-pt 降 <15% 即摊销假设死，一轮判死活 | 检查是否已有摊销曲线数据且边际平坦度已知 | D27 教训 1（两次立项死于可一轮判死的假设）、workflow #24 补充（n 扫描一次否决整派） |
| **J8 CPU 侧占比门槛（先 benchmark 钉主导成本）** | 该环节 CPU 耗时占 chunk 总耗时比例须先实测（WG_PHASETICK 口径）；占比 <~15% 的环节即使 10× 加速全管线收益 <10%，不值得 GPU 级投入 | 检查是否有该环节 stage 级 CPU 占比实测数据 | D26（结构优化收益失真 5% vs 预估 2-4×）、D27（结构性成本非单点可解） |
| **J9 编译/分发可行性** | 需预编译二进制随 mod 分发（VK_KHR_pipeline_binary / C2ME tar.zst 模式）+ 现场编译兜底秒级；shader 规模函数数 ≤~50、单函数体 ≤~1.6KB（noodle 基准）；用户侧首次启动秒级 | 检查 kernel 是否可按设备分发 + shader 规模符合 noodle 基准 | G4（预编译分发）、G2/D5（函数体/函数数双维度）、G6（每用户每 GPU 首次约束） |
| **J10 并发安全与 CPU 管线共存** | GPU 调用须与 CPU 多线程 worldgen 共存（fill 加 mutex 串行 = 性能进一步劣化）；须有 per-thread GPU 资源或证明串行无损 | 检查是否多线程安全设计 + 串行化成本核算 | D24（P2-4 并发驱动崩溃 → mutex 串行化） |
| **J11 验证域覆盖能力** | 介入点须可跨域验证（多 chunk/cell/y 层 diff 抽查 + 边界分支覆盖）；吞吐探针必须带 diff | 检查验证方案是否含跨域采样 | D23（单域逐位一致 ≠ 全域正确）、D23 判错 2（性能探针必须带 diff） |
| **J12 bench 串行/口径纪律** | 任何判定数据须严格串行采集（无并发 bench）、微测外推须复刻调用形态（hot/cold 差 40-95×）、跨口径数字不比 | 检查采集方案的串行声明 + 形态同构声明 | workflow #28（并发污染）、#21（hot/cold 形态差）、#29/#30（时序自证） |

> J1-J5 = 结构/带宽域（一次死三次失败的三族根因）；J6-J8 = 经济性域；J9-J11 = 工程域；J12 = 测量纪律域（横切）。

### B1. density 专用 kernel 重设计（C2ME 式，verdict 三选一之 ②）

| 判据 | 判定 | 依据 |
|---|---|---|
| J1 | ✅ | 角点形态 26.6MB/chunk 已验证未饱和（D27）；专用 kernel 进一步降 per-pt 输入 |
| J2 | ✅ | 角点/单元形态可显式声明 |
| J3 | ✅（设计目标） | 专项化 kernel 是该候选的定义本身（每 DF 类型一个 kernel） |
| J4 | ✅（设计目标） | 网格预填充原生实现是候选核心（G4） |
| J5 | ⚠️ | 需重构为「共享实例+坐标参数」（D25 指出当前生成器为角点分组冗余）；工程量大但方向明确 |
| J6 | ⚠️ | 38×/170× 起步门槛已知，但专用 kernel 的实际 per-pt **无实测**——这是最大未知数（C2ME 证明 OpenCL 可行，未证明本项目 Vulkan 移植可达） |
| J7 | ✅（已有数据） | D27 摊销曲线已在盘（对新 kernel 仍需重测，但方法已知成本一轮） |
| J8 | ✅ | density 是 CPU 主导成本（estopt/MT 系列在盘） |
| J9 | ⚠️ | 两阶段可拆 7 个 kernel（C2ME 先例），但本项目 shader 规模历史劣迹（D1/D3/D5/D21/D22）——spline 动态分派/SSBO 化教训需全部规避；预编译分发未验证 |
| J10 | ⚠️ | 多线程 worldgen 下 GPU 资源并发方案未设计 |
| J11 | ✅（方法在盘） | 三件套复验 + 跨域 diff 方法已建立（I5/D23 修复后） |
| J12 | ✅（方法在盘） | #28/#29/#30 纪律已固化 |

小结：结构域全过/可过，**经济域 J6 依赖专用 kernel 实测（无数据）**，工程域 J9/J10 未设计。

## C. 判据无法判、需实测数据的盲区项

| 盲区 | 需要的实测 | 阻塞的判据 | 廉价获取方式 |
|---|---|---|---|
| 1. 各阶段 CPU 耗时占比分解 | Rust 侧 WG_PHASETICK（或等价）stage 级 ms/chunk：density/aquifer/biome/surface/carvers/feature/光照 | J8（B2/B3/B5/B6/B7 全部卡在此） | 既有探针跑一轮（探针污染铁律下用无探针整批 wall + PHASETICK 计数口径） |
