## 4. (b) 全树单 dispatch 判决

### 4.1 判据回顾

- (b) 立项重议条件（260903-12）：density 段需 **<4.5ms/chunk**（对标 8 线程 CPU，「超 Java 10×」门槛换算）。
- CPU 对照基线（260903-16 confirmed）：default ~27.5–28.5ms/chunk（256 chunks 大样本 median）。

### 4.2 数据论证

1. **边际成本不下降**：重估实验的核心问题「n≥49152 边际是否下降」答案为否——三档边际 0.2319→0.2331 ms/pt，平到第四位有效数字且末档**微升**。GPU 通道密度通路的成本是**逐点计算主导**（~88%+ 为边际），放大批次无法摊薄。
2. **per-chunk 折算 vs 判据**：全档 per-chunk 折算 178.4–188.1ms，即达到批次上限（256 chunks）时 density 段仍 ~178.9ms/chunk——是 **<4.5ms 判据的 ~40 倍**，且这是把固定成本摊到最薄后的下界。缺口感 ~174ms/chunk，比判据大两个数量级，不存在改造能闭合此缺口（改造面只能砍固定成本与 dispatch 开销，砍不了逐点 0.233ms 的计算成本本身；要降 c 需重写 shader 算法/精度/吞吐结构，属另一立项而非 (b) 范围）。
3. **vs CPU 基线**：178.9 vs 27.5–28.5ms = **慢 ~6.3–6.5×**。GPU density 段不仅达不到「超 CPU」，反而显著慢于现有 CPU 路径——(b) 即使立项也负收益。

### 4.3 判决（candidate 候选，draft）

**（b）全树单 dispatch：终局出局。**

- 依据链：边际成本全档平坦（0.232±0.001 ms/pt）→ 批量化无摊薄空间 → per-chunk 下界 ~178.9ms，距 4.5ms 判据 ~40×，距 CPU 基线慢 ~6.3× → Amdahl 上界下 (b) 不可行，且负收益。
- 至此 GPU 批量化三候选全灭：(a) 合批+异步（260903-16 出局）、(c) 混合（同上）、(b) 全树单 dispatch（本轮出局）。GPU density 加速课题建议按 260903-16 判决收束——GPU 通路仅保留诊断/对拍价值，性能主线回归 CPU 侧（如 C2ME 式 DFC 编译直排）。
- 本判决为降级结论援引（Degraded→Partial 层性能读数，非逐位对齐验证），§9.7 三要素见 §1。
