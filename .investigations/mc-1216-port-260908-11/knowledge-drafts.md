### 发现 #88: 生成期探针 = 一次性窗口——「在盘」≠「会重新经过探针」，复跑采集必须删 world（260908-11）

- **时间/置信度/module**：260908-11；candidate（dbg 行确认采样点在 chunk 生成期触发 + 复跑零命中可复现）；workflow-patterns / 探针采集纪律（#19 删 run\world 家族的**生成期探针**形态，#13「探针零输出先查过滤/驱动条件」新分支）。
- **来源定位**：`.investigations/mc-1216-port-260908-11/errors.md` E3；progress-260908-11.md §F2 链级验证。
- **现象**：air 点集 aqdump 复跑（未删 `run\world`）→ `[AQDUMP] done` 但 0 行输出、输出文件未创建；同命令删 world 后正常命中。
- **根因**：aqdump 类探针采样钩在 **chunk 生成期**（worldgen 管线内）；复用已生成世界时 chunk 直接从 region 读盘，根本不重新走生成管线 → 探针窗口已关，零命中是结构性的，不是 bug。
- **定位**：对照删 world 重跑（同 seed）→ 命中恢复；「done 但 0 行 + 文件未创建」= 窗口已关签名。
- **判据/如何利用**：① 生成期探针（worldgen 管线内钩子）**每次采集前必删 `run\world`**，与 seed 三查并列成固定前置；② 「探针零输出」排查树加分支：先问「目标 chunk 会不会重新走生成路径」再查过滤/驱动条件；③ 「在盘」与「会经过探针」是两件事——凡探针挂在过程性管线（生成/加载/写入）上，其可观测窗口 = 该过程实际发生的时刻。
- **证据**：errors.md E3 三段 + progress 记录。

### 发现 #88 附（同条收编）：E4 驱动开关与数据通道是两个开关（#20 死参数家族变体）

- **时间/置信度/module**：260908-11；candidate；workflow-patterns（#20 补充案例，随 #88 同载体记录）。
- **来源定位**：`.investigations/mc-1216-port-260908-11/errors.md` E4。
- **现象**：`-PaqDumpRust` env 数据通道已配（dbg 行确认生效）但无 AQDUMP 输出、服务器不自动停。
- **根因**：Rust 侧 dump 只打命中点，点区域 chunk 无人加载时无输出；且 forceload pregen + stop 的**驱动**由另一开关 `-PaqDump` sysprop 触发——数据通道生效 ≠ 行为链闭合，缺驱动臂 = 无人触发采样也无人停服。
- **判据**：多开关接线任务先画「开关→行为链」图：**驱动开关（谁触发/谁停止）与数据通道开关（谁记录）分开核对**，各自要有行为化证据；dbg 行只证「通道开」，不证「链闭合」（#81 同族）。新接线通道首跑无 dbg 行则三态（property 未映射/env 未传/点未命中）不可区分——新通道首跑必须先带行为化 dbg（E5，#32/#81 家族）。

### 发现 #89 简记: 探针可观测窗口被缓存/早退主导时，spread 路径字段级验证结构性难采样——降级声明须写明采样失败机制（260908-11）

- **时间/置信度/module**：260908-11；candidate（四轮多形态点集一致 + 机制解释明确）；workflow-patterns / 验证载体局限（简记，中价值）。
- **来源定位**：`.artifacts/mc-1216-port-260908-11/verdict-f1f2-chunky-260908-11.md` §F2 降级声明；progress-260908-11.md §F2。
- **现象**：F2 探针 spread-replay 路径的字段级手算对拍多轮未达成：164 地表柱点 / 1408 深部网格点全 density>0 早退、144 空气点 / 28 水洞点走链但**缓存命中主导**，几乎采不到 replay（扩散重算）行。
- **机制**：aquifer 链字段在首算后缓存，后续查询命中缓存即返回——replay 行只在缓存 miss 且需扩散重算时出现，正常采样集里占比趋零；「点集选在哪」不能改变这一结构性占比（早退点集连链都不进）。
- **如何利用**：① 验证目标落在低频路径（如 spread-replay）时，先评估该路径在可用采样形态下的**可采性**，不可采就 early 声明降级（静态对齐 + 旁证），不要多轮硬采（本轮四轮即达证据饱和）；② 降级声明不只写「未达成」，要写**为什么采不到**（缓存命中主导/早退主导），下个块才不会重走同一死路；③ 跨执行体旁证（Rust 自算链 fl/decision 与 vanilla 缓存真值逐点一致）是 spread 路径不可采时的可接受替代证据等级。

### #80 补充案例（260908-11，反向形态）：核验时机必须跟随被核验行的产生时机——Done 后 init，即时断言 FAIL 误报

- **时间/置信度/module**：260908-11；candidate（30s 轮询后稳定命中）；workflow-patterns（#80/#69 时序家族的核验侧反向形态）。
- **来源定位**：`.investigations/mc-1216-port-260908-11/errors.md` E6。
- **现象**：coreswap 臂 `Done (4.952s)` 后立即 grep `[CppBridge] init` → 空 → FAIL 退出（且 FAIL 分支未杀 java，残留进程）。
- **根因**：BenchMod/CppBridge 初始化是惰性的，init 行在 Done 之后若干秒才打印；「以 init 行时间戳作接管生效判据」是 #69 原判据，本条是反向：**核验早于 init 行产生**——被核验事件与查询时刻错序，即时断言结构性误报。
- **判据/如何利用**：① 核验脚本先确认「被核验行在日志流的哪个时刻产生」（可早可晚于 Done），查询时机跟随产生时机，**逐秒轮询带超时**（如 30s）优于即时断言；② FAIL 分支必须补资源清理（杀 java），否则误报还留残留进程污染下一轮；③ 判「核验失败」前先区分「事件未发生」与「事件尚未发生」。

### 发现 #42 简记: JNA 临时文件「拒绝访问」瞬时错误——瞬时环境错误重跑优先于立案 + 驱动脚本固化 `JAVA_TOOL_OPTIONS` tmpdir 规避（260908-11）

- **时间/置信度/module**：260908-11；candidate（一次复现一次自愈 + tmpdir 固化后未复发）；build-tooling / JVM 环境坑（简记；#38 平台分层家族环境面）。
- **来源定位**：`.investigations/mc-1216-port-260908-11/errors.md` E7；progress-260908-11.md 载体备注。
- **现象**：runServer 启动一次报 `UnsatisfiedLinkError: Failed to create temporary file for jnidispatch.dll: 拒绝访问`，重跑即恢复。
- **根因**：沙箱下 java.io.tmpdir 提取 JNA 临时 dll 偶发被拒（环境面瞬时，非代码缺陷）。
- **修复/判据**：修复 = Chunky/探针驱动脚本统一 `JAVA_TOOL_OPTIONS=-Djava.io.tmpdir=.tmp\java-tmp`（1.20.1 驱动已有先例，本次固化到 1.21.6 驱动）。判据 = **一次性、重跑即消的环境错误先重跑复现次数再决定是否立案**；复发模式的环境坑才升级为脚本级固化规避。
- **教训**：驱动脚本固化规避要进脚本本身（不靠记忆），跨版本复制驱动时随命令清单一并带走。

### #14/#18 补充案例（260908-11）：伪参照跨块存活在「权威数据目录」——路径权威 ≠ 内容权威；已 confirmed 数字是现成复现锚

- **时间/置信度/module**：260908-11；candidate（旧 R 臂交叉 diff 定责 100.0000% + 真参照复现 99.9993%）；build-tooling（#14「文件名内嵌 bench.seed ≠ worldSeed → 伪参照」260908-10 案例的**跨块存活**新形态 + #18「在盘 ≠ 本次执行体生成」目录维度）。
- **来源定位**：`.investigations/mc-1216-port-260908-11/errors.md` E1；`.tmp/p7-260908-10/vanilla/`（真参照）。
- **现象**：1.21.6 P7 R 臂复跑与 `versions/1.21.6/data/vanilla_-8248318472910187742_8_200_200.blocks` 对拍 = 89.08%、biome 14160/16384 差（ocean↔deep_ocean）→ 疑似大回归。该文件是 NEXT_SESSION 260908-10 已警告的伪参照（17:44 导出时 level-seed 未设 → worldSeed=-5307 污染副产品），**却放在正式 data 参照目录里且文件名内嵌正确 seed**，跨块存活一天后再次被当真参照消费。
- **根因**：测量侧错误。伪参照未清理出权威目录——「位于 data 目录 + 文件名内嵌 seed」两信号都是**位置/命名权威**，不构成**内容权威**；对拍异常时先怀疑实现回归，把测量侧排最后，成本倒挂。
- **定位（怎么发现的，可复用）**：三步交叉定责：① 核接管证据（807 intercepted ✓，排除未接管）→ ② 核 dll/工作区 diff（仅 F1 一分支，量级远小于 89%）→ ③ **旧 R 臂交叉 diff**：新 R vs 旧 R = 100.0000%，旧 R vs 伪参照 = 同一 89.08% → 锁定测量侧。改用 `.tmp/p7-260908-10/vanilla/` 真参照 → **99.9993%/41/biome 0**，与已 confirmed 结论逐位复现。
- **判据/如何利用**：
  1. **参照谱系核对是任何异常对拍的第一动作**——先核参照文件（来源 run、seed 头、导出时间）再怀疑实现；「已警告过的伪参照」会换目录/换块存活，警告不清除文件本身则必再犯。
  2. **已 confirmed 的结论数字是现成复现锚**——复跑结果对不上时，先对「旧产物 vs 旧产物」做交叉 diff 分离测量侧/实现侧（两侧都过 confirmed 锚 = 实现没变）。
  3. data 目录里的参照文件建议带谱系注记或在收录时核对 seed 头（内容指纹），防位置权威冒充内容权威。
- **证据**：errors.md E1 全段；99.9993% 复现数见 verdict-f1f2-chunky-260908-11.md §F1。
