## 〇、记录价值门（2026-08-21 对齐框架升级——先判价值，再决定写不写 & 写多详）

**写任何知识库内容前，先过价值门**。这是框架新增的上位规则，本文件以下所有载体/格式都在价值门约束下执行。原则：**只记"若再遇到，我不想重新想一遍"的东西**——完全用这个标准筛，比"发现了就记"诚实得多。

| 层级 | 判定（复用判据） | 处置 |
|------|------|------|
| **高价值（必记）** | 错误/失败链条、判错方法/签名、环境坑、反模式、可复用判据 | 详实记录（五段式错误台账 / 判错经验 / 速查表） |
| **中价值（简记）** | 算法/协议指纹、编译器惯用法、跨模块通用模式 | 只记"是什么"，格式从简 |
| **低价值（不记）** | 一次性结论（某次跑出的数值、特定地形位置、自推可得）、当前对齐状态快照 | **不写入知识库**——写进去反而稀释高价值资产权重 |

**铁律**：结论性 docs（主题篇/时间线）**不是**知识库核心资产——无复用价值的结论不写进去。别为一次性结论花 subagent 迭代成本（那是"无价值结论写成 docs"的反模式，与"主会话自评污染"同样不合规）。

## 一、错误优先原则（最高优先级，用户 2026-08-13 明确）

**错误信息 + 详细记录「为什么错」才是最重要的资产，比验证通过的正确结论更重要。**

1. 排查中遇到的**每个错误/踩坑** MUST 按五段式完整记录，不得只记「已修复」而不记「为什么错」。
2. 错误台账的**详实度要求高于一切正确结论**——正确结论只记「是什么」，错误链条要记「不是什么 + 为什么」。
3. **被排除的假说同样保留**（❌ 在主题篇留一行排除清单；完整链条进错误台账/时间线）——排除链条是核心资产，防重走弯路。
4. **判错经验尤其要记**：可复用的判错方法（如「符号级错误一定是结构错不是精度错，先查公式/索引/坐标，别在精度上纠结」）必须沉淀，比单条错误更有价值。

## 二、五段式错误记录格式（每条错误 MUST 完整）

| 段 | 内容要求 |
|---|---|
| **现象** | 具体数据/表现（报错原文、数值、波形、输出片段），禁止笼统描述 |
| **根因** | 为什么错——机制层面（对象搞混/索引错位/语义差/常量传播…），不是表面现象复述 |
| **定位** | 怎么发现的——诊断方法/工具（减法二分、ref_probe 对拍、spirv-dis、grep 断言…） |
| **修复** | 改了什么（文件+逻辑+为什么这样改能修） |
| **教训** | 下次怎么避坑 + 可复用判错经验 |

**反模式**（绝对禁止）：
- ❌ 只写「已修复」不写根因机制
- ❌ 现象=根因（把表面表现当原因）
- ❌ 无定位过程（「改对了」但说不出怎么发现的——下次同类错误无法复用）

## 三、知识库载体映射（CoreSwap 项目实际结构，非 skill 通用 errors/ 目录）

**载体优先级**：项目级指定载体 > 框架默认 `knowledge/discovered/errors/error-<NNN>-<slug>.md`。两条规则**不并行**——CoreSwap 用项目级指定载体（见下表），框架默认路径为未被指定时的回退（本文件即"项目级指定载体"的声明，消除"默认路径成死规则"）。

| 内容类型 | 载体 | 价值门 | 说明 |
|---|---|---|---|
| **错误台账**（排查中每个错误） | `.investigations/<课题>/<课题>-errors.md` 独立成篇（如 perf-rework/gpu-accel-errors.md） | **高价值（必记）** | 按 A-G/D 系列编号（GPU 课题）或项目相关编号；**独立成篇不散落**；末尾附「错误→根因」速查表（一页索引） |
| 结论/已验证/修复 | `versions/1.20.1/docs/` 01-09 主题篇 | 按价值门分层（高价值详记/中价值简记/低价值**不写 docs**） | 追加小节，**追加不覆盖**；被排除假说只留一行 ❌ 排除清单 |
| 排查过程/中间结论/被推翻假说/工具演进 | `versions/1.20.1/docs/10-timewise-archive.md` | 中价值（简记） | 时间线追加，每条带状态 ✅/❌/🔍/已结案 |
| 通用可复用模式（跨版本/跨项目） | `knowledge/discovered/`（INDEX.md 入口） | 按价值门分层 | 按 core-knowledge 的「发现 #N」格式，写后同步 INDEX |
| 过程性中间产物 | `.investigations/` | 主会话可写，非结论 | 临时排查记录/中间产物，非知识库资产 |
| 结论性 docs/discovered（**高价值**内容） | subagent 产出草稿 → 主会话应用 + 验证 | 高价值 | 强制触发点（AGENTS.md 九） |
| **无复用价值的结论**（记录价值门低价值层） | **不写 docs** | 低价值 | 不是"subagent 写"，而是**根本不写**——避免为一次性结论花 subagent 迭代成本 |

**载体纪律**：
- 主题篇（01-09）禁止新建时间线式章节（时间线只进 10）；
- 错误台账独立成篇（如 <课题>-errors.md），不与正确结论混写；
- 交接文档唯一 `NEXT_SESSION.md`（仓库根，不入库），禁止在子目录建交接副本；
- **先过价值门再选载体**：低价值结论不进任何知识库载体（docs/discovered/INDEX），只留 `.investigations/`（过程性，主会话可写）。

## 四、产出检查清单（subagent 交付前自检）

- [ ] **先过价值门**：本条内容是高/中/低哪档？低价值 → 不写知识库（只留 .investigations/ 或不落盘）
- [ ] 每个错误都有五段式（现象/根因/定位/修复/教训），无「只记修复」条目
- [ ] 根因是机制层面（为什么错），不是现象复述
- [ ] 定位含诊断方法/工具（可复用）
- [ ] 判错经验已沉淀（有则必写）
- [ ] 被排除假说有标注（❌/⚠️），未删除
- [ ] 写入载体正确（错误→错误台账 / 高价值结论→主题篇 / 过程→时间线 / 通用→discovered）
- [ ] 无复用价值的结论**未写 docs**（正确处置 = 不写，不是简写）
- [ ] 错误台账末尾速查表已同步（新增错误加一行）
- [ ] 数字来自主会话提供的实测记录，无编造、无占位符
- [ ] 格式与目标文件末尾现状对齐（先读目标文件末尾再写）

## 五、与框架通用 skill 的关系

- core-knowledge skill（框架通用）定义了「错误 > 正确」优先级 + **记录价值门三分**（高价值必记/中价值简记/低价值不记）+ 错误账本条目格式 + 载体优先级（项目级指定 > 框架默认）；
- **本文件是 CoreSwap 项目级强化**：载体改为项目独立错误台账文件（声明项目级指定载体）、格式改为五段式、补充判错经验要求与载体纪律、**与框架价值门对齐**（§〇 复用判据 + 低价值结论不写 docs）；
- 冲突时**本文件优先**（项目级指令 > 框架通用层，同 AGENTS.md 优先级规则），但**不冲突框架价值门**——本文件是价值门在 CoreSwap 的落地，不违背框架上位规则。
