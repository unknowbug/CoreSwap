## 结论

1. **Java 侧 bulk section 写回已落地并与老路径等价**：607/625/625 次写回调用（overworld/nether/end）的**写回后读回指纹逐 chunk 全等**——方块状态层（`hash`）与派生字段层（`dh`，三个计数）**差均为 0**，覆盖 59,670,528（overworld）+ 各 625×N 位置；两臂 chunk 集完全相同、零异常。
2. **编码四支全绿**：SINGULAR / ARRAY / BI_MAP / **ID_LIST**（合成自检逐位读回，自然生成 `max_distinct=7` ⇒ ID_LIST 实测不可达，必须刻意压测）。
3. **写回分项成本**（同 run、同仪器、单变量 `-Dcoreswap.bulkwb`）：overworld −69.7%、nether −67.7%、end −71.4%；其中 `counts_set` 由 `calculateCounts` 的 72,480 ns/section 降至 ~100 ns/section。
4. **价值定位**：**可维护性/可移植性为主**（消掉 98,304 次/块逐块循环与 per-version 诊断，为共享 Java 适配核与 1.21.6 收敛铺路）；性能为**次要附带收益**，端到端落在 ±10% 机器噪声带内，**不予主张**。
5. **两项实施期发现（高价值）**：
   - `calculateCounts()` 与增量 `setBlockState` 的**计数语义不一致**（流体重复计入 `nonEmptyBlockCount`；`nonEmptyFluidCount` 只计有随机刻的流体）⇒ 走构造器会静默改变 `hasRandomFluidTicks()`/客户端包语义；已改为复刻增量语义。
   - `bits==0` 的单态 section **不得构造 `PackedIntegerArray`**（`Validate 1..32` 抛 IAE，首跑 539 次）。
6. **Tier 3（region 差 0）判据在本 harness 不可达，已降级声明**：全域差 0.0277% 中，**从未走过本代码路径的 chunk 也有 0.0260%** ⇒ 残差是跨 run 固有抖动（FEATURES 阶段产物 + 随机刻可改写方块的双向对称变化）。**口径外溢须登记**：本工程历史上基于 live-server region 对拍的保真度数字（含 B1 复算的 0.0133-0.0198%）同受该抖动限制，不可当绝对保真度读。
