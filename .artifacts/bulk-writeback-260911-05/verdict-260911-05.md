## 结论

1. **Java 侧 bulk section 写回已落地，与老路径在「写回点内存态」逐 chunk 全等（层次与前提必须声明）**：607/625/625 次写回调用（overworld/nether/end）的**写回后读回指纹逐 chunk全等**——方块状态层（`hash`）与派生字段层（`dh`，三个计数）**差均为 0**，覆盖 59,670,528（overworld）+ 各 625×N 位置；两臂 chunk 集完全相同、零异常。
   - **层次（judge M3）**：等价的是**同 JVM 内、写回之后的内存态**；**存档层未证等价**（见结论 6）。
   - **前提（judge M3）**：等价**依赖「section 入口全空气」**——老路径 `SKIPAIR` 对空气格不写（保留旧块），新路径整容器替换（清为 air），前提被证伪时两路径行为**相反**。该前提**已实测**：`-Dcoreswap.wbcheck=1` 臂 `[WB-CHECK] air_skipped=40,329,368 stale_nonair=0`；且 Tier 1 的全等结果在 5,967 万位置上**独立蕴含**该前提。
2. **编码四支全绿**：SINGULAR / ARRAY / BI_MAP / **ID_LIST**（合成自检逐位读回；自然生成 `max_distinct=7` ⇒ ID_LIST 实测不可达，必须刻意压测）。**边界（judge S4）**：自检编码侧与期望侧共享 `stateById` 与索引约定 ⇒ 它验证的是「字节流能被 **vanilla 自己的** `readPacket`/四支 palette/`PackedIntegerArray` 接受」+「长度前缀精确匹配」+「分支选择正确」；**验不出** `stateById` 映射错误（由跨实现世界对拍承载）与 buf 布局约定错误（由 Tier 1 承载）。
3. **写回分项成本（同 run、同仪器、单变量 `-Dcoreswap.bulkwb`）**：overworld −69.7%、nether −67.7%、end −71.4%；**结论表述为区间 −49%~−70%**（两轮：2,070,297→1,052,606 = −49.2%；2,151,591→652,202 = −69.7%）。
   - **§9.7 声明（judge S3）**：`counts_set` 72,480 ns/section → **116 ns/section** 是**跨载体量并列**，不可读成「计数成本降到 1/600」——`calculateCounts()` 被**消除**，其替代成本（O(distinct) 去重遍）**并入 `build`**（`build=75,666` 含 `readPacket`）；`counts_set=116` 只是发布计数引用的成本。
4. **价值定位**：**可维护性/可移植性为主**（消掉 98,304 次/块逐块循环与 per-version 诊断，为共享 Java 适配核与 1.21.6 收敛铺路）；性能为**次要附带收益**，端到端落在 ±10% 机器噪声带内，**不予主张**。
5. **三项实施期发现（高价值）**：
   - `calculateCounts()` 与增量 `setBlockState` 的**计数语义不一致**（流体重复计入 `nonEmptyBlockCount`；`nonEmptyFluidCount` 只计有随机刻的流体）⇒ 走构造器会静默改变 `hasRandomFluidTicks()`/客户端包语义；已改为复刻增量语义。
   - `bits==0` 的单态 section **不得构造 `PackedIntegerArray`**（`Validate 1..32` 抛 IAE，首跑 539 次）。
   - 「607 vs 441」误推为「重复接管存在」（record §3.3）：Chunky 的 `center` 是**方块坐标**，`-48,-11` 块 = chunk `(-3,-1)`，半径 160 块 = 10 chunk ⇒ 441 = 21×21 ✔；607 行坐标**零重复**，差额 166 = 服务器自生成邻近 chunk。
6. **Tier 3（region 零差对拍）＝ 判据未满足（FAIL）+ 残差未归因（judge M1 判决后定稿）**：
   - 预注册判据（`verify-design-draft:29-33`）是 **`diff = 0`**，实测全域 **0.0277%** ⇒ **未达成**。
   - **补跑 `bulk × bulk` 同实现对照（3 对，judge 指出的唯一缺失对照）**：切片 A = 0.0352 / 0.0358 / 0.0272%；而 old×old 3 对 = 0.0249 / 0.0239 / 0.0284% ⇒ **交付对 0.0348% 落在 bulk 臂自身跨 run 区间内** ⇒ **无「写回引入系统性存档层差异」的证据**。
   - **弱信号（如实登记，不掩盖）**：按「对里是否含 bulk 臂」分组，两组**不重叠**（含 bulk 的对 0.0258–0.0284% vs 两 old 的对 0.0238–0.0253%，全域口径）⇒ 最自然的读法是 **bulk 臂自身跨 run 离散度更高**（**方差效应，非均值效应**）。n=3/组、切片 A 口径下区间仍重叠 ⇒ **仅提示性，未达显著**。
   - **机制候选并列**：A 运行期调度（bulk 每 chunk 快 ~1.5 ms ⇒ 改变并行生成流水线中「邻块写特征」先后）；B 容器编码差异（**不成立方向**：Tier 1/2 已证写回后状态逐位全等）；C 其他（开放）。**噪声底主体在 vanilla FEATURES 阶段**（关掉全部 live-server 随机源后差分仍 0.0259%，top pairs 仍是特征产物）⇒ 随机刻只占 6-11%。
   - **分母口径**：归档世界 313,589,760 块中 **58.1%（1854 个 chunk）从未生成内容**（纯稀释分母；两侧皆空 chunk 差分**恰好 0**，100% 的差分落在有内容的 1336 个 chunk 上 = 0.0661%）；成因一手源 = `ChunkSerializer:301-312` 对光照范围内每个 section 索引**无条件**写 `block_states`（无 `isEmpty()` 检查）⇒ 未走到 NOISE 的部分生成 chunk 也会完整落盘。
