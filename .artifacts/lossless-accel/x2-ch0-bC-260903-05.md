# X2 通道对拍 bC：ch0（final_density 顶层 Interpolated）角点 y 依赖性判定（core.worker，260903-05）

- 状态：draft（Degraded 静态级——知识库/文档/历史参照数据实证，未跑新探针）
- 问题：chunk(0,0) x=4,z=16 列，seed=8576294172403134396，Rust transpiler ch0 角点 y=8≡y=16（-1.386253）、y=200≡y=208（-1.139378）跨 y 恒定段；GPU ch0 y=8/16/56 平滑变化。Java 语义下 ch0 角点应「随 y 平滑」还是「存在跨 y 恒定段」？

## 结论

**Java 语义下 ch0（顶层 Interpolated，即 interp(blend_density(...))，ChunkNoiseSampler interpolators idx0）角点值应随 y 平滑变化；不存在结构性跨 y 恒定段。** Rust 侧 y=8≡16 / y=200≡208 的严格相等是**结构性 bug 签名**（角点 y 索引/跨度问题），不是 Java 行为。GPU 的平滑变化方向与 Java 语义一致。

## 结构性理由（证据链）

1. **ch0 身份（03 篇 L96/L97）**：8 个 DensityInterpolator 中 idx0 = finalDensity 顶层（BlendDensity）；树 = `min(squeeze(0.64×interp(blend)), caves/noodle)`。X2 的 ch0 = 5 channels 里的 interp_0 = 该顶层 Interpolated（x2-pivot-judge-260903-05.md B1：interp_0..4 与 5 channels 对应）。
2. **interp 的 arg 是 3D 树，y 依赖内嵌于 Interpolated argument（vanilla 语义，judge 文 B1-3 已确认）**：blend_density(init 树) 展开为 `0.1171875 + yclamp×(...range_choice(sloped_cheese, when_in=min(sloped_cheese, 5×entrances), when_out=cave 逻辑))`（algorithm-fingerprints.md 发现 #2）。三个 y 依赖源：
   - **YClampedGradient[fromY=-64, toY=320, 1.5→-1.5]** 在树内（vanilla_density_overworld_c45_-26_b8_8_cache.txt L9 实证存在）——随角点 y 线性变化；
   - **sloped_cheese = base_3d_noise（InterpolatedNoiseDF）** 是 3D 噪声，逐角点 (x,y,z) 采样；
   - **entrances 是 3D 噪声**，在角点约束 when_in（fingerprints 发现 #2：同 (x,z) 不同 y 的角点值各不相同）。
3. **empirical 铁证（fingerprints 发现 #2，GRID 角点 dump）**：cacheId=12（init 树 interpolated）单个 cell 的 8 角点 = 0.1471/0.0522/-0.2658/-0.3200/0.0476/-0.0854/-0.3258/-0.3774——同一 cell 内 8 个角点（含 y 方向 2 层）**全部不同**，三线性 fy=0.5 才有意义。Java 角点从不出现「相邻 y 层严格相等」。
4. **cache dump 逐 y 值实证（c45_-26_b8_8_cache.txt）**：树内各 y 依赖分量在同 (x,z) 不同 y 的采样值全部不同（如 L9 factor 链、L11-15 aquifer_lava noise：-0.971@-64 / 0.378@-8 / 0.097@0 / 0.045@8 / -0.015@48）。
5. **2D 性不适用于 ch0**：flat_cache / Cache2D（2D 性来源）只作用于 offset/factor/continents/erosion/ridges 的 spline locationFunction 与 depth 链（YClampedGradient+FlatCache+Cache2D 组合），它们是 noise_router 的**独立分量/ch0 arg 的间接输入**；顶层 interp 的 arg 本体无 2D 化包装。若 ch0 角点真为 2D，那意味着整棵 blend 树被错误地按 (x,z) 采样——与 Java NoiseChunk 语义（角点 = arg.sample(corner) 逐 3D 坐标）相悖。
6. **恒定段唯一合法位置**：y≥256 无地形常数分支（-0.02499 类，timeline L1366/y-scan）属于 final_density combine 后整树行为，且是 clamp 分支非「角点重复」；ch0 角点在 y=8/16、y=200/208（地形主区间）不落入任何常数分支。

## 对 X2 对拍的判读

- Rust transpiler y=8≡16 严格相等（相隔一整个 y 格距=8）⇒ 其角点填充在某处把 y 维折叠/复用（嫌疑：fill_cell_corner_densities 的 gy 索引、或某 2D 缓存误罩 ch0 arg）——**Rust 侧偏离 Java**，需修。
- GPU y=8/16/56 平滑（-1.1128/-1.0967/-1.1264）⇒ 方向正确；对拍参照应以修复后的 Rust/C++ 角点为准，不能以现 Rust transpiler 值为 ground truth。
- 判定性质：候选（结构证据充分，建议后续用 densityDump/got_export 对 x=4,z=16 列直接 dump ch0 角点逐 y 复核升级）。
