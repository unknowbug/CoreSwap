# X2-bB (260903-05): GPU ch0 独立调用形态 vs final shader interp_0 d000 等价性审查

- 状态: **draft**（静态审查，Degraded 层——无运行时探针新数据，仅代码逐字比对）
- 范围: `.investigations/perf-rework/dfc_gen.py`（生成器）、`final_density.comp` / `final_density_ch0.comp`（生成产物）、宿主 `gpu_density_engine.cpp`
- 待判定假设: 「GPU ch0 main 的 `eval_df_base_0(133,0,sIdx,ix,iy,iz)` 调用形态 ≠ final shader interp_0 的 d000」——特别怀疑 valBuf 区段 / corner 语义 / root 常量。

## 证据

### E1. 两份 shader 逐行 diff：除 main 末行外**字节级全同**
`Get-Content` 逐行对比 967 行 vs 967 行，唯一差异：
```
LINE 966:
  final_density.comp    : outBuf.density[idx] = eval_density(int(idx), ix, iy, iz);
  final_density_ch0.comp: outBuf.density[idx] = eval_df_base_0(133, 0, int(idx), ix, iy, iz);
```
即 eval_df_base_0 函数体、CLOSURE_0/VAL_SLOTS_0/SLOT_OF_0 等 134 项 const 数组、interp_0、顶层 eval_df、normal_noise/interp_noise/spline_eval、NOISE/NORMAL_PACK 噪声表全部相同。任何「两个 shader 生成代码不同」的怀疑直接排除。

### E2. root=133 两处同一
- ch0 main（ch0.comp:966）：字面量 `133`。
- final interp_0 d000（final.comp:869）：`eval_df_base_0(133, 0, sIdx, ...)` —— 同一字面量（dfc_gen.py:406 `samples[c].replace('__ROOT__', str(root_pos))`，root_pos = interp_root_pos[0] = interp_0 闭包内 delegate 根位置；dfc_gen.py:593）。
- 越界检查：`CLOSURE_0_LEN = 134`（final.comp:543），rootPos=133 = 闭包末节点，合法且两处一致。

### E3. valBuf 区段布局核对：不写顶层区段、8 角点子区互不重叠
生成器布局（dfc_gen.py:471/472/475）：`per_sample = val_slots_top(=8) + 8*Σpeak`；closure 0 base B=8，`VAL_SLOTS_0 = 18`。
- eval_df_base_0 所有读写 = `PER_SAMPLE*sIdx + 8 + corner*18 + SLOT_OF_0[...]` → **只触及区段 [8, 152)，永不写顶层区段 [0,8)**（顶层区段只有顶层 eval_df 使用，final.comp:824/839）。
- final interp_0 的 8 次调用（corner=0..7）占用同一 sIdx 段内 8 个互不重叠的 18 槽子区；ch0 main 的 corner=0 恰好就是 d000 的那个子区。**无区段错位。**
- 容量：段内最大地址 = 8 + 7*18 + 17 = 151 < 152（interp_1 base）< PER_SAMPLE=352。宿主 `gpu_density_engine.cpp:45`: `valBuf = n * perSample * sizeof(float)`，ch0 main sIdx=int(idx)<n → 最大地址 < n*352，**无越界**。

### E4. 无「前置写入依赖」：eval_df_base_0 自包含
函数体（final.comp:553-592）为叶子→根顺序循环，常量/噪声/spline/y 节点现场求值、每个闭包节点写自己的槽，返回 `SLOT_OF_0[rootPos]`。不读任何由其他 corner 或顶层 eval_df 写入的槽。**单 corner 独立调用完全自足，不存在「缺 delegate 前置中间值」机制。**

### E5. sIdx 语义一致
final main（:961-966）与 ch0 main 完全同源（E1）：`ix,iy,iz = coord.coords[idx*3..]`，sIdx 均为同一线程 idx。final 路径 interp_0(sIdx,...) 由 eval_df 传入同一 sIdx（:634）。

## 判定

**假设「GPU ch0 调用形态 ≠ final interp_0 d000」＝伪（静态层）。**

在探针前提（采样点均为 cell min-corner：gx%4==0 ∧ gy%8==0 ∧ gz%4==0）下，`interp_0` 的 d000 坐标 `(chunkX*16+cx*4, minY+cy*8, chunkZ*16+cz*4)` ≡ 查询点 `(ix,iy,iz)`；结合 E1-E5，ch0 main 的调用与 final interp_0 d000 在 root(133)/corner(0)/sIdx(idx)/valBuf 区段([8,152) 子区)/闭包数组五要素上**逐项相同**。valBuf 越界/区段错位/顶层区段写入三个怀疑点全部排除。

### 推论（对 260903-05 channels 探针差异的含义）
既然调用形态等价且 shader 逐字相同，GPU ch0（平滑）vs Rust transpiler ch0（恒定段）的差异**不在调用形态/valBuf，而在共享叶子函数的宿主供给或 CPU 侧语义**，嫌疑收敛到：
1. **ch0 探针宿主的噪声预传（npBuf/permBuf）与 ch0 main 坐标集不一致**——normal_noise(slot+corner*stride, sIdx) 按预传 buffer 取值；若 ch0 harness 的 noise prepass 采样网格/顺序与 main 的 coord.coords 不同序，则 sIdx 错位 → 平滑假象（GPU 值是邻居采样的插值/错位值）。
2. **Rust transpiler ch0 侧**：恒定段可能意味着 CPU ch0 的 delegate 闭包内 y 相关节点（DF_Y / DF_Y_CLAMPED / spline 的 iy）被常量化或坐标绑定错（eval_df_base 取值绑定 sIdx 的坐标——dfc_gen.py:2362 注释明确警告此点）。
3. spline_eval 的 biome/offset 表（locBuf/derBuf/vfBuf）供给差异。
（以上为收敛方向建议，未验证——需 ch0 通道 host 供给链探针。）
