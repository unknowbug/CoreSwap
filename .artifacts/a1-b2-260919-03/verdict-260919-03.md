## 4. 机制归因（证据绑定，区分实测/推断）

### 4.1 C-3 packed 路：拷入节省 < 解码成本（实测主导）

| 窗（LP P50, μs/task） | on25（blocks25 宽 ABI） | onpk2（packed） | Δ |
|---|---|---|---|
| alloc_copyin | 1091 | **169** | **−922（C-3 目标段，−85%）** |
| kernel | 26518 | **33271.5** | **+6753.5（+6.75ms）** |
| subcopy / copyout | 2304 / 70 | 2122 / 66 | −182 / −4 |
| 端到端 nativeMs P50 | 3.370 | 4.012 | **+0.642ms/center（×9 ≈ +5.8ms/task）** |

- **实测**：alloc_copyin 降 922μs，kernel 窗涨 6753.5μs → 净 +5831.5μs/task，与端到端退步量级（~5.8ms/task）自洽。
- **窗位核对（判据 §2 声明的代码实证）**：`jni_bridge.rs:575-588`（`Java_wg_CppWorldgen_lightComputeDomainPacked`）——计时窗 `kp`（t2 起）先调 `light_decode_packed_domain`（packed 帧解码进 b25）再调 `light_compute_domain*`，**Rust 侧 packed 解码确实落在 kernel 窗内**，与判据 §2「alloc_copyin=packed copyin、解码落 kernel 窗」的声明一致。即 C-3 把 Java 侧拼帧成本转成了 Rust 侧解码成本且放大（推断归因：解码逐节 palette 展开 + 后帧覆盖重叠写，量级 > blocks25 arraycopy 直拷；未做窗内解码/内核拆分打点，属推断，登记 idk）。
- **参考**：VOID 臂 onpk kernel=34633μs，与 onpk2（33271.5）同向，支持归因稳健性（仅参考，不进判定）。

### 4.2 C-4 缓冲复用：灰区（E1 同轮单变量 + E3 跨实现参照）

- **实测（E1/E2）**：on25/off = 3.370/3.410 = 0.988——C-4（b25/outv thread_local 复用，jni_bridge.rs LIGHT_B25/LIGHT_OUTD 已核在位）端到端仅 −1.2%，落在灰区带（0.97–1.00）。
- **参照（E3，非判定）**：新 off 臂 3.410 vs R2-on1 3.962 = **0.861**（对旧构建参照 −14%）。⚠️ E3 跨实现态（dll f1d30ee9→7519ddb8 + #103 顺序效应 + 跨批次），只作量级参照：C-4+重编的组合效应方向为正，但本判据主读（E1 同轮 off 基）下 C-4 单独效应未达满足线。

## 6. 降级声明 + idk（如实）

- **降级声明**：单 seed 单区域门控打点运行时数据（verdict 级 Full 但外推受限）；onpk 臂 VOID 使 packed 路首轮读数缺失，判据臂为其复采（同 dll 同 seed，E1）；P50 主读法（判据写死）。
- **idk-1**（预登记）：内核 Scratch/b9 不在范围——B-C4 灰区无法归因到「复用无效」还是「可观测份额本就小」；归因混淆如实声明。
- **idk-2**（新增）：**Java 提交线程 packed 收集成本不在 nativeMs 窗**（nativeMs 计时起点在域任务提交后）——packed 帧收集（writePacket 拆帧/拼 meta）若比 blocks25 arraycopy 贵，差额在本口径不可见。**总管线（提交线程+native）是否净退步需另一口径（端到端 tick/wall）才能裁决**；本 verdict 的「净退步 ~18%」仅指 nativeMs 窗内。
- **idk-3**（新增）：kernel 窗内 packed 解码成本与 light_compute_domain 内核本体未拆分打点——§4.1 的「解码 ~6.75ms」是窗差推断（含重叠覆盖写语义），非独立实测段。
- **idk-4**（继承 idk-2）：packed 帧重叠窗口跨提交时刻快照差异——本轮 ratio 门全绿，未触发；留档。
- **idk-5**（继承 idk-3）：thread_local 缓冲常驻（b25 ~9.4MB + outv ~0.9MB/线程）驻留量未专项测量；本轮无 RSS 异常信号，不立案。

## 7. 结论建议（供 judge/用户，非决策）

1. **C-3 packed 域批直传：建议不采纳/回退缺省关**（packed 门控缺省关保持现役 blocks25 路）——B-主 1.177 远超未满足线，机制归因闭合（拷入省 0.92ms 被 kernel 窗解码成本 +6.75ms 反超，实测+代码窗位实证）。若后续翻案，须先解 idk-3（解码/内核拆分打点）+ 评估解码算法（如批量 palette 直映射），属新一轮立项。
2. **C-4 缓冲复用：建议保留**（灰区非未满足；代码已并线无开关成本；E3 参照方向为正 −14% 对旧构建；风险低）。灰区归因受限（idk-1），若 judge 要二值化，可加一轮 C-1 范围内 Scratch/b9 复用后重测 B-C4。
3. **下一步输入**：.b2 系域批输入/缓冲轴已触顶（拷入已 0.155×、C-4 灰区），**native 段下一个主收益面回 .b1 系 C-1（域共享 fill/传播，上界 ≤59%）**——但 C-1 MUST 先解 G3 收敛性约束设计（整域快照一次重载性质可证）再立项；C-2 受 round4 纯算力冻结排序约束。
4. **证据饱和状态**：本轮数据层证据充分（B-主/B-C3/B-C4 三判据全部有窗级数据 + 窗位代码实证），无 retry 压力；无 halt 信号。
